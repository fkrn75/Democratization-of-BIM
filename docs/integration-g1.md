# G1 준비: 스파이크 코어 통합 충돌 측정

측정일 2026-11-09. 스파이크 브랜치를 임시 브랜치에서 합쳐 보고 충돌을 쟀다. 이 측정은 병합하지 않았고, 합친 결과도 올리지 않았다. 목적은 G1(roadmap.md) 전에 통합 비용과 순서를 정하는 것이다.

## 1. 대상

| 브랜치 | 커밋 | 코어(`spikes/s1-core/src`) 변경 |
|---|---|---|
| spike/s2-roundtrip | 7f7ada0 | 10파일, +1,636줄 |
| spike/s3-drawings | 6490cd2 | 11파일, +1,728줄 |
| spike/s4-families | 0b58138 | 20파일, +4,217줄 |
| spike/s8-merge | 0949b73 | 6파일, +1,181줄 |
| spike/s7-packaging, s9-krules, s10-headless | — | 코어를 고치지 않아 충돌 0 |

spike/s5-annotations(280d329)는 이 측정 뒤에 완성돼 포함하지 않았다. S5는 s3 위에서 코어 7파일을 고친다(+1,025줄, `commands.py`·`ifc_model.py`·`engine.py`·`drawing_export.py` 포함). 통합 전에 다시 재야 한다.

## 2. 텍스트 충돌

- 충돌 덩어리는 합치는 순서와 관계없이 15~17개다.
- 가장 무거운 짝은 s2와 s4다. `ifc_model.py`에서만 5덩어리가 난다.
- 권장 순서: **s3 → s8 → s4 → s2**. 가벼운 것부터 합치고, 왕복 규칙을 바꾸는 s2를 마지막에 얹는다.

## 3. 합친 코어의 시험 결과 (s2→s3→s4→s8 순)

- `pytest -m "not slow"`: 254 통과, 실패 0, 건너뜀 38. 건너뛴 것은 ifcdiff 환경이 없어 S2 왕복을 검증하지 못한 시험이다.
- S4 시험 120개 통과.
- import-linter 계약 5개는 유지된다. 단 S2의 foreign 처리, S8의 merge, S4의 family 모듈은 "ifcopenshell 직접 사용 금지" 계약이 감시하지 않는다.
- 커맨드 47개. 패리티 C는 실패로 나오는데, 원인은 하나다. `commands.search`가 6,000B 상한 때문에 한 쪽에서 34개만 돌려준다. 기대값을 페이지를 넘기며 모으도록 고치면 된다.

## 4. 의미 충돌 (git이 잡지 못함, 모두 재현됨)

| # | 짝 | 증상 |
|---|---|---|
| 1 | S8 × S2 | 가져온 프로젝트를 병합할 수 없다. S2는 가져온 상태를 rev0 시작 상태로 두는데 S8은 로그를 접어 비교한다. 오류도 `IO_ERROR`/`ORPHAN_UNIT`으로 나와 원인을 오해하게 만든다 |
| 2 | S8 × S3·S4 | `merge.py`가 아는 요소 종류가 level·wall·door뿐이다. view나 패밀리 인스턴스가 있는 프로젝트는 병합을 거부한다. 또 병합의 요소 쓰기가 S2의 `ELEMENT_FROZEN`을 우회한다 |
| 3 | S3 × S4 | 크래시. 도면이 벽에 걸린 자식을 모두 `sill`을 가진 문으로 가정한다. 패밀리 문이 벽에 있으면 `view.linework`가 `KeyError`로 죽는다 |
| 4 | S2 × S3 | 도면이 wall 목록만 읽는다. foreign 요소는 빠지고, detached 요소는 낡은 매개변수로 그려진다 |
| 5 | S2 × S4 | `family.place`가 S2의 저작 확인을 거치지 않아 detached 벽에도 놓인다. 또 S4의 의미 덤프를 합치면 해시 형식이 바뀌어, 가져올 때 저장한 projection_hash가 무효가 된다 |
| 6 | S2 × S3 | 증분 도면의 입력 키 계산과 효과 적용이 관계(att) 처리에서 서로 다르다 |

## 5. 통합 전 선행 작업

1. 요소 종류, 효과 태그, 관계 종류를 레지스트리 하나로 모은다. 2·3·4·6번의 공통 원인이다.
2. S2의 가져온 시작 상태를 로그의 rev0 항목으로 기록한다(1번).
3. 모든 변경 커맨드가 같은 저작 확인 경로를 거치게 한다(2·5번).
4. `IfcModel`의 상태 필드와 정규화 함수를 하나로 합치고, 해시 형식이 바뀌면 가져온 프로젝트를 다시 판정한다(5번).
5. 패리티 도구가 `commands.search`를 페이지 단위로 순회한다.
6. 위 의미 충돌 6건을 통합 시험으로 고정한다. S5를 포함해 다시 잰다.

## 6. 한계

- Windows 11, Python 3.12, ifcopenshell 0.9.0.post1 한 환경에서 쟀다.
- 느린 시험과 ifcdiff 왕복 시험은 합친 코어에서 돌리지 않았다.
- 의미 충돌은 코드를 읽고 재현한 것이며, 모든 짝을 체계적으로 탐색한 것은 아니다.
