# ADR-0006. 재생성: 수요 구동 증분 계산과 조기 차단

- 상태: **제안** (S1로 검증)
- 일자: 2026-11-07

## 결정 (제안)

양방향 연관성은 **메모이즈된 순수 질의의 그래프**로 구현한다. rust-analyzer의 Salsa 같은 red-green 방식을 참고한다.

- 입력은 의도 저장소와 IFC 의미 데이터다. 그 외는 전부 파생 질의다.
- 의존 관계는 실행 중 읽기를 기록해 자동으로 얻는다. 손으로 선언하지 않는다.
- 값이 필요할 때만 계산한다. 보이지 않는 뷰는 계산하지 않는다.
- 결과 해시가 그대로면 전파를 멈춘다(조기 차단). 문 색을 바꿔도 평면 선분이 그대로면 시트는 갱신되지 않는다.
- 조인처럼 상호 의존하는 관계는 벽 축선에서 계산하는 별도 노드로 뽑아 순환을 없앤다.
- 그래도 남는 순환은 오류로 보고한다. 일반 구속 해석은 MVP에 넣지 않는다.

## 대안

| 대안 | 기각 이유 |
|---|---|
| 푸시 방식(변경 시 즉시 전파, Blender 드라이버·Revit 원시 재생성 유사) | 보이지 않는 뷰까지 계산. 순서 문제 |
| 전체 재생성 | 단순하지만 대형 모델에서 불가. 다만 **검증 기준**으로는 유지한다 |
| 의존성 수동 선언 | 누락 버그가 조용히 도면을 틀리게 한다 |
| FreeCAD식 문서 재계산 + 위상 참조 | 위상 명명 문제를 그대로 물려받는다 |
| BimCraft식 명시 재생성(변경 요소 + 조인 이웃) + 뷰·일람표·시트 요청 시 전체 재도출 | 가장 단순하고 실제로 돌아간다. 소형 건물에서는 충분할 수 있다. 그러나 대형 뷰 비용과 누락 위험이 남는다. **그래프가 S1에서 실패하면 이 방식이 후퇴안이다** |

## 위험

- Python에서 읽기 기록 비용. 5,000요소 합성 모델로 측정한다.
- 공간 질의(근처 벽 찾기)가 넓은 의존을 만들면 효율이 사라진다. 격자 셀 단위 노드로 쪼갠다.
- 증분 결과가 전체 재계산과 다르면 신뢰가 무너진다. 차등 테스트를 CI에 항상 둔다.

## 불변식

같은 입력은 같은 출력을 낸다. 파생 엔티티의 GlobalId는 부모 ID로부터 결정적으로 만들고(uuid5), 시각과 난수를 파생 경로에서 금지한다.
