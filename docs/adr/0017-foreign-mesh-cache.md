# ADR-0017: 외래 형상 삼각형화 결과를 프로젝트 파일에 저장한다(프로젝트 형식 2)

- 상태: **채택** (2026-11-21, 저장 형식 변경 승인. 브랜치 `phase1/w1x-10`)
- 관련: ADR-0005(데이터 정본: 외래 요소의 형상은 IFC 가 정본이고 동결, "IFC 와 파생물은 언제든 다시 만들 수 있어야 한다"), `spikes/phase1-drawings/elements-design.md` 31·32절, `baseline.md` 54·55절

## 문제

외래 요소 3만여 개가 섞인 모델에서 차가운 첫 뷰가 평면 44초·단면 53초·입면 58초다(baseline.md 54절). 그중 약 27초가 외래 형상 삼각형화(ifcopenshell.geom.iterator, 16 스레드)이고 약 8.5초가 프로젝트를 열 때 외래 기반 IFC 를 다시 읽는 시간이다. 외래 요소의 형상은 바뀌지 않는데(ADR-0005: 무변경 통과, 속성만 편집) 프로세스를 새로 띄울 때마다 같은 계산을 되풀이한다. 목표는 이 모델의 차가운 첫 뷰 30초 이내다.

## 결정

1. **무엇을 저장하나**: 그리는 외래 요소(그리는 범주이고 형상 표현이 있는 IfcElement) 전체의 정리 메시, 곧 `foreign_geom._clean` 의 결과(mm, 0.01mm 반올림·용접·퇴화 제거·회전 정규화한 꼭짓점과 정렬한 삼각형). 계산하지 못한 요소(형상 커널 실패·빈 메시·삼각형 상한 초과)는 "없음"으로 적는다. 층·공간·문창 기호 입력은 싸서 저장하지 않는다.
2. **언제 계산하나**: IFC 가져오기(`ifc.import`)가 프로젝트를 만든 직후 한 번. 뷰가 요청할 때와 같은 길이다(외래 id 전체로 `prefetch` → 요소마다 미리 계산한 값 또는 `create_shape` → `_clean`). 계산이 실패해도 가져오기는 실패하지 않는다(뷰가 그때 계산한다: 지금까지와 같다).
3. **저장 형식**: 새 테이블 `foreign_mesh`(행 하나: `cache_key`, `ids`, `counts`, `verts`, `tris`, `digest`). ids 는 GlobalId 를 정렬해 줄바꿈으로 이은 것, counts 는 요소마다 (꼭짓점 수, 삼각형 수) int64(없음은 -1, -1), verts 는 float64(반올림한 값을 그대로 담아 되읽어도 같은 수), tris 는 요소 안 색인 int32. 넷 다 리틀 엔디언·zlib 압축이고 digest 는 압축한 넷의 sha256. 프로젝트 형식(`meta.schema_version`)을 **2** 로 올린다.
4. **무효화 키**: `cache_key` = 외래 기반 원본 sha256 + ifcopenshell 판(형상 커널 포함) + 삼각형화 설정 + 정리 규칙 판(`MESH_FORMAT`)과 그 상수(반올림 자릿수·삼각형 상한) + 미리 계산 문턱(iterator 와 create_shape 중 어느 길로 계산했는지가 갈린다). 하나라도 다르거나 digest·길이가 맞지 않으면 쓰지 않는다.
5. **캐시는 파생물이다**: 로그·리비전·실행 취소·병합과 무관하다. 없거나 낡았거나 깨졌으면 첫 형상 요청 때 같은 길로 계산하고(값이 같다), 그 뒤 저장을 시도한다. 저장은 덤이라 트랜잭션 안이거나 잠겨 있으면 기다리지 않고 건너뛴다(읽기 전용 파일도 같다).
6. **이전 파일(형식 1)**: 그대로 열린다(테이블이 없을 뿐이다). 첫 형상 요청 뒤 캐시를 저장할 때 테이블을 만들고 형식 번호를 2 로 올린다(같은 트랜잭션). 이 변경 이전 코드는 형식 2 파일을 "지원하지 않는 프로젝트 형식"으로 거절한다(1.0 이전이라 받아들인다). 병합은 형식 1·2 를 모두 읽는다.

## 근거

- 저장한 메시는 그 자리에서 계산한 메시와 값이 같다: 계산 길이 하나(`compute_all`)이고 저장은 그 결과의 무손실 직렬화다. 시험은 저장소 표본 4건에서 저장 메시로 그린 도면 = 캐시를 지우고 다시 계산해 그린 도면(선·SVG 해시, 요소마다 형상 입력 값), 다시 저장한 바이트 = 가져올 때 바이트, 저장소 표본 기준선과 같음을 본다(`tests/test_foreign_mesh_cache.py`).
- 원시 삼각형화가 아니라 정리 메시를 담는 이유: 정리도 수 초가 걸리고(3만 요소), 용접 뒤라 꼭짓점이 적다. 정리 규칙이 바뀌면 `MESH_FORMAT` 을 올려 무효화한다.
- 프로젝트 파일 안에 두는 이유: 프로젝트는 파일 하나로 옮기고 나눈다. 외래 기반 원본도 이미 같은 파일에 있다(`foreign_base`).

## 위험과 완화

- **형상이 바뀌는 길이 생기면 캐시가 낡는다**: 지금은 외래 요소의 형상·배치·관계 연결이 동결이라(ELEMENT_FROZEN, 관계 맺기 검사) 가져온 뒤 외래 메시가 바뀌는 길이 없다. 이 전제는 같은 프로세스 안의 메모(4차)도 이미 기대고 있다. 외래 형상을 바꾸는 기능(예: 외래 요소에 저작 개구부, 외래 타입 지우기가 표현 사상을 지움)을 넣을 때는 키에 그 상태를 넣거나 캐시를 지워야 한다.
- **파일 크기**: 늘어난다. 3만여 요소 혼합 모델의 증가량은 baseline.md 55절에 적는다.
- **판이 다른 ifcopenshell**: 키에 판이 들어 있어 다시 계산한다(결과는 그 판의 값).

## 되돌리기 비용

낮다. 테이블을 무시하면 형식 1 과 같은 동작이다(형식 번호만 남는다).

## 남은 것

프로젝트를 열 때 외래 기반 IFC 전체를 다시 읽는 시간(3만여 요소 모델에서 약 8.5초)은 그대로다. IFC 신원(엔티티 객체)을 지연 로드하거나 읽기 결과를 저장하는 일은 범위가 커서 다음 몫으로 둔다.
