# ADR-0012. 주석: 의미 이름 참조, 파생 값, 고아 표시

- 상태: **제안** (S5로 검증, 결과는 `spikes/s5-annotations/report.md`)
- 일자: 2026-11-09

## 맥락

치수·태그 같은 주석은 모델이 바뀌어도 맞아야 한다. 면·모서리를 인덱스로 가리키면(FreeCAD식 위상 참조) 코너가 다시 계산될 때 번호가 바뀌어 주석이 조용히 엉뚱한 곳을 가리킨다. 아키텍처 6절은 이를 피하려고 "의미 참조만 쓴다"고 정했고, 로드맵 S5는 "치수·태그 50개를 둔 RA-01에서 편집 시나리오 3종 후 고아 0건, 값 오류 0건"으로 검증하기로 했다.

## 결정 (제안)

1. **참조는 `종류:요소 id#역할` 문자열**이다. 역할은 위상 인덱스가 아니라 의미 이름이다.
   - 벽: `axis.start`, `axis.end`(축선 끝점, 분할 뒤에도 원래 끝), `own.end`(이 벽 자신의 현재 끝점), `trim.start`, `trim.end`(조인으로 정리된 끝점, 분할 뒤에도 원래 끝), `own.trim.end`(이 벽 자신의 정리된 끝점), `axis`, `face.left`, `face.right`(진행 방향 기준 직선), `base`, `top`(높이)
   - 문: `center`, `jamb.start`, `jamb.end`(호스트 축선 위 점), `sill`, `head`(높이)
   - 레벨: `elevation`
   해석 결과는 점·직선·높이 중 하나이고, 치수는 두 결과 사이의 거리다(점-점, 점-직선, 평행한 직선-직선, 높이-높이. 평면과 높이는 섞지 않는다).
2. **요소 id 로 모자라는 경우의 규칙**
   - 벽 분할(`wall.split`)은 관계 `succ`(원래 벽 -> 끝 쪽을 이어받은 벽)를 남긴다. 끝 역할(`axis.end`, `trim.end`)은 이 사슬 끝까지 따라가 해석한다("원래 끝", 사슬 중간 벽이 지워져도 `succ` 가 지워진 벽을 지나 이어지므로 사슬 끝 벽이 살아 있으면 값이 나온다). 시작·직선·면·높이 역할은 원래 벽에 남는다. 그래서 분할은 `axis.end`·`trim.end` 를 쓰는 어떤 치수 값도 바꾸지 않는다. 사슬 끝 벽까지 사라지면 자기 끝(분할점)으로 대체하지 않고 고아(`successor_deleted`)로 둔다. 분할이 형상(조인 정리)을 바꾸게 되면 분할 자체를 거절한다.
   - **두 끝 참조를 나눈 이유(검수 반영).** 분할 뒤 `axis.end` 가 원래 끝을 가리키므로 그 벽 자신의 끝(조각 길이)을 재는 참조가 따로 없었다(치수 6000 대 태그 length 3000). 선택지는 (가) `axis.end` 를 현재 끝으로 바꾸고 원래 끝을 `chain.end` 로 분리, (나) `axis.end` 는 원래 끝으로 두고 자기 끝을 새 역할 `own.end` 로 추가였다. (나)를 택했다: 분할 불변성(분할은 값을 바꾸지 않는다)과 이미 저장된 참조의 의미를 그대로 두고, 조각 길이를 재려는 사람이 `own.end`/`own.trim.end` 를 명시하게 한다. 태그의 `length` 는 벽 자신의 길이이므로 `own.*` 와 같은 기준이다. `own.*` 는 분할로 값이 바뀌는 것이 설계다.
   - **분할 이력에 쓰인 id 는 다시 쓰지 않는다.** `succ` 는 지워진 벽을 지나 이어져야 하므로 삭제 때 정리하지 않는다. 대신 한 번이라도 `succ` 에 나온 id 는 `wall.split` 의 `new_id` 와 모든 생성 커맨드가 거절한다(undo 로 분할 이력이 사라지면 다시 쓸 수 있다). 지워진 후계 id 로 다시 분할하면 `succ(X→X)` 순환이 생기고(검수에서 발견), 지워진 벽 id 로 새 벽을 만들면 끝 참조가 엉뚱한 새 벽으로 조용히 부활하기 때문이다. `wall.split` 은 끝에서 순환 여부도 확인하고, 해석기는 순환을 만나도 터지지 않고 `bad_ref` 고아로 낸다(방어선).
   - 문 이동·폭 변경·조인 변경·벽 이동·분할로 문이 다른 벽에 옮겨지는 경우: id 와 역할이 그대로이므로 참조는 끊기지 않고 기하만 따라간다(호스트는 문의 속성이지 참조의 일부가 아니다).
3. **경고 `direction_changed`**: 역할 이름은 축선 방향에 의존한다(시작·끝·왼쪽·오른쪽·문틀). 치수를 만들 때 방향에 의존하는 참조의 벽(문이면 호스트) 축선 단위 방향을 지문(`params.dirs`)으로 저장하고, 지금 방향과 내적이 음수이면(`wall.set axis` 로 반전하거나 90도 넘게 돌렸다) `annot.check`/`annot.list` 의 `warnings` 에 `direction_changed:a|b` 를 낸다. 끝 역할은 값을 내는 사슬 끝 벽의 방향도 본다. 값은 그대로 따라가므로 고아도 무효도 아니다. 사람이 확인하고 `annot.rebind` 로 같은 참조를 다시 묶으면 지문이 갱신된다.
4. **고아**: 해석할 수 없으면 값을 만들지 않고 이유(`target_deleted`, `successor_deleted`, `bad_ref`)와 함께 고아로 표시한다. 좌표가 너무 커서 거리가 유한하지 않으면(제곱이 넘침) 값을 만들지 않고 `invalid`(`non_finite`)로 낸다. 주석은 지워지지 않고, `annot.check`·`annot.list`가 목록으로 보여 준다. 수동 복구는 `annot.rebind`(새 참조로 다시 묶기)다. 합격 기준의 "고아"는 참조 대상이 살아 있는데 끊긴 경우로 정의한다.
5. **주석은 의도 요소**(`dim`, `tag`)이고 **IFC 로 투영하지 않는다**(IFC 해시 불변). 값(치수 값, 태그 글)은 저장하지 않는 그래프 질의이므로 편집 때 영향받는 주석만 다시 계산된다. 주석은 뷰에 속하고(관계 `annot_of`), 뷰를 지우면 그 뷰의 주석도 같은 트랜잭션에서 지워진다(응답에 나열, undo 로 복귀).

## 대안

| 대안 | 기각 이유 |
|---|---|
| 면·모서리 인덱스 참조(FreeCAD 위상 이름) | 코너 재계산 때 번호가 바뀌어 조용히 엉뚱한 곳을 가리킨다 |
| 기하 위치로 다시 찾기(근처 모서리) | 편집 뒤 같은 것인지 판정할 수 없다. 조용한 오류 |
| 대상이 사라지면 주석도 삭제 | 사용자가 잃은 것을 모른다. 복구 불가 |
| 값을 주석에 저장(스냅숏) | 편집 뒤 낡은 값이 남는다 |
| 주석을 IFC(IfcAnnotation)로 투영 | 연관 치수를 담을 안정된 표현이 없다. 나중에 내보내기 옵션으로 검토 |

## 위험과 한계

- 역할 이름은 축선 방향에 의존한다(`axis.start`, `face.left`). 축선을 뒤집으면(`wall.set axis`) 참조는 끊기지 않지만 물리적으로 다른 위치를 가리키게 된다. 지금은 `direction_changed` 경고로 알릴 뿐 값을 보정하지 않는다(경고를 보는 쪽이 사람이다). 방향 지문은 치수에만 있고 태그는 방향에 의존하지 않는다. 코어에 벽의 안팎(외부/내부)이 없어 의미 이름이 `exterior` 가 아니라 `left` 다.
- **고아 정의의 한계**: "고아 0건"은 "참조 대상 요소가 살아 있으면 끊기지 않는다"는 뜻이다. 대상이 살아 있어도 그 요소가 다른 것이 되었을 수 있다(벽 `wall.set` 으로 전혀 다른 곳으로 옮겼거나 반전했을 때 값은 따라가지만 사용자의 의도와 다를 수 있음). 이런 경우를 고아로 세지 않는다. 방향 반전만 `direction_changed` 로 잡고, 나머지는 사람이 값을 본다.
- 벽을 지우고 새 id 로 다시 그리면 참조는 고아가 된다(사용자 의도와 같은지는 사람이 판단, `annot.rebind`).
- 분할만 위상이 바뀌는 연산으로 시험했다. 벽 병합, 외래 IFC 요소에 대한 참조, 창·슬래브·기둥은 시험하지 못했다.
