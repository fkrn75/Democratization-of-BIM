# ADR-0005. 데이터 정본: 의도 저장소 + IFC 분담, 모든 변경은 커맨드 로그

- 상태: **제안** (가장 위험한 결정. S0·S1로 검증)
- 일자: 2026-11-07

## 맥락

| 모델 | 장점 | 문제 |
|---|---|---|
| A. IFC 단독 정본 (Bonsai 방식) | 매핑 코드가 없고 충실도가 최고 | 파라미터·구속·뷰를 담을 자리가 없어 Pset에 우회. 비루트 엔티티는 안정 ID가 없어 병합이 어려움. 재생성 때 STEP ID가 흔들림 |
| B. 내부 모델 정본 + 내보내기 (Revit 방식) | 설계 자유, 협업·성능 유리 | 매핑표가 끝나지 않고 왕복이 손실됨. 쐐기로 삼은 IFC 품질을 해침 |
| **C. 분담 (제안)** | 각자 잘하는 것만 정본 | 두 정본 사이의 불일치 위험 |

## 결정 (제안)

정보 종류별로 정본을 하나만 둔다. 같은 정보를 두 곳에서 정본으로 다루지 않는다.

| 정보 | 정본 | 비고 |
|---|---|---|
| 파라미터, 호스팅·조인 규칙, 패밀리 참조 | 의도 저장소 | 재생성의 입력 |
| 뷰, 시트, 주석, 일람표 정의 | 의도 저장소 | IFC로는 선택적으로만 투영 |
| 속성셋, 분류, 재료, 공간 구조, 타입 관계 | IFC | `ifcopenshell.api`로 편집 |
| 저작 요소의 형상·배치 | **파생물** | 직접 편집 금지, 해시로 변조 감지 |
| 외래 요소의 형상 | IFC, 동결 | 무변경 통과, 속성만 편집 |

연결 키는 IFC GlobalId다. 저작 요소에는 의도를 `DoBIM_Intent` Pset에도 복제해 IFC 파일만으로 복원할 수 있게 한다. 다른 도구가 이 Pset을 버리면 요소는 일반 IFC 요소로 강등될 뿐 파일은 유효하다.

모든 변경은 커맨드를 거쳐 추가 전용 로그에 남는다. IFC와 파생물은 언제든 다시 만들 수 있어야 한다.

## 선례: BimCraft의 모델 A 구현

BimCraft는 IFC 텍스트를 정본으로 직접 편집한다. 도구 1회를 저널 1단위로 묶어 실행 취소하고, 요소는 GlobalId로 참조하며, 요소마다 자기 소유 라인만 가져 부분 교체가 안전하다(`research/04-bimcraft-deep-dive.md`). 모델 A가 동작한다는 증거이므로 **뒤집을 때의 후퇴 설계로 삼는다.** 다만 저널은 라인 단위라 의미 수준 병합이 어렵고, 뷰는 요청 시 전체 재도출이다. 증분 도면과 협업을 목표로 하는 이 프로젝트에는 C가 여전히 낫다고 판단한다. 이 판단은 측정 전이며 S1에서 확인한다.

## 왜 C인가

- 쐐기가 IFC 품질이므로 B는 맞지 않는다.
- 라이브 도면·패밀리·협업이 요구하는 정보가 IFC에 자리가 없으므로 A만으로는 계속 우회해야 한다.
- 커맨드 로그는 실행 취소, 감사, 협업 병합을 한 장치로 해결한다.

## 위험과 완화

- **불일치**: 외부 도구가 저작 요소 형상을 바꿔 돌려주면 해시가 어긋난다. 조용히 덮어쓰지 않고 그 요소를 "분리됨(동결)"으로 바꾼 뒤 경고한다.
- **커맨드 우회**: `ifcopenshell.file`을 직접 수정하는 코드는 린트로 금지한다.
- **검증**: 임의 커맨드열에 대해 "증분 결과 = 로그 전체 재생 결과"를 속성 테스트로 확인한다(S1).

## 되돌리기 비용

높다. 스파이크 뒤에 바꾸면 코어를 거의 다시 짠다. 그래서 G1 전에는 UI를 만들지 않는다.

## 뒤집는 조건

- S1에서 불일치 테스트를 통과하지 못하거나 분담 규칙 예외가 계속 늘면 **A로 후퇴**한다. 의도는 Pset에만 두고 커맨드 로그만 유지한다. "요소별 소유 엔티티" 규칙은 BimCraft 선례를 따른다.
- 외래 요소 통과 때 IFC 전체 로드 메모리가 한계면 요소 단위 저장으로 바꾼다.

## 다음 세대 고려

IFC5(IFCX)의 계층 합성은 커맨드 로그와 잘 맞는다. 다만 개발 중인 표준이므로 MVP 저장 형식으로 쓰지 않는다. ifc-lite가 IFCX 내보내기와 CRDT 협업을 구현했다고 하므로 나중에 참고한다.
