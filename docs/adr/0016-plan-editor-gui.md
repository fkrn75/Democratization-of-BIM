# ADR-0016: 평면 GUI 편집기 — Tauri 2 + Svelte 5 + PixiJS 캔버스, 코어 사이드카, 커맨드만 호출

- 상태: **초안** (2026-11-18, 설계 문서 `docs/2d-editing.md` 2절. 코드는 지휘자 지시 후 PR B0~B4)
- 관련: ADR-0004(플랫폼·스택: Tauri 2 + Svelte 5 + Python 사이드카, 2D 는 PixiJS), ADR-0011(모든 기능은 CLI·MCP, 패리티 G), `spikes/s6-viewer/report.md`(3D 뷰어 선택)

## 문제

사용자가 2D 편집을 요청했다(2026-11-18). 2D 작도는 커맨드로 먼저 만들었고(27단계), 그 위에 평면에서 벽·문·창을 그리고 옮기면 모델이 바뀌는 GUI 가 필요하다. 로드맵은 GUI 를 2b(G3 뒤)로 두었는데 평면 편집만 앞당긴다. 패리티 G(GUI 전용 기능 0개)를 처음부터 지켜야 한다.

## 결정(초안)

1. **셸·UI·캔버스**: Tauri 2 + Svelte 5, 평면 캔버스는 PixiJS v8(WebGL2, 필요 시 Canvas 폴백). 화면에 그리는 선분은 코어가 계산한 것만 쓴다(새 조회 `view.scene`: 요소 id 가 붙은 선분·채움·문자, 2D 작도 포함).
2. **코어 연결**: Python 사이드카 `dobim gui-serve` 가 줄 단위 JSON 으로 기존 `dispatch.run` 을 부른다. 봉투·오류 코드·rev 가 CLI·MCP 와 같다. GUI 는 코어 내부를 import 하지 못한다.
3. **패리티 G**: 모든 메뉴·도구는 `gui/actions.json` 에서 커맨드 또는 `gui_exempt.yaml` 항목(이유 필수)에 매핑된다. 검사기가 빌드를 막는다. 제외 동작은 실행 뒤 `rev`·해시가 그대로여야 한다. GUI 시나리오의 조작 기록(커맨드 목록)을 CLI 로 재생해 같은 `model.hash` 가 나와야 한다.
4. **GUI 가 필요한 조회는 코어 커맨드로 먼저**: `view.scene`, `view.pick`, `geom.snap`, `selection.save`·`session.selection`. 에이전트도 같은 것을 쓴다.
5. **3D 는 이 ADR 범위 밖**: 붙일 때 S6 권고를 따른다.

## 근거

- S6 는 3D 뷰어 비교였고 2D 캔버스는 재지 않았다. 2D 평면의 선분 수는 같은 모델의 3D 삼각형 수보다 훨씬 적고(평면 한 장), 화면은 코어가 이미 계산한 선분을 받아 그리기만 하므로 렌더 비용보다 코어 조회 지연이 병목일 것으로 본다(추정, B1 에서 `view.scene` 응답 시간으로 잰다).
- (b) SVG DOM 은 가장 단순하지만 요소 수가 커지면 끌기·확대가 느려진다는 것이 일반적 경험이다(이 프로젝트에서 미측정). 선택 강조·끌기 미리보기를 자주 다시 그려야 하는 편집 화면에는 캔버스가 낫다고 본다.
- (c) 는 3D 렌더러로 2D 도면 표현(용지 mm 선굵기, 문자 회전, 해치)을 다시 만들어야 한다.
- (d) 는 ADR-0004 를 뒤집고, Qt 의 동결 배포 라이선스 검토가 새로 생긴다.

## 뒤집는 조건

- B1 에서 `view.scene` 이 큰 평면(합성 5,000 요소)에서 응답 30초 상한·8,000토큰 목표를 쪽 나누기로도 못 맞추면 사이드카 전용 이진 전송(같은 데이터, 다른 직렬화)을 검토한다.
- B2 에서 WebView2 안 WebGL2 가 막히면 Canvas 폴백 또는 SVG(b)로 바꾼다.

## 알려진 한계

- 실제 창(Tauri·WebView2) 안의 종단 시험은 창이 필요해 아직 방법이 없다. 단위 시험(vitest)과 조작 기록 재생 해시 시험으로 대신한다.
- 동시 편집(GUI + 에이전트)은 `dobim daemon`(아키텍처 15.6)이 필요하다. MVP 는 GUI 단독 쓰기 + 에이전트 읽기로 시작한다.
