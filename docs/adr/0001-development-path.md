# ADR-0001. 개발 경로: 헤드리스 코어를 먼저 만들고, 앱은 관문 통과 후 결정

- 상태: **제안** (경로 자체는 S0 결과로 확정. **S0 착수는 승인**, 2026-11-07 사용자 지시)
- 일자: 2026-11-07

## 맥락

요청은 "오픈소스 장점을 모아 Revit 대체 도구를 만들 준비"다. 조사 결과 전체 대체 오픈소스는 없다. 다만 반증 과정에서 전제가 두 가지 바뀌었다.

1. ConstructCAD(GPL-3.0)는 저장소 생성 20일 만에 Rust 6.5MB(1인 466/473커밋)로 평면·단면·입면·일람표·시트·IFC 왕복 코드를 갖췄다. BimCraft(Apache-2.0)는 수식(formula) 파라미터, 솔리드, IFC 내 패밀리 저장 코드를 실제로 갖고 있다. **에이전트 시대에 기능 폭은 싼 자원이 됐다.** 또 하나의 넓은 앱은 차별점이 없다. 검증된 깊이가 없는 것이 공백이다.
2. Bonsai 도면의 투영선은 벡터다(HLR). 래스터는 선택 사항인 underlay뿐이다. 그래서 공백은 "벡터 도면"이 아니라 **모델과 뷰의 증분 연동, 주석 연관성, 한국 납품 서식**으로 좁혀진다.

3. 사용자가 확정 제약 3개를 추가했다(ADR-0011): 전 기능 CLI·MCP 제어, Claude·Codex 동등 사용, 헤드리스 실행. 이 제약으로 경로 평가가 바뀌었다.

## 비교

목표를 같게 맞췄다. "소형 건물 1동을 모델링하고, 도면이 자동으로 따라오고, 시트를 출력하고, IFC로 납품하는 일을 CLI·MCP만으로, 디스플레이 없이 해낸다." 인월은 전업 1인 + AI 에이전트 기준 **추정**이며 근거는 `docs/roadmap.md` 5절에 있다.

| 경로 | 인월(추정) | 도달 범위 | 막히는 지점 |

## 결정

**F를 추천한다.** 순서는 다음과 같다.

1. **S0(1주)**: Bonsai, FreeCAD, BimCraft, ConstructCAD를 실제로 돌려 기준선을 잰다. 이 결과가 "새로 만들 이유"의 유일한 근거다.
2. **헤드리스 코어**: IfcOpenShell 위에 재생성 그래프, 커맨드 로그, 패밀리 레시피, 증분 도면을 Python 라이브러리로 만든다. UI에 묶지 않는다.
3. **1단계 제품**: 앱 없이 쓸 수 있는 "IFC → 라이브 도면·일람표·납품 검사" 도구. 외부 저작 도구의 IFC로도 동작하므로 Revit 사용자에게도 가치가 있다.
4. **헤드리스 저작(2a)**: GUI 없이 Claude·Codex와 CLI로 RA-01을 처음부터 만들고 납품한다.
5. **GUI(2b)**: 그 뒤 선택 패키지로 얹는다. 기본값은 자체 Tauri 앱이다. 코어가 Python이므로 Bonsai 어댑터(IfcOpenShell API 리스너 활용)도 얇은 표시·편집 호스트로 가능하다.

**전체를 처음부터 새로 만드는 것은 추천하지 않는다.** 코어 우선 추천은 유지하되 근거가 강해졌다. 헤드리스·전 기능 제어가 필수가 되면서 코어 분리는 선택이 아니라 요구사항의 직접 구현이 됐다.

**이전 결론에서 바뀐 점**

- "빠른 실사용이면 Bonsai 플러그인"은 철회한다. 제약을 충족하지 못한다. 지금 당장 쓸 도구가 필요하면 Bonsai를 GUI로 쓰고, 자동화는 IfcOpenShell의 `ifcedit`·`ifcmcp`로 하는 조합이 현실적이다(요구 전체를 충족하지는 않음).
- BimCraft 포크는 순위가 내려갔다.
- **ConstructCAD 기여는 순위가 올라갔다.** GPL을 받아들일 수 있고 S0을 통과하면 F보다 나을 수 있다. D1(라이선스)이 경로를 가르는 결정이 됐다.

## 뒤집는 조건 (G0)

- 후보 하나가 왕복·편집 전파·벡터 시트·CLI/MCP·헤드리스 기준을 모두 통과하고 라이선스가 수용 가능하면, 신규 저작 앱을 중단하고 그 도구에 기여하거나 포크한다. 코어는 그 도구의 확장으로 전환한다.
- ConstructCAD가 기능 기준을 통과하고 사용자가 GPL을 수용하면 D로 바꾼다. Rust 기여로 스택도 바뀐다.

## 결과

- 초기에는 설치할 앱이 없다. 대신 Claude·Codex에서 건물을 만들고 도면 이미지를 돌려받는 시연이 가능하다.
- 코어 경계가 호스트 교체 비용을 낮춘다.
