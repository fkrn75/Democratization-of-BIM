# S5 연관 주석 결과

질문: 주석이 편집을 견디는가? (docs/roadmap.md S5)
합격 기준: 치수·태그 50개를 둔 RA-01에서 편집 시나리오 3종 후 고아 0건, 값 오류 0건.

**결론: 통과(독립 검수 반영 뒤 재측정).** 주석 72개(치수 53 + 태그 19)로 편집 시나리오 E1~E9(하위 단계 포함 15단계)를 돌린 결과 단계마다 **고아(기준) 0건, 값 오류 0건**이다. 지워진 대상을 가리키는 주석은 모두 이유와 함께 "정상적 고아"로 표시되었고 오라클이 센 수와 같았다. 임의 편집열 6시드 × 400스텝에서 불일치 0(이번에는 매 스텝 IFC 투영과 새로 연 엔진 대조 포함), 변이 15/15 검출이다. 로드맵의 대안(참조 체계 확장, 고아 수동 복구 UI)은 쓰지 않았다. 수동 복구 커맨드 `annot.rebind`는 있다. 이 브랜치는 spike/s3-drawings 위에 있다.

**이 결론이 말하지 않는 것(고아 정의의 한계).** "고아 0건"은 *참조 대상 요소가 살아 있는 한 참조가 끊기지 않고 값이 따라간다*는 뜻이다. 대상이 살아 있지만 사용자의 의도와 다른 것이 되었을 때(축선 반전, 벽을 전혀 다른 곳으로 옮김, 분할 뒤 끝 참조가 원래 끝을 가리킴)는 고아로 세지 않는다. 오라클은 코어의 규칙을 독립 구현한 것이라 "규칙 자체가 의도에 맞는가"는 검증하지 못한다. 독립 검수가 이런 사례를 찾았고(9절), 방향 반전은 `direction_changed` 경고로, 분할 뒤 자기 끝은 `own.end` 참조로 보완했다. 나머지는 사람이 값을 봐야 한다. 합격 기준이 재려던 "치수·태그가 편집을 견디는가"의 의미에서 기준은 충족했지만, "주석이 항상 맞다"를 보증하지 않는다.

## 용어 정의

| 용어 | 정의 |
|---|---|
| 정상적 고아 | 대상(또는 분할로 끝을 이어받은 벽)이 의도 저장소에서 실제로 사라졌고 코어가 같은 이유(`target_deleted`/`successor_deleted`)로 표시. 기준의 고아에 세지 않음 |
| 고아(기준) | 대상이 살아 있는데 고아·무효 표시 + 대상이 없는데 값이 나옴 + 이유 불일치 + 그 밖의 불일치 + 뷰 없는 주석. 합이 0이어야 함 |
| 값 오류(기준) | 코어와 오라클이 둘 다 정상인데 치수 값이 1e-6mm 넘게 다르거나 태그 글이 다름 |

## 1. 참조 체계 (ADR-0012)

참조는 `종류:요소 id#역할` 문자열이고 역할은 위상 인덱스가 아닌 의미 이름이다.

- 벽: `axis.start`·`axis.end`(점, 분할 뒤에도 원래 끝), `own.end`(이 벽 자신의 끝), `trim.start`·`trim.end`(조인 정리 뒤 점, 원래 끝), `own.trim.end`(자신의 정리된 끝), `axis`·`face.left`·`face.right`(직선), `base`·`top`(높이)
- 문: `center`·`jamb.start`·`jamb.end`(호스트 축선 위 점), `sill`·`head`(높이)
- 레벨: `elevation`(높이)

치수는 두 참조의 거리다(점-점, 점-직선, 평행한 직선-직선, 높이-높이). 평면 치수는 평면 뷰에, 높이 치수는 단면·입면 뷰에 둔다. 태그는 대상(벽·문)과 표시 필드(이름·폭·두께·길이·방화등급·재료·레벨·호스트), 오프셋으로 이루어진다. 값은 저장하지 않는 그래프 질의다.

| 상황 | 규칙 | 결과 |
|---|---|---|
| 벽 분할 | `wall.split`이 관계 `succ`(원래 벽 → 끝을 이어받은 벽)를 남기고, 끝 역할은 사슬 끝까지 따라감. 시작·직선·면·높이는 원래 벽에 남음 | 분할 118회(임의 편집열) + 시나리오 2회에서 모든 치수 값 불변 |
| 사슬 끝 벽을 지움 | 자기 끝(분할점)으로 대체하지 않고 `successor_deleted` 고아 | 임의 편집열 892건, 오라클과 일치 |
| 사슬 가운데 벽만 지움 | `succ`가 지워진 벽을 지나 이어지므로 사슬 끝이 살아 있으면 값이 나옴(예전에는 고아로 오판) | 직접 시험 + 임의 편집열 |
| 분할 뒤 이 벽 자신의 끝 | `own.end`/`own.trim.end`(분할 이력을 따라가지 않음). 태그 `length`와 같은 기준 | E6b: `axis.end` 12000, `own.end` 6000 |
| 분할 이력에 쓰인 id | `new_id`·모든 생성 커맨드가 거절(CONSTRAINT). `succ` 순환·지워진 벽의 부활을 막음 | 임의 편집열 시도 31회 전부 거절, E9 |
| 축선 방향 반전 | 치수가 방향 지문(`params.dirs`)을 저장, 내적이 음수이면 `direction_changed` 경고(값은 따라감) | E6, 임의 편집열 반전 34회 |
| 문 이동·폭 변경, 조인 변경, 벽 이동 | id·역할 그대로, 기하만 따라감 | E1~E3 |
| 분할로 문이 다른 벽에 옮겨짐 | 문 id 유지(호스트는 참조의 일부가 아님) | E4a |
| 분할이 조인 정리를 바꾸는 위치, 문을 가로지르는 위치 | 분할 거절(CONSTRAINT) | 임의 편집열 거절 77회 |
| 대상 삭제 | 고아 표시. 주석은 남고 `annot.check`/`annot.list`가 이유와 함께 나열 | 정상적 고아 |
| 수동 복구 | `annot.rebind`로 새 참조에 다시 묶음 | E5 |

## 2. 코어 확장

- 의도 요소 `dim`, `tag`: **IFC로 투영하지 않음**(연관 치수를 담을 안정된 IFC 표현이 없음). 주석 72개를 만든 뒤에도 IFC 해시가 불변이고, 상태·파생 해시는 변한다. 주석을 모두 지우면 파생 해시가 원래대로 돌아온다.
- 커맨드 7개(레지스트리 38 → 45): `annot.dim.create`, `annot.tag.create`, `annot.rebind`, `annot.delete`, `annot.list`, `annot.check`, `wall.split`. 스키마·examples·위험 등급(조회 read, 나머지 write)·응답 상한 규약을 지킨다. `wall.split`은 위상을 바꾸는 편집이 없으면 요소 id 참조가 끊기지 않아 시험이 무의미해서 더했다.
- 영향받는 주석만 재계산: 참조 하나가 노드 하나(`ref_resolve`), 그 위에 `dim_value`, `dim_flags`, `tag_text`, `annot_draw`, `view_annots`. 참조 값이 그대로면 치수 값에서 전파가 멈춘다. 뷰 선분 캐시와는 독립이다.
- 뷰를 지우면(`view.delete`, `element.delete`) 그 뷰의 주석도 같은 트랜잭션에서 지워지고 응답 `deleted`에 나열된다. undo로 함께 돌아온다.
- SVG 주석 층: 치수(보조선·치수선·45도 눈금·회전한 값 글), 태그(지시선·글), 고아·무효(빨간 ×·점선 원·한글 이유). PDF는 선과 ASCII 글만 그린다(한글은 물음표, S3 한계 그대로).
- `commands.search` 응답이 상한(6,000B)을 넘지 않도록 기존 요약 문구 약 30개를 줄였다(5,508B). 역할 목록 조회 커맨드는 응답 상한 때문에 빼고 스키마 설명과 오류 hint에 넣었다.

## 5. 오라클과 임의 편집열 (`results/s5_fuzz.json`)

**오라클의 독립성.** 코어의 주석·기하 질의를 쓰지 않고, 같은 원시 입력(의도 저장소의 요소 행·관계, IFC 속성셋·재료)에서 기하를 따로 계산한다. 분할 이력은 코어의 `succ`를 읽지 않고 하네스가 성공한 `wall.split`을 기록해 undo/redo와 짝지어 유지한다. 한계: 조인 정리 규칙(1000mm 한도)과 분할의 후계 규칙은 같은 명세를 다시 구현한 것이라 명세 자체의 오류는 못 잡는다. 그래서 규칙에 의존하지 않는 **물리 불변성 검사**를 따로 둔다. 분할 전후로 모든 치수 값, 모든 벽 시작·끝점, 모든 문 중심이 그대로여야 한다.

매 스텝 검사: (a) 모든 주석의 코어 상태 = 오라클(방향 경고 포함), (b) 증분 파생 해시 = 캐시 없는 전체 파생 해시, (c) 4스텝마다 마지막 트랜잭션 undo → 같은 검사 → redo → 같은 검사 + 스냅숏 정확 일치, (d) 시드마다 S1 `full_check`(로그 재생·재오픈·Intent 일관성·IFC 유효성), **(e) 검수 반영으로 추가: 검사 때마다 상주 엔진을 IFC로 투영(flush)하고(터지면 실패), 3회에 한 번 파일을 새로 연 엔진의 IFC 해시와 대조**, (f) 분할 이력(`succ`) 순환 0, (g) 새로 만들거나 다시 묶은 치수의 방향 지문이 그 순간 실제 벽 방향과 같음, (h) 분할 이력에 쓰인 id를 `new_id`·`wall.create`로 재사용하면 거절됨.
(e)가 없던 이전 측정은 투영 상태가 낡은 채 undo로 이어지는 결함(9절)을 구조적으로 못 봤다. 이전 임의 편집열은 마지막에 한 번만 IFC를 투영했다.

| 시드 × 스텝 | 6 × 400 = 2,400 (생성기 항목 성공 1,975 / 거절 425) |

판정 경계: 조인 정리 규칙이 `|t| = |t-L|`, `|t| = 1000` 같은 경계에서 불연속이라, 두 구현의 부동소수 오차가 다른 분기를 고르는 사례가 나왔다. 오라클은 이런 벽(1e-6mm 안)의 기대를 "모호"로 두고 비교에서 빼서 따로 센다. 이 불연속은 코어 조인 규칙의 성질이고 주석의 문제는 아니다.

| M10 고아를 0값으로 표시 | 오라클 `silent_alive` (121, 20) |
| M11 분할이 문 오프셋을 안 옮김 | 물리 불변성 (121, 300, 아슬아슬) |
| M12 벽 삭제 때 개구부 투영 상태를 안 정리(검수가 찾은 결함을 되살림) | IFC 투영 오류 `Instance not found` (121, 297) |
| M13 `succ` 이력 id 재사용 허용 | 이력 id 재사용을 받아들임 (121, 300) |
| M14 방향 경고를 안 냄 | 오라클 `flag_mismatch` (121, 195) |
| M15 사슬 가운데 삭제를 고아로 처리(옛 규칙) | 오라클 `false_orphan` (124, 257) |

변이 없는 같은 시드 6개는 모두 불일치 0이다(`clean_failures_per_seed` = [0,0,0,0,0,0]). 검출 시드·스텝이 이전 측정과 다른 것은 임의 편집열의 분기(반전·이력 id 재사용 시도)와 매 검사의 IFC 투영이 생성 순서를 바꿨기 때문이다.

검출 스텝은 14~300으로 편차가 크다. M11·M12·M13은 첫 시드의 끝 무렵에야 잡혔다(임의 편집열은 특정 결함 경로를 늦게 만난다). 그래서 새 변이 4종(M12~M15)은 임의 편집열과 별개로 **직접 시나리오**(분할→투영→undo, 이력 id 재사용, 반전, 가운데 삭제)를 pytest에 두어 변이를 주입하면 즉시 실패하게 했다. pytest는 임의 편집열 5종 + 직접 시나리오 4종을 고정 시드로 시험한다.

## 7. 한계와 미확인

1. **코어 범위만**: 창·슬래브·기둥·보·계단·공간·재료 층이 없어 그 요소를 가리키는 참조는 시험하지 못했다. 이 브랜치에는 S2(외래 IFC 가져오기)·S4(패밀리)가 없어 외래 요소·패밀리 인스턴스 참조도 미시험이다.
2. **역할 이름이 축선 방향에 의존**: 축선을 뒤집으면(E6) 참조는 끊기지 않고 값이 따라가지만 `axis.start`·`face.left`가 가리키는 물리적 위치가 뒤바뀐다. 이제 `direction_changed` 경고로 알리지만(치수만, 90도 넘게 돈 경우 포함) 값을 고치지는 않는다. 코어에 벽의 안팎이 없어 `face.exterior`를 못 만든다.
3. 벽을 지우고 새 id로 다시 그리면 고아다. 같은 벽으로 보는 규칙은 없고 `annot.rebind`로 수동 복구한다. 수동 복구 UI는 없고 커맨드만 있다.
4. 위상이 바뀌는 편집은 분할만 시험했다. 병합 등은 미시험이다. 분할은 조인 한도(1000mm) 근처 위치를 거절한다(임의 편집열 시도의 36%).
5. 치수 배치는 단순하다(오프셋 숫자 하나). 글 충돌 회피·정렬·연쇄 치수는 없고, 태그는 평면 뷰에만 둔다. 높이 치수가 단면선에서 실제로 보이는지는 검사하지 않는다.
6. SVG는 사람이 눈으로 보지 않았다. PDF의 한글은 물음표다.
7. 측정은 개발용 노트북에서 다른 작업과 동시에 돌렸다. 단일 프로세스, Python 3.12.
8. "납품 초안" 수준의 도면 판정은 **미확인(사람 판정 필요)**.
9. **고아 정의의 한계**(결론 참조): 대상이 살아 있으면 고아가 아니다. 경고는 방향 반전만 안다. 대상이 의도와 다른 것으로 바뀐 다른 경우(큰 이동, 사슬 중간 벽을 지워 끝 벽이 다른 형상을 이어받음 등)는 값만 따라간다.
10. 좌표가 1e155 근처로 아주 큰 벽은 주석이 없어도 S1 코어의 파생 해시(`model.hash`)가 넘쳐 INTERNAL이 난다(S1의 별도 한계, 이번에 고치지 않았다). 주석 쪽은 `invalid:non_finite`로 구조화되어 `annot.list`/`annot.check`가 정상 응답한다.
11. 분할 이력에 쓰인 id는 영구히 못 쓴다(undo로 분할 자체를 취소하면 풀린다). 지워진 벽의 id를 새 벽에 다시 쓰는 일은 막혀 있다.

## 8. S3 결함 한 건 발견·수정

로그 전체 재생 검사를 S5 임의 편집열에 붙이자, 단면·입면 뷰가 있는 로그의 재생이 `SCHEMA_INVALID`("section 뷰에는 쓰지 않는 필드다")로 실패했다. 로그에는 기본값까지 적혀 있는데 `view.create` 검증이 명시된 값을 "쓰지 않는 필드"로 거절한 탓이고, S3 시험은 뷰 로그를 재생하지 않아 못 봤다. 기본값과 같은 값은 쓰지 않은 것으로 보도록 고쳤다(`ViewCreate._by_type`). 기본값이 아닌 값은 그대로 거절한다.
