# 도면 요소 설계 메모: 창·기둥·슬래브 (1단계, 2026-11-15)

상태: **제안 + 부분 구현**. 기둥은 패밀리 인스턴스로 최소 구현했고(아래 3절), 슬래브는 설계만 한다. 근거 ADR: 0005(저작 원천), 0006(의존 그래프), 0008(패밀리), 0014(패밀리 의도 왕복).

## 1. 문제

코어 요소 종류는 `level·wall·door·ftype·finst·foreign·view·dim·tag` 뿐이다(`kinds.py`). 창·기둥·슬래브는 종류가 따로 없다. G2 5-1절 법정 8항목 중 "기둥·벽·창문 위치"(#2), "복도·계단"(#4), "종·횡단면의 슬래브 표현"(#7)이 이 요소들에 걸려 있다. 가져온 IFC에서는 의도(DoBIM_Intent)가 없는 요소가 외래(foreign)라 형상 정보가 없어 도면에 못 그린다(baseline.md 1절).

## 2. 선택지와 결정

| 요소 | A. 패밀리 인스턴스로 | B. 새 요소 종류로 | 결정 |
|---|---|---|---|
| 창 | `window.fixed`(IfcWindow). 벽에 호스팅·개구부 이미 있음 | 불필요 | **A** (이미 있음). 도면 표현만 고쳤다 |
| 기둥 | `column.section`(IfcColumn). 평면 기호·압출 형상이 레시피에 이미 있음 | `column` 종류 신설 | **A**. 새 종류를 만들지 않아 해시·왕복·IFC 투영을 건드리지 않는다 |
| 슬래브 | 레시피 형상은 압출(경계 다각형)이라 가능하나, 경계 편집(꼭짓점 목록)·벽 경계 자동 추종은 패밀리 모델이 못 한다 | `slab` 종류: 레벨 + 경계 다각형 + 두께 | **B**(미구현) |

패밀리(A)를 쓰는 이유는 ADR-0008·0014가 이미 인스턴스 형상·평면 기호·속성·IFC 클래스를 한곳(레시피)에서 평가하고 의도로 왕복시키기 때문이다. 기둥은 점 하나(위치·회전)와 단면·높이 매개변수로 충분하다. 슬래브는 가변 길이 꼭짓점 목록이 본질이라 매개변수 레시피에 안 맞는다.

## 3. 기둥 (구현함)

### 요소 스키마
변경 없음. `family.place family=column.section level=<레벨> position=[x,y]` 로 `finst`(+`ftype`)가 만들어진다. 단면(`rect·round·chamfered`)·폭·깊이·모따기는 타입 값, 높이는 인스턴스 값. IFC는 `IfcColumn`(PredefinedType COLUMN)으로 나간다(이미 투영됨). 호스트는 없고 `on_level` 관계로 레벨에 걸린다.

### 도면 표현 (`drawing.py`)
도면은 `queries.ifc_spec` 의 평가 결과(`plan` 평면 기호, `body` 압출)를 그대로 읽는다. 별도 기하 사본을 두지 않으므로 IFC로 나가는 형상과 도면이 어긋나지 않는다.

| 뷰 | 그림 |
|---|---|
| 평면 | 절단 높이가 기둥 높이 범위(zb..zt) 안일 때 기호의 절단(cut) 도형을 굵은 선과 **절단 채움**(`view_fills`, 벽 절단과 같은 회색 poche)으로, 대각선(투영 스타일)은 symbol 선으로 |
| 단면 | 각기둥 조각을 가림 후보로 쓰고, 절단면에 닿으면 (s,z) 절단 사각형을 cut 선·채움으로. 안 닿으면 모서리를 투영 선으로(벽·다른 기둥이 앞에 있으면 가려짐) |
| 입면 | 각기둥 모서리(수직 + 위·아랫면 둘레)를 투영 선으로, 가림 판정 포함. 기둥이 앞에 서면 뒤의 벽 선도 가린다 |

지원 압출 단면은 rect·circle(24각형 근사)·polygon(볼록)뿐이다. 회전·위치는 사인·코사인을 쓰므로 libm 대신 사분면 줄임 + 테일러 급수(`_sincos_deg`)로 계산해 결정성(같은 입력 같은 바이트)을 지킨다.

### 캐시·해시 영향
- 새 질의 노드(`free_fam`, `scope_fams`, `plan_fam_parts`, `fam_lines`, `vfam_*`)는 `finst` 행·`ifc_spec` 에서만 읽는다. 뷰에 묶인 노드는 `VIEW_SCOPED` 에 넣어 뷰 삭제 때 치운다.
- 평면 뷰는 그 레벨의 기둥만 의존한다. 다른 층 평면의 선분은 그대로다(시험으로 고정. 캐시 신선도는 기존 증분 시험이 다룬다).
- **단면·입면의 벽 선은 이제 모델의 모든 자립형 패밀리 인스턴스에 의존한다**(기둥이 벽을 가리므로). 기둥을 추가·이동하면 단면·입면의 벽 선 캐시가 전부 다시 계산된다. 5,000요소 이하 목표에서는 허용했고, 필요하면 경계 상자 이웃 판정(`_nbrs`와 같은 방식)으로 좁힌다.
- 기둥이 없는 모델의 도면 바이트는 바뀌지 않는다(G1 판정 비교용 기본 7뷰 동일 확인 대상).
- 요소 해시·IFC 투영·의도 왕복·`family.*` 커맨드는 손대지 않았다.

### 알려진 한계
- 기둥과 벽이 겹칠 때 벽 안쪽에 기둥 윤곽 선이 남는다(절단 윤곽 병합은 벽끼리만 한다).
- 기둥 높이 아래로 끝나는 기둥(절단 높이가 기둥 위)은 평면에서 그리지 않는다(벽의 '절단면 아래 투영'에 해당하는 표현 없음).
- 단면에서 기둥의 단면 모양은 절단면과 만나는 폭의 사각형이다(원형도 사각형).

## 4. 슬래브 (설계만)

### 요소 스키마
`slab` 종류 신설.

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `level` (관계 `on_level`) | 소속 레벨. 윗면 기준 높이는 레벨 + `top_offset` |
| `boundary` | 경계 다각형 꼭짓점 `[[x,y], ...]`(3~256개, 반시계, 자기 교차 금지) |
| `thickness` | 두께 mm. 윗면에서 아래로 |
| `top_offset` | 레벨 기준 윗면 오프셋(기본 0) |
| `openings`(선택, 후순위) | 구멍 경계 목록(계단실·샤프트) |

### 커맨드(기존 레지스트리, CLI·MCP 동시 노출)
`slab.create`, `slab.set`(경계·두께·오프셋), `slab.move`, `slab.delete`. 검사는 `element.*` 공통(id·충돌·undo)과 같은 길을 탄다. 벽 경계를 자동으로 따라가는 `slab.from_walls`(레벨의 외벽 둘레로 경계 채움)는 2차.

### IFC 매핑
`IfcSlab`(PredefinedType FLOOR 기본, `ROOF`는 선택 인자), `IfcExtrudedAreaSolid`(경계 프로필 `IfcArbitraryClosedProfileDefinition`, 두께 방향 -Z, 위치는 레벨 높이 + 오프셋). 레벨 `IfcBuildingStorey` 에 `IfcRelContainedInSpatialStructure`. 가져오기 복원 표(`IMPORTABLE_BY_CLASS`)에 `IfcSlab: slab` 추가.

### 도면 표현
- 평면: 절단 높이가 슬래브 두께 범위 안이면(보통은 아님) 절단 채움. 대신 슬래브 아래 레벨의 위쪽 투영은 관행상 그리지 않거나 점선 외곽만(선택). 기본은 슬래브 외곽을 **투영 선**으로 그리지 않는다(평면은 벽이 윤곽을 준다). 슬래브 가장자리 표기는 후속 항목.
- 단면: 절단면과 슬래브 경계의 교차 구간 × 두께를 **절단 사각형**(cut 선 + 채움)으로. 벽과 닿는 곳은 벽 절단과 합집합 윤곽(`outline_edges`)에 넣어 이음매 선을 지운다. 이것이 G2 #7(슬래브 단면 표현)의 핵심이다.
- 입면: 두께 띠(슬래브 옆면)의 보이는 가장자리. 벽 뒤면에 숨는 부분은 가림 판정.

### 캐시·해시 영향
- 새 종류라 `ELEMENT_KINDS` 와 의존 그래프 입력(`("el", id)`)이 늘고, 도면 질의는 `slab_pieces(V,s)`·`vslab_pieces(V,s)` 단위를 추가한다(벽과 같은 단위 구조).
- 상태 해시·`element` 행은 종류를 모르는 소비자(내보내기·검사·복원)가 새 종류를 만났을 때의 동작(`CONSTRAINT`)을 정해야 한다. 새 종류는 기존 프로젝트 해시를 바꾸지 않는다(요소가 없으면 입력이 없다). 그러나 `PROJECTED_KINDS` 순서·`IMPORTABLE_BY_CLASS`·의도 해시 형식이 바뀌므로 **해시 형식 버전을 올려** 가져온 프로젝트를 다시 판정하게 한다(통합 시험의 해시 판정 규칙, ADR-0014).
- 레벨·벽 변경이 슬래브 단면 캐시에 퍼지는 범위: 슬래브는 레벨 높이만 읽으므로 레벨 변경에만 반응한다. 벽에는 의존하지 않는다(경계가 값이므로).

### 단계
1. `slab` 종류·`slab.create/set/delete`·IFC 투영·왕복. 2. 단면 절단 사각형·벽 합집합. 3. 평면 가장자리·구멍. 4. `slab.from_walls`.

## 5. 이 메모 이후에 남는 것
슬래브 구현, 보(IfcBeam, 평면 점선 + 단면), 계단(법정 #4), 공간(방 이름·복도 판정). 요소 종류를 새로 만드는 것은 슬래브·계단·공간이고, 보·기둥·창·문은 패밀리로 간다.
