# 도면 요소 설계 메모: 창·기둥·슬래브·계단·공간·대지 (1단계, 2026-11-15)

상태: **구현함(창·기둥·슬래브)**, 계단·공간·방화·외부 마감은 6~8절(구현 순서대로 반영). 기둥은 패밀리 인스턴스로(아래 3절), 슬래브는 새 종류 `slab` 으로(4절, 구현 결과는 4절 끝 "구현 결과") 구현했다. 근거 ADR: 0005(저작 원천), 0006(의존 그래프), 0008(패밀리), 0014(패밀리 의도 왕복).

## 1. 문제

코어 요소 종류는 `level·wall·door·ftype·finst·foreign·view·dim·tag` 뿐이다(`kinds.py`). 창·기둥·슬래브는 종류가 따로 없다. G2 5-1절 법정 8항목 중 "기둥·벽·창문 위치"(#2), "복도·계단"(#4), "종·횡단면의 슬래브 표현"(#7)이 이 요소들에 걸려 있다. 가져온 IFC에서는 의도(DoBIM_Intent)가 없는 요소가 외래(foreign)라 형상 정보가 없어 도면에 못 그린다(baseline.md 1절).

## 2. 선택지와 결정

| 요소 | A. 패밀리 인스턴스로 | B. 새 요소 종류로 | 결정 |
|---|---|---|---|
| 창 | `window.fixed`(IfcWindow). 벽에 호스팅·개구부 이미 있음 | 불필요 | **A** (이미 있음). 도면 표현만 고쳤다 |
| 기둥 | `column.section`(IfcColumn). 평면 기호·압출 형상이 레시피에 이미 있음 | `column` 종류 신설 | **A**. 새 종류를 만들지 않아 해시·왕복·IFC 투영을 건드리지 않는다 |
| 슬래브 | 레시피 형상은 압출(경계 다각형)이라 가능하나, 경계 편집(꼭짓점 목록)·벽 경계 자동 추종은 패밀리 모델이 못 한다 | `slab` 종류: 레벨 + 경계 다각형 + 두께 | **B**(미구현) |

패밀리(A)를 쓰는 이유는 ADR-0008·0014가 이미 인스턴스 형상·평면 기호·속성·IFC 클래스를 한곳(레시피)에서 평가하고 의도로 왕복시키기 때문이다. 기둥은 점 하나(위치·회전)와 단면·높이 매개변수로 충분하다. 슬래브는 가변 길이 꼭짓점 목록이 본질이라 매개변수 레시피에 안 맞는다.

## 3. 기둥 (구현함)

### 요소 스키마
변경 없음. `family.place family=column.section level=<레벨> position=[x,y]` 로 `finst`(+`ftype`)가 만들어진다. 단면(`rect·round·chamfered`)·폭·깊이·모따기는 타입 값, 높이는 인스턴스 값. IFC는 `IfcColumn`(PredefinedType COLUMN)으로 나간다(이미 투영됨). 호스트는 없고 `on_level` 관계로 레벨에 걸린다.

### 도면 표현 (`drawing.py`)
도면은 `queries.ifc_spec` 의 평가 결과(`plan` 평면 기호, `body` 압출)를 그대로 읽는다. 별도 기하 사본을 두지 않으므로 IFC로 나가는 형상과 도면이 어긋나지 않는다.

| 뷰 | 그림 |
|---|---|
| 평면 | 절단 높이가 기둥 높이 범위(zb..zt) 안일 때 기호의 절단(cut) 도형을 굵은 선과 **절단 채움**(`view_fills`, 벽 절단과 같은 회색 poche)으로, 대각선(투영 스타일)은 symbol 선으로 |
| 단면 | 각기둥 조각을 가림 후보로 쓰고, 절단면에 닿으면 (s,z) 절단 사각형을 cut 선·채움으로. 안 닿으면 모서리를 투영 선으로(벽·다른 기둥이 앞에 있으면 가려짐) |
| 입면 | 각기둥 모서리(수직 + 위·아랫면 둘레)를 투영 선으로, 가림 판정 포함. 기둥이 앞에 서면 뒤의 벽 선도 가린다 |

지원 압출 단면은 rect·circle(24각형 근사)·polygon(볼록)뿐이다. 회전·위치는 사인·코사인을 쓰므로 libm 대신 사분면 줄임 + 테일러 급수(`_sincos_deg`)로 계산해 결정성(같은 입력 같은 바이트)을 지킨다.

### 캐시·해시 영향
- 새 질의 노드(`free_fam`, `scope_fams`, `plan_fam_parts`, `fam_lines`, `vfam_*`)는 `finst` 행·`ifc_spec` 에서만 읽는다. 뷰에 묶인 노드는 `VIEW_SCOPED` 에 넣어 뷰 삭제 때 치운다.
- 평면 뷰는 그 레벨의 기둥만 의존한다. 다른 층 평면의 선분은 그대로다(시험으로 고정. 캐시 신선도는 기존 증분 시험이 다룬다).
- **단면·입면의 벽 선은 이제 모델의 모든 자립형 패밀리 인스턴스에 의존한다**(기둥이 벽을 가리므로). 기둥을 추가·이동하면 단면·입면의 벽 선 캐시가 전부 다시 계산된다. 5,000요소 이하 목표에서는 허용했고, 필요하면 경계 상자 이웃 판정(`_nbrs`와 같은 방식)으로 좁힌다.
- 기둥이 없는 모델의 도면 바이트는 바뀌지 않는다(G1 판정 비교용 기본 7뷰 동일 확인 대상).
- 요소 해시·IFC 투영·의도 왕복·`family.*` 커맨드는 손대지 않았다.

### 알려진 한계
- 기둥과 벽이 겹칠 때 벽 안쪽에 기둥 윤곽 선이 남는다(절단 윤곽 병합은 벽끼리만 한다).
- 기둥 높이 아래로 끝나는 기둥(절단 높이가 기둥 위)은 평면에서 그리지 않는다(벽의 '절단면 아래 투영'에 해당하는 표현 없음).
- 단면에서 기둥의 단면 모양은 절단면과 만나는 폭의 사각형이다(원형도 사각형).

## 4. 슬래브 (설계 + 구현)

### 요소 스키마
`slab` 종류 신설.

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `level` (관계 `on_level`) | 소속 레벨. 윗면 기준 높이는 레벨 + `top_offset` |
| `boundary` | 경계 다각형 꼭짓점 `[[x,y], ...]`(3~256개, 반시계, 자기 교차 금지) |
| `thickness` | 두께 mm. 윗면에서 아래로 |
| `top_offset` | 레벨 기준 윗면 오프셋(기본 0) |
| `openings`(선택, 후순위) | 구멍 경계 목록(계단실·샤프트) |

### 커맨드(기존 레지스트리, CLI·MCP 동시 노출)
`slab.create`, `slab.set`(경계·두께·오프셋), `slab.move`, `slab.delete`. 검사는 `element.*` 공통(id·충돌·undo)과 같은 길을 탄다. 벽 경계를 자동으로 따라가는 `slab.from_walls`(레벨의 외벽 둘레로 경계 채움)는 2차.

### IFC 매핑
`IfcSlab`(PredefinedType FLOOR 기본, `ROOF`는 선택 인자), `IfcExtrudedAreaSolid`(경계 프로필 `IfcArbitraryClosedProfileDefinition`, 두께 방향 -Z, 위치는 레벨 높이 + 오프셋). 레벨 `IfcBuildingStorey` 에 `IfcRelContainedInSpatialStructure`. 가져오기 복원 표(`IMPORTABLE_BY_CLASS`)에 `IfcSlab: slab` 추가.

### 도면 표현
- 평면: 절단 높이가 슬래브 두께 범위 안이면(보통은 아님) 절단 채움. 대신 슬래브 아래 레벨의 위쪽 투영은 관행상 그리지 않거나 점선 외곽만(선택). 기본은 슬래브 외곽을 **투영 선**으로 그리지 않는다(평면은 벽이 윤곽을 준다). 슬래브 가장자리 표기는 후속 항목.
- 단면: 절단면과 슬래브 경계의 교차 구간 × 두께를 **절단 사각형**(cut 선 + 채움)으로. 벽과 닿는 곳은 벽 절단과 합집합 윤곽(`outline_edges`)에 넣어 이음매 선을 지운다. 이것이 G2 #7(슬래브 단면 표현)의 핵심이다.
- 입면: 두께 띠(슬래브 옆면)의 보이는 가장자리. 벽 뒤면에 숨는 부분은 가림 판정.

### 캐시·해시 영향
- 새 종류라 `ELEMENT_KINDS` 와 의존 그래프 입력(`("el", id)`)이 늘고, 도면 질의는 `slab_pieces(V,s)`·`vslab_pieces(V,s)` 단위를 추가한다(벽과 같은 단위 구조).
- 상태 해시·`element` 행은 종류를 모르는 소비자(내보내기·검사·복원)가 새 종류를 만났을 때의 동작(`CONSTRAINT`)을 정해야 한다. 새 종류는 기존 프로젝트 해시를 바꾸지 않는다(요소가 없으면 입력이 없다). 그러나 `PROJECTED_KINDS` 순서·`IMPORTABLE_BY_CLASS`·의도 해시 형식이 바뀌므로 **해시 형식 버전을 올려** 가져온 프로젝트를 다시 판정하게 한다(통합 시험의 해시 판정 규칙, ADR-0014).
- 레벨·벽 변경이 슬래브 단면 캐시에 퍼지는 범위: 슬래브는 레벨 높이만 읽으므로 레벨 변경에만 반응한다. 벽에는 의존하지 않는다(경계가 값이므로).

### 단계
1. `slab` 종류·`slab.create/set/delete`·IFC 투영·왕복. 2. 단면 절단 사각형·벽 합집합. 3. 평면 가장자리·구멍. 4. `slab.from_walls`.

### 구현 결과 (phase1/drawing-slab)
- 종류·커맨드: `kinds.ELEMENT_KINDS["slab"]`(IfcSlab, 투영 순서 1, 관계 `on_level`), `slab.create/set/move/delete`(그룹 `model.slab`, CLI·MCP 동시 노출). 경계는 반시계로 정규화해 저장하고, 꼭짓점 3~256개·면적 0 아님·반복 꼭짓점 없음·자기 교차 없음을 검사한다(`kinds.polygon_problem`). `element.delete`로도 지워진다. 슬래브가 있는 레벨은 지울 수 없다.
- IFC: `IfcSlab`(FLOOR), 경계 프로필을 레벨 좌표계 원점에서 압출(윗면 = 레벨 + `top_offset`, 솔리드는 `top_offset - 두께`에서 +Z 로 두께만큼), 층 소속은 `IfcRelContainedInSpatialStructure`. 가져오기는 `IMPORTABLE_BY_CLASS["IfcSlab"]`, 해시 형식 번호를 "3"으로 올렸다(가져온 프로젝트는 열 때 다시 판정). 내보냈다 가져오면 저작 슬래브로 되살아나고 의도·파생 해시가 같다. 외부에서 두께를 바꾸면 분리(동결)된다.
- 병합 검증: 레벨이 없는 슬래브는 `LEVEL_MISSING`.
- 도면: 평면은 절단 높이가 슬래브 두께 안일 때만 경계를 절단선·채움으로(아니면 그리지 않는다, 설계 메모대로). 단면은 절단면과 경계의 교차 구간(오목 경계는 짝수-홀수 규칙으로 구간이 여럿)마다 절단 사각형(cut 선 + 채움)을 만들고 벽 절단과 합집합 윤곽으로 이음매 선을 지운다. 입면·단면 뒤쪽은 윗·아랫면 둘레와 수직 모서리를 투영선으로(경계를 삼각형으로 나눈 볼록 조각이 가림 판정에 쓰인다. 벽·기둥 선도 슬래브가 앞에 서면 가려진다).
- 캐시: 슬래브가 없으면 도면 바이트가 그대로다(시험으로 고정). 슬래브 추가·변경은 모든 단면·입면의 벽 선 캐시를 다시 계산시킨다(기둥과 같은 보수적 의존, 5,000요소 이하 목표에서 허용).
- 한계: `openings`(구멍)·`slab.from_walls`·평면의 아래층 슬래브 윤곽은 아직 없다. 경사 슬래브·곡선 경계는 지원하지 않는다.

## 5. 이 메모 이후에 남는 것(12절에서 슬래브 구멍·난간·꺾인 계단·`space.from_walls` 를 구현했다)
슬래브 구멍·`slab.from_walls`, 보(IfcBeam, 평면 점선 + 단면). 요소 종류를 새로 만드는 것은 슬래브·계단·공간이고(계단·공간은 6~7절), 보·기둥·창·문은 패밀리로 간다. 방화(#3)·외부 마감(#6)은 새 종류 없이 기존 속성으로 간다(8절).

## 6. 계단 (법정 #4 계단 위치, #7 계단 단면)

직선 계단 하나를 한 요소로 둔다. 참(landing)이 있는 꺾인 계단은 직선 계단 둘로 나눠 만든다(후속: 한 요소 안의 여러 단).

### 요소 스키마
`stair` 종류 신설(IFC 클래스 `IfcStair`, 투영 순서 1, 관계 `on_level`, `geometric`).

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `level` (관계 `on_level`) | 소속 레벨. 아래 끝 높이 = 레벨 + `base_offset` |
| `run` | 걸음선 `[x1,y1,x2,y2]` mm. 아래 첫 챌판에서 위 끝(위층 바닥 가장자리)까지, 길이 1mm 이상 |
| `width` | 계단 폭 mm(걸음선 좌우로 반씩) |
| `height` | 전체 오름 mm(아래 끝에서 위층 바닥까지) |
| `risers` | 챌판 수(2~100). 디딤판은 `risers - 1` 개, 디딤판 깊이 = 걸음선 길이 ÷ (`risers - 1`), 챌판 높이 = `height` ÷ `risers` |
| `base_offset` | 레벨 기준 아래 끝 오프셋(기본 0) |

커맨드는 `stair.create/set/move/delete`(그룹 `model.stair`, CLI·MCP 동시 노출, 슬래브와 같은 검사 경로). 이동은 걸음선 평행 이동. 레벨에 계단이 있으면 레벨을 지울 수 없다(`on_level` 관계 규칙).

### IFC 매핑
`IfcStair`(PredefinedType STRAIGHT_RUN_STAIR). 몸체는 톱니 옆모습 다각형을 폭 방향으로 압출한 `IfcExtrudedAreaSolid` 하나(옆모습 평면이 걸음선·수직을 펼치고 압출 방향은 걸음선의 오른쪽 법선). 층 소속은 `IfcRelContainedInSpatialStructure`. 가져오기 복원 표에 `IfcStair: stair` 추가, 의도(DoBIM_Intent)에 전 매개변수를 싣는다.

### 도면 표현
- 평면: 계단 윤곽(걸음선 방향 직사각형)과 디딤판 선은 투영선, 걸음선 + 화살촉(오르는 방향)은 symbol 선, 절단 높이가 계단 높이 범위 안이면 그 높이에 이르는 위치에 절단선(대각 cut 선)을 긋고 그보다 위쪽 디딤판 선·윤곽은 그리지 않는다. 절단 높이가 계단 위면 계단 전체를 그린다. 절단 높이가 계단 밑이면 그리지 않는다. 채움은 없다.
- 단면: 절단면과 만나는 각 디딤 조각(디딤판 깊이 구간 x 바닥~디딤판 윗면)을 (s,z) 사각형으로 구해 슬래브·벽과 같은 합집합 윤곽(cut 선) + 절단 채움으로. 단면이 걸음선과 평행하면 톱니 단면이 나온다.
- 입면·단면 뒤쪽: 톱니 옆모습 윤곽(양 옆면), 디딤판 앞 모서리를 투영선으로. 가림 판정은 디딤 조각(볼록 각기둥)으로 한다. 계단은 앞에 서면 벽·슬래브·기둥 선을 가리고, 반대로도 가려진다.

### 캐시·해시 영향
- 새 질의 노드(`stair_info`, `scope_stairs`, `plan_stair_parts`, `_stair_vpieces`, `stair_cut_rects`, `stair_vedges`, `stair_lines` 등)는 뷰 범위 노드 표(`VIEW_SCOPED`)에 넣는다. 평면은 그 레벨의 계단만, 단면·입면은 모델 전체를 읽는다.
- 계단이 있으면 모든 단면·입면의 벽·슬래브·패밀리 선 캐시가 다시 계산된다(기둥·슬래브와 같은 보수적 의존). 계단이 없으면 도면 바이트가 바뀌지 않는다(시험으로 고정).
- 해시 형식 번호를 4 로 올린다(`IfcStair` 이 의도 복원 대상이 된다). 요소가 없으면 기존 프로젝트 해시는 그대로다.
- 한계: 위층 평면에서 아래층에서 올라오는 계단의 위쪽 부분은 그리지 않는다(레벨에 놓인 계단만 그 레벨 평면에 나온다). 참·곡선·나선 계단, 난간은 없다.

### 구현 결과 (phase1/drawing-stairs)
- 종류·커맨드: `kinds.ELEMENT_KINDS["stair"]`(IfcStair, 투영 순서 1, 관계 `on_level`), `stair.create/set/move/delete`(그룹 `model.stair`, CLI·MCP 동시 노출). 걸음선 1mm 미만·챌판 수 범위 밖(2~100)·폭/오름 0 이하를 거절한다. `element.get` 의 파생값에 아래·위 z, 챌판 높이, 디딤판 깊이가 나온다. 병합 검증은 레벨 없는 계단을 `LEVEL_MISSING` 으로 잡는다.
- IFC: 톱니 옆모습 다각형을 걸음선의 오른쪽 법선 방향으로 폭만큼 압출(원점 = 걸음선 시작에서 왼쪽으로 폭의 절반). 가져오기·왕복·분리(외부에서 형상을 바꾸면 동결)는 슬래브와 같다. 해시 형식 번호 "4".
- 도면: 위 설명대로. 평면 절단선은 절단 높이가 가리키는 디딤판 위치에 대각 cut 선 하나이고 그 위쪽 선은 생략한다. 단면의 디딤 조각 사각형은 슬래브·벽의 절단 사각형과 한 윤곽으로 합친다. 계단은 단면·입면에서 벽·슬래브·기둥의 가림 후보에도 들어간다(계단이 없으면 바이트 동일, 시험으로 고정).

## 7. 공간 (법정 #4 복도·실명)

### 요소 스키마
`space` 종류 신설(`IfcSpace`, 투영 순서 1, 관계 `on_level`, `geometric`).

| 매개변수 | 의미 |
|---|---|
| `name` | 실명(예: 사무실) |
| `category` | 분류 문자열(비어 있어도 된다. 복도 판정에 쓴다) |
| `boundary` | 경계 다각형 `[[x,y],...]`(슬래브와 같은 검사, 반시계로 저장) |
| `height` | 공간 높이 mm(레벨에서 위로) |

복도 판정: `category` 가 "복도"·"corridor"·"hallway"(대소문자 무시)이거나 이름이 "복도"로 끝나면 복도. 분류도 이름도 없으면(기본 이름 `SP-xxxxxx` 뿐) 복도로 보지 않는다. 커맨드는 `space.create/set/move/delete`(그룹 `model.space`).

### IFC 매핑
`IfcSpace`(PredefinedType INTERNAL, `Name` = 실명, `ObjectType` = 분류), 경계 프로필 압출(레벨 원점, 높이 = `height`), 층 소속은 `IfcRelAggregates`(공간은 층에 집합으로 분해). 가져오기 복원 표에 `IfcSpace: space` 추가(해시 형식 번호 5).

### 도면 표현
평면만 그린다. 공간은 선·채움을 만들지 않는다(윤곽은 벽이 준다). 대신 **문자 층**(`labels`)에 실명과 면적(㎡, 소수 둘째 자리)을 경계 무게중심에 놓는다. 단면·입면은 그리지 않는다. 문자 층은 뷰 데이터(`_render_view`)의 새 키 `labels`(`(x, y, 문자, 높이 mm)` 목록, 가운데 정렬)이고 SVG·PDF·시트가 모두 그린다. 문자가 없으면 출력 바이트가 바뀌지 않는다.

### 캐시·해시 영향
공간이 없으면 도면 바이트·해시가 그대로다. 평면 뷰는 그 레벨의 공간·방화 속성·재료만 읽는다(뷰 범위 노드 `scope_spaces`·`plan_space_labels`).

### 구현 결과 (phase1/drawing-stairs)
- 종류·커맨드: `kinds.ELEMENT_KINDS["space"]`(IfcSpace, 투영 순서 1), `space.create/set/move/delete`(그룹 `model.space`). 경계 검사는 슬래브와 같다(`kinds.polygon_problem`). 복도 판정은 `kinds.is_corridor(이름, 분류)` 한 곳이다. `element.get` 파생값에 `area_m2` 와 `corridor` 가 나온다. 병합 검증은 레벨 없는 공간을 `LEVEL_MISSING` 으로 잡는다.
- IFC: 경계 프로필 압출, 층 소속은 `IfcRelAggregates`(층이 바뀌면 다시 집합). 가져오기는 집합 관계에서 층을 이어받는다. 해시 형식 번호 "5". 왕복 뒤 의도·파생 해시가 같다.
- 도면: 뷰 데이터에 문자 층 `labels`(`(x, y, 문자, 높이 mm, 앵커)`)를 더했다. `drawing.view_labels` 가 만들고 SVG(`<g id="labels">`)·PDF·시트가 그린다. 평면 문자는 실명(위)과 면적(아래, `24.00㎡`), 위치는 경계 면적 무게중심이고 간격은 용지 위 일정(축척 곱)이다. 문자가 없으면 출력 바이트가 같다(시험으로 고정). 선 종류 `hatch` 는 8절에서 추가한다.

## 8. 방화(#3)와 외부 마감(#6): 새 종류 없이

기존 속성 체계(`Pset_WallCommon`·`Pset_DoorCommon` 의 `FireRating`, `IsExternal`, 재료)만 읽는다. 속성이 없으면 도면 바이트가 그대로다.

- 방화벽·방화문(평면): `FireRating` 값이 비어 있지 않은 벽은 벽 중심선을 따라 파선 `symbol` 선(마디 길이는 용지 위 일정)과 `FW <등급>` 문자를, 문은 중심 옆에 `FD <등급>` 문자를 문자 층에 놓는다. 방화 구획 면적 판정은 범위 밖이다.
- 외부 마감(입면): `IsExternal` 이 참이고 재료 이름이 있는 벽만. 벽 앞면의 보이는 부분에 45도 해치(`hatch` 선 종류 신설, 가는 선, 간격은 용지 위 일정)를 긋고(가림 판정 포함) 재료 이름을 문자 층에 놓는다. 재료가 없거나 외부가 아니면 그리지 않는다. 단면 뒤쪽은 대상 아님.
- 선 종류 `hatch` 는 선분 우선순위 표(`PRIORITY`)·SVG/PDF 스타일 표(`STYLE`)에 한 칸 늘어난다. 해치 선이 없는 도면은 출력 바이트가 같다.

### 구현 결과 (phase1/drawing-stairs)
- 방화(평면): `drawing.plan_fire_lines`(방화벽 중심선 파선: 마디 4mm·간격 1.2mm x 축척, 걸음은 조인으로 줄인 벽 범위), `plan_fire_labels`(`FW <등급>` 벽 왼쪽 바깥, `FD <등급>` 문 오른쪽 바깥, 벽 두께 절반 + 1.6mm 간격). 등급은 문자열만 읽고 앞 16자까지다. 값이 없으면 아무것도 더하지 않는다.
- 외부 마감(입면): `drawing.elev_finish`. 벽 조각(개구부로 나뉜 띠)마다 앞면 깊이에 세계 격자(`s - z` = 간격 정수배)에 맞춘 45도 해치를 긋고, 가림 판정은 대각선용 `_visible_slanted`(수평·수직용 `visible_parts` 를 대각선으로 넓힌 것)로 한다. 뒤쪽 벽은 앞벽에 가려 해치가 안 나오고, 가림 경계의 부스러기(SEG_MIN 미만)는 버린다. 재료 문자는 보이는 해치가 가장 많은 충분히 넓은 조각의 해치 범위 가운데에 한 번, 해치가 하나도 안 보이면 없다. `IsExternal` 은 IFC 불린이라 문자열 "false" 가 참으로 저장되는 점에 주의(시험은 불린 값을 쓴다).
- 새 선 종류 `hatch`(굵기 0.09, #555555): `drawing_export.STYLE`·`LINE_ORDER`(SVG·PDF·시트가 같은 순서·굵기를 쓴다). 해치가 없으면 출력 바이트가 같다. `run_baseline.py --no-stairs --no-spaces --no-fire --no-finish` 산출은 이전 단계(phase1-after3)의 SVG 와 바이트 단위로 같다(baseline.md 8절).

## 9. 시트 정의의 저장 (BIM 지침 B-04): 새 비 IFC 종류 `sheet`

뷰·치수·태그처럼 IFC 신원이 없는 의도 요소다(`kinds.NON_IFC_KINDS`). 시트 파일(SVG·PDF)은 정의에서 다시 만드는 파생물이다.

- 파라미터: `sheet.export` 의 인자에서 `path`·`overwrite` 를 뺀 것 전부와 이름(`name`)이다: 올린 뷰 목록(`views`, 앞에서부터 왼쪽 위 -> 오른쪽 -> 아래 배치), 용지, 표제란(프로젝트명·도면명·도면번호·작성일·북각·건축주·설계사무소·서명 영역), 개정 이력, 통심선, 부위 상세, 단면·입면 기호(`marks`), 부호 태그, 키 플랜, 선 굵기 프로파일. 값은 항상 전부 적는다(생략한 선택 값은 기본값으로 채워 정규형으로 저장).
- 커맨드: `sheet.define`(만들기·같은 id 면 통째로 바꾸기), `sheet.delete`, `sheet.list`(뷰가 사라진 시트는 `missing_views` 로 알린다), `sheet.render`(저장한 정의로 SVG·PDF 내보내기: `sheet.export` 와 같은 코드 경로라 같은 인자면 바이트까지 같다). 모두 CLI·MCP 에 함께 열린다.
- 뷰 참조: 시트가 올린 뷰를 `view.delete` 가 조용히 지우거나 고치지 않는다: 시트가 쓰는 뷰는 지울 수 없다(CONSTRAINT, 시트를 고치거나 지운 뒤에 지운다). 병합으로 뷰가 사라진 시트는 `sheet.list` 의 `missing_views`·`sheet.render` 의 CONSTRAINT 로 드러난다. 참조 id 를 새로 매기는 병합(`remap_params`)은 목록(`views`)·중첩(개정 구름·부위 상세의 `view`)·`key_plan` 을 함께 옮긴다.
- IFC 왕복(ADR-0015 확장): 정의는 `DoBIM_Defs` 속성 하나(이름 = 시트 id)로 실리고 값에 변조 탐지 해시(check)가 든다. 가져올 때 `viewdefs._sheet_values` 가 커맨드와 같은 모델(`commands_sheet.SheetDef`)로 값을 다시 검사하고 정규형(저장 형식과 같은 값)만 받는다. 올린 뷰가 하나라도 되살려지지 않았거나 키 플랜이 평면 뷰가 아니거나 같은 이름의 시트가 더 있으면 그 시트만 되살리지 않는다(경고, 정의는 파일에 그대로 남는다).
- 해시: 시트가 없으면 `state`·`derived`·`ifc` 가 모두 이전과 같다(시트 흔적 없음). 시트가 있으면 `state`(요소 행)와 `ifc`(정의 속성)에만 반영되고 `derived`(그래프 파생값)에는 들어가지 않는다. 해시 형식(`ifc_model.CLOSURE_FORMAT`)을 6 으로 올린다: 제품 클로저는 같고, 가져온 프로젝트를 한 번 다시 판정할 뿐이다.

## 10. 대지(site)와 배치도 뷰 (법정 P-01·P-02·P-04, BIM B-05)

### 요소 스키마
`site`(IFC 클래스 IfcSite, 투영 순서 0): `name`, `boundary`(반시계 다각형 3~256점, 자기 교차 금지), `north_angle`(도면 위에서 시계방향으로 정북까지, ±360), `roads`(최대 8: `{name, edge, width}`, `edge` = 저장한 경계의 변 번호, 변마다 하나), `elevation`(mm 또는 null). 레벨·관계가 없다(뼈대 대지 아래에 놓인다). 시계 방향 경계는 뒤집어 저장하며 도로 변 번호는 입력한 경계의 순서 기준으로 받아 저장 순서로 옮긴다.

### 커맨드·IFC
`site.create`·`site.set`(표고는 `clear_elevation` 으로 지운다)·`site.delete`(그룹 `model.site`, CLI·MCP 동시). IFC: 뼈대 `IfcSite "Site"` 아래 하위 `IfcSite`(`IfcRelAggregates`), 몸체는 `GeometricCurveSet` 폴리라인, `RefElevation`. 방위·도로는 `DoBIM_Intent` 로 왕복한다. 뼈대 판정(`skeleton_check`)은 하위 IfcSite + 의도를 가진 엔티티(`is_site_element`)를 사이트 수에 세지 않는다. 해시 형식 번호 8. 대지 요소는 도면(평면·단면·입면)이 그리지 않는다(`geometric=False`).

### 배치도 뷰(`view.create type=site`)
뷰 설정은 이름·종류·축척뿐이다(`drawing.view_cfg` 가 `("site", ...)` 를 돌려준다). 뷰 질의 노드 `site_lines`·`site_labels`·`site_dims`(뷰 범위, 뷰를 지우면 함께 치운다)와 모델 전체 질의 `building_polys`·`building_outline`·`site_setbacks`. 건물 외곽은 모든 레벨의 그리는 벽 윤곽과 저작 슬래브 경계의 합집합 바깥 선이다(각 변을 다른 다각형 변과의 교점에서 쪼개고, 조각 중점에서 바깥으로 0.5mm 나간 점이 다른 다각형 안이면 이음매라 뺀다). 이격은 대지 경계 변마다 수선의 발이 변 안에 드는 건물 꼭짓점 중 가장 가까운 것이다. 이격·도로 폭 치수는 연관 치수 주석과 같은 항목 모양(`("dim", id, 보조선, 보조선, 치수선, 글, 글 위치, 방향)`, id 는 `site:...`)이라 SVG·PDF·시트가 같은 코드로 그린다. 대지가 없으면 건물 외곽만 그린다. 평면 치수·태그는 배치도 뷰에 달 수 없다.

### 선 위계(sheet.export profile)
`hidden_lines`(`drawing.vwall_hidden`·`view_hidden_lines`: `vwall_lines` 와 같은 가림 판정 `visible_parts` 의 여집합에서 보이는 선과 겹치는 부분을 뺀다. 선 등급 `hid` 는 `drawing_export.STYLE`·`LINE_ORDER` 에 넣지 않고 시트가 파선으로만 그린다: 기본 선 종류 표·`drawing.profile` 의 선 굵기 표는 그대로), `line_hierarchy`(치수선·보조선 굵기 0.25/0.18), `projection`(표제란 투상법 칸). 모두 파일을 낼 때만 받는 입력이라 저장하는 시트 정의에는 넣지 않는다.

## 11. 벽·슬래브 층 구성, 문짝 두께, 공간 천장 높이 (SC-09·B-17, 아홉 번째 작업)

모두 **선택 파라미터**다. 입력이 없으면 요소 행에 키 자체가 없어 저장 형식·상태/파생/IFC 해시·산출 바이트가 이전과 같다(시험: 더했다 지우면 해시가 처음과 같다). 해시 형식 번호(ADR-0014)는 9 로 올렸다.

| 요소 | 파라미터 | 커맨드 | 의미 |
|---|---|---|---|
| 벽 | `layers` = `[{material, thickness}, ...]`(1~8층) | `wall.layers`(id, layers 또는 null) | 벽 지역 +v 방향 순서(첫 층 = 축선 왼쪽 반대 면). 두께 합이 벽 두께(커맨드가 두께를 합으로 맞춘다). 층 구성이 있으면 `wall.set` 의 두께 변경·`material.set` 의 다른 재료는 거절한다 |
| 슬래브 | `layers` | `slab.layers` | 윗면에서 아래로 순서. 두께 합이 슬래브 두께 |
| 문 | `leaf`(문짝 두께 mm) | `door.place` 의 `leaf`, `door.set` 의 `leaf`·`clear_leaf` | 1:50 평면 상세의 문짝 두께 선. 없으면 규약값 40 |
| 공간 | `ceiling_height`(레벨 위 천장 마감 높이 mm, 공간 높이 이하) | `space.create`·`space.set` 의 `ceiling_height`·`clear_ceiling` | 1:50 단면 천장선 |

- 재료 이름표: 층 구성이 있는 벽·슬래브의 재료는 가장 두꺼운 층의 재료다(같으면 앞쪽). 일람표·외부 마감(입면 해치)이 읽는 이름표(`queries.material`)가 이 값을 돌려주므로 입력은 요소 파라미터 하나다(투영이 늦어도 해시가 같다).
- IFC: 층 구성은 `IfcMaterialLayerSetUsage`(+ `IfcMaterialLayerSet` Description = `DoBIM`, 층마다 `IfcMaterialLayer`·`IfcMaterial`)로 투영한다. 벽은 `AXIS2`·`POSITIVE`·`OffsetFromReferenceLine` = -두께/2(첫 층이 -v 면). 슬래브는 `AXIS3`·`POSITIVE`, IFC 층 순서는 아래에서 위(입력의 역순), 오프셋 = 솔리드 밑면(`top_offset - 두께`). 층 구성을 떼면 층·층 집합·쓰던 재료까지 지운다(고아 없음). 투영이 소유하는 지정이라 `has_complex_material`·부속 스냅숏·재료 이름 읽기에서는 제외한다(Description 으로 외래 층 구성과 구분). 문짝 두께·천장 높이는 IFC 속성이 아니라 의도(`DoBIM_Intent`)로 왕복한다.
- 가져오기: `foreign._parse_intent` 가 선택 파라미터를 같은 모양으로 해석한다(층 합 ≠ 두께, 천장 > 공간 높이는 외래로 둔다). 내보냈다 가져와도 해시 3종이 같다(시험).

### 상세 도면(`sheet.export detail`, 1:50 이하)
- 평면(`plan_detail_lines`): 층 구성이 있으면 층 경계마다 가는 선. 없고 재료만 있으면 규약(양면 20mm 안쪽). 문짝 두께는 문 `leaf`.
- 단면(`vwall_detail`·`slab_detail_lines`·`space_ceiling_lines`): 층 구성이 있는 벽·슬래브의 절단 사각형 안에 층 경계선과 층별 절단 해치(재료 이름으로 정해지는 무늬 3종, 용지 위 1.5mm 이상인 층에만. 간격 2mm, 세계 격자 정렬). 이웃 벽 절단 사각형 안쪽은 지운다(슬래브는 벽이 우선). 천장 높이가 있는 공간은 절단면이 공간을 지나는 구간에 천장선(`proj`).
- 입면(`vwin_detail`): 벽에 호스팅된 창의 창대(창 아래 40mm, 양옆 50mm 더 나온 선 3개, 앞의 벽·기둥·슬래브·계단에 가려진 부분은 뺀다). 창 프레임 폭·유리·멀리언은 창 패밀리(`frame_w`)의 형상이라 기본 입면이 이미 그린다.
- 1:100 이상의 축척과 `detail` 을 켜지 않은 출력은 바이트가 그대로다.


## 12. 꺾인 계단·슬래브 구멍·난간·공간 자동 생성 (열 번째 작업)

모두 **선택 입력 또는 새 종류**다. 입력이 없는 프로젝트의 요소 행·상태/파생/IFC 해시·도면 산출은 이전과 바이트까지 같다(HEAD 와 작업본에 같은 직선 계단·슬래브·공간 프로젝트를 돌려 평면·단면·입면 선분·채움과 해시 3종이 같음을 확인했다. IFC 파일 자체는 헤더 시각 때문에 실행마다 바이트가 다르다). 해시 형식 번호(ADR-0014)는 10 으로 올렸다.

### 12.1 투영이 소유하는 부속 (공통 메커니즘)
꺾인 계단의 단 묶음·층참과 슬래브 구멍은 요소 하나가 IFC 엔티티 여럿으로 나가는 첫 경우다. 문의 개구부(요소당 하나, `openings` 사전)와 달리 요소당 여럿이라 `IfcModel.parts`(요소 id → {이름표: 엔티티})를 두었다.
- GlobalId = `part_guid(요소 id, 이름표)`(uuid5, 프로젝트 무관). 이름표: `flight:0`·`flight:1`·`landing`, `opening:0..31`. 내보냈다 가져와 다시 투영해도 같은 값이 나온다.
- `_sync_parts(eid, wanted)`: 이름표 순서로 만들고, 있는 것은 제자리에서 고치고, 더는 없는 것은 지운다. 요소를 지우면 부속이 먼저 간다.
- 가져오기: 저작 요소로 되살아난 슬래브·계단의 부속은 요소 행을 만들지 않는다(`owned`). 요소 클로저가 부속의 형상을 포함한다(슬래브: 구멍 개구부의 형상, 계단: 집합된 부속의 형상). 외부에서 부속 형상을 바꾸면 그 요소가 분리(동결)된다. 부속이 없는 요소의 클로저는 이전과 같다.

### 12.2 꺾인 계단 (L형·U형, 층참)
`stair` 의 선택 파라미터 `turn` = `{type: "L"|"U", side: "left"|"right", risers_a, landing, gap}`. 없으면 직선 계단(변화 없음).

| 필드 | 의미 |
|---|---|
| `run`(기존) | 층참 **아래** 단 묶음의 걸음선. 끝이 층참 가까운 변 |
| `risers_a` | 층참 아래 단 묶음의 챌판 수(2 이상, 전체 - 2 이하: 위 묶음도 챌판 둘 이상). 층참 윗면 = 레벨 + base_offset + risers_a × 챌판 높이 |
| `landing` | 층참 깊이 mm(걸음선 방향, 비우면 폭, 폭 미만 불가) |
| `side` | 꺾는 쪽(걸음선 진행 방향 기준) |
| `gap` | U형 두 단 묶음 사이 간격(기본 100, L 은 0) |

배치는 순수 함수 `kinds.stair_layout`(그리기·IFC 가 같은 값을 쓴다). 디딤판 깊이는 두 묶음이 같다(`run` 길이 ÷ (risers_a - 1)). L형은 위 묶음이 층참의 옆변 중앙에서 90도로, U형은 가까운 변에서 옆 칸(폭 + 간격)으로 되돌아 오른다. 위 묶음은 밑을 층참 두께(150mm)만큼 더 채운다.
- 커맨드: `stair.create`·`stair.set` 의 `turn`, `stair.set` 의 `clear_turn`. 챌판 분배·층참 깊이는 두 커맨드가 `kinds.stair_turn_problem` 으로 검사한다(챌판 수를 줄여 `risers_a` 가 넘치면 거절).
- IFC: `IfcStair`(QUARTER_TURN_STAIR / HALF_TURN_STAIR, 자신의 몸체 없음)에 `IfcStairFlight` 둘(톱니 옆모습 압출, NumberOfRisers·NumberOfTreads·RiserHeight·TreadLength)과 층참 `IfcSlab`(LANDING)을 `IfcRelAggregates` 로 집합. 직선으로 되돌리면 부속이 지워지고 몸체가 돌아온다.
- 평면: 단 묶음마다 직선 계단 규약(윤곽·디딤판 선·절단선). 절단 높이가 층참 윗면 이상이면 층참 윤곽(`proj`)을 그리고 **걸음선이 층참 안에서 꺾여 위 묶음으로 이어지는** 화살표(`symbol`, 화살촉은 위 묶음 끝)를 그린다. 층참 윗면 아래에서 자르면 아래 묶음만 절단선과 함께 그린다(위 묶음·층참은 생략).
- 단면·입면: 단 묶음의 디딤 조각과 층참 판(두께 150)이 같은 합집합 윤곽·가림 판정에 들어간다.
- 한계: 층참 하나·단 묶음 둘(두 번 꺾이는 계단·삼각 디딤판·곡선 계단 없음). 위층 평면에서 아래층에서 올라오는 부분은 직선 계단과 같이 그리지 않는다.

### 12.3 슬래브 구멍 (계단실·샤프트)
`slab` 의 선택 파라미터 `openings` = 다각형 목록(최대 32). 커맨드: `slab.create`·`slab.set` 의 `openings`(전체 교체)·`clear_openings`, `slab.move` 가 구멍도 옮긴다. 검사(`kinds.openings_problem`): 각 구멍은 올바른 다각형(반시계 저장)이고 슬래브 경계 **안쪽**에 있으며(경계와 만나지 않는다) 서로 겹치지 않는다.
- 면적: `element.get` 의 파생값에 `area_m2`(구멍을 뺀 값)·`opening_area_m2`·`openings` 가 더해진다(구멍 없는 슬래브의 응답은 그대로).
- IFC: `IfcOpeningElement`(경계 압출, 슬래브보다 위아래 10mm 길게) + `IfcRelVoidsElement`. 문의 개구부와 달리 채우는 요소가 없다.
- 평면: 슬래브가 절단 높이 아래(윗면 < 절단 높이)면 구멍을 윤곽(`proj`)과 **X 표시**(`symbol`: 사각형은 두 대각선, 볼록이면 무게중심에서 꼭짓점으로, 오목이면 윤곽만)로 그린다. 절단 높이가 슬래브 두께 안이면 구멍 윤곽도 절단선이다. 슬래브가 절단 높이 위면 그리지 않는다.
- 단면: 절단 사각형 구간을 짝수-홀수 규칙에 구멍 둘레를 더해 구하므로 구멍을 지나는 구간이 빠진다.
- 한계: 입면·단면 뒤쪽의 가림 판정용 조각(경계 삼각형 분할)은 구멍을 뚫지 않는다(구멍을 통해 보이는 것이 슬래브에 가려질 수 있다: 17.3 에서 고쳤다). 평면 절단 채움은 구멍을 비우지 않았다(13.3 에서 비운다).

### 12.4 난간 (`railing`, 새 종류)
`IfcRailing`, 투영 순서 1, 관계 `on_level`, `geometric`.

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `path` | 난간선 꼭짓점 `[[x,y],...]`(2~256, 열린 선, 이웃 꼭짓점 1mm 이상) |
| `height` | 난간 높이 mm(바닥 마감에서 손잡이 윗면까지, 기본 1100) |
| `base_offset` | 레벨에서 난간선 시작점의 바닥 마감까지 |
| `rise` | 끝점의 바닥 마감이 시작점보다 더 높은 만큼(경사 난간, 선 길이에 비례해 오른다. 평평하면 0) |

형상은 `kinds.railing_geom`(손잡이 윗선 3D 폴리라인 + 기둥, 기둥 간격 ≤ 1200mm)이 정한다. 커맨드: `railing.create/set/move/delete`, `railing.from_stair`(단 묶음 양 옆에 경사 난간, 꺾인 계단이면 층참의 트인 가장자리에 평평한 난간), `railing.from_slab`(바깥 경계 또는 구멍의 변 선택, 이어진 변은 한 난간·모든 변이면 닫힌 한 줄). 자동 생성은 `ctx.new_id` 순서로 id 를 매겨 같은 입력이면 같은 id·순서다.
- IFC: `IfcRailing`(GUARDRAIL), 몸체는 손잡이 `IfcSweptDiskSolid`(반지름 25) + 기둥마다 수직 `IfcSweptDiskSolid`(반지름 15). 속성·재료 없음(필요하면 `pset.set`).
- 평면: 바닥 마감선이 절단 높이 이하인 부분의 난간선을 투영선으로(경사 난간은 절단 높이에서 끊는다). 단면·입면: 손잡이선과 기둥을 투영선으로, 앞의 벽·슬래브·계단·패밀리가 가린다. 난간은 다른 요소를 가리지 않는다.
- 한계: 난간선은 평면상 꺾이는 점에서 선 길이로 rise 를 나누므로 계단 옆 난간은 단 묶음마다 하나다. 계단과 난간의 연결(계단을 옮기면 난간이 따라 옮겨지는 관계)은 17.1 에서 더했다(`src` 출처 표식: 이전에 낸 난간은 연동되지 않는다).

### 12.5 `space.from_walls` (공간 자동 생성)
`space.from_walls(level, points | all, edge, category, height, min_area_m2)`. 새 요소 입력은 없고 기존 `space` 요소를 만든다(해시 형식 영향 없음). 순수 기하는 `regions.py`: 저작 벽 축선을 서로의 교점·T 접합점에서 잘라 평면 그래프를 만들고, 막다른 벽을 걷어낸 뒤 반변 따라가기로 면을 얻는다(반시계 = 방).
- `points`: 각 점을 둘러싼 가장 작은 영역마다 공간 하나(같은 영역을 가리키는 점은 하나로). 닫힌 영역에 들지 않으면 거절(CONSTRAINT)한다. `all`: 레벨의 모든 닫힌 영역(`min_area_m2` 미만은 건너뜀). 같은 경계의 공간이 이미 있으면 건너뛴다(다시 실행해도 중복이 없다).
- `edge`: `inner`(기본) = 변마다 벽 두께의 절반만큼 안쪽 선들의 교점(실 면적), `center` = 벽 중심선. 안쪽 면을 구하지 못하면 중심선으로 만들고 경고한다.
- 결정성: 벽을 id 로 정렬하고 방을 (가장 왼쪽-아래 꼭짓점, 면적)으로 정렬하며 다각형은 그 꼭짓점에서 시작한다. id 는 `ctx.new_id("space")` 순서다. 입력 벽 순서가 달라도 같은 방을 낸다(시험).
- 한계: 직선 벽만(곡선 벽 종류가 엔진에 없다). 방 안의 따로 떨어진 섬(연결되지 않은 닫힌 벽)과 기둥을 구멍으로 빼는 것은 17.2 에서 더했다. 벽이 열려 있으면(문이 아니라 벽 자체가 끊김) 영역이 아니다. 문 개구부는 벽이 이어져 있으므로 영역을 가르지 않는다.

### 12.6 승강기·지붕 평면 (설계 메모, 13절에서 구현)
- 승강기: 샤프트는 슬래브 구멍(12.3) + 벽으로 이미 표현할 수 있다. 남는 것은 카(`IfcTransportElement` ELEVATOR) 요소다. 안: `elevator` 종류 = (`level`, 샤프트 안쪽 사각형 `shaft`, 카 크기 `cab` [폭, 깊이, 높이], 서비스 레벨 목록 `stops`) 한 요소, IFC 는 `IfcTransportElement`(ELEVATOR) 한 개(카 상자 몸체)와 층마다 문 개구부는 벽 문 요소를 쓴다. 평면은 카 외곽(`proj`)과 대각 X(`symbol`)에 "EV" 문자를, 단면·입면은 카 상자의 절단·가림 조각이다. 레벨마다 슬래브 구멍이 샤프트와 같은지 검사(`model.validate` 경고).
- 지붕 평면: 지금은 `slab`(PredefinedType ROOF 는 아직 없음)로 평지붕만 가능하다. 안: `slab.create` 의 선택 `kind: "roof"` 로 IFC PredefinedType 만 ROOF 로 바꾸고, 경사 지붕은 `roof` 종류(`boundary`, `slope` [방향, 경사], `overhang`)로 분리한다. 지붕 평면 뷰는 `view.create type=plan` 에 레벨(최상층 + 1)의 절단 높이를 지붕 위로 줘서 ROOF 슬래브 윤곽·배수 방향 화살표(`symbol`)를 그리는 것으로 시작한다.
- 둘 다 부속 메커니즘(12.1)과 선택 파라미터 규약(요소 행에 키가 없으면 바이트 동일)을 그대로 쓰면 된다.

## 13. 승강기·지붕 평면 (열한 번째 작업)

12.6 의 안을 구현했다. 모두 **새 종류(`elevator`) 또는 슬래브의 선택 입력**이다. 승강기가 없고 슬래브에 지붕 입력이 없는 프로젝트의 요소 행·상태/파생/IFC 해시·도면 산출은 이전과 바이트까지 같다(시험 `test_승강기가_없으면_도면이_바뀌지_않는다`, `test_지붕이_아닌_슬래브의_도면은_바뀌지_않는다`). 해시 형식 번호(ADR-0014)는 11 로 올렸다.

### 13.1 승강기 (`elevator`, 새 종류)
`IfcTransportElement`(ELEVATOR), 투영 순서 1, 관계 `on_level`(카가 서는 가장 아래 정차층), `geometric`.

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `shaft` | 샤프트 안쪽 사각형 `[x1,y1,x2,y2]` mm(저장은 최소·최대로 정렬, 각 변 800mm 이상) |
| `cab` | 카 크기 `[폭(x), 깊이(y), 높이]` mm. 폭·깊이는 샤프트 안쪽 이하, 높이는 `rise` 이하. 카는 샤프트 가운데에 놓인다 |
| `base_offset` | 레벨에서 카 바닥(= 샤프트 아래)까지 |
| `rise` | 샤프트 높이(카 바닥에서 샤프트 위까지) |

형상은 순수 함수 `kinds.elevator_geom`(그리기·IFC·슬래브 구멍이 같은 값)이다. 설계 메모의 `stops`(정차층 목록)는 두지 않았다: 위 정차층은 `elevator.create` 의 입력 `to_level`(+ `overrun`)로 받아 **그 시점의 `rise` 값으로 저장**한다(이후 레벨을 옮겨도 따라가지 않는다. `elevator.set` 의 `rise` 로 고친다). 정차층마다 문은 벽 문 요소를 쓴다.
- 커맨드: `elevator.create/set/move/delete`, `elevator.cut_slabs`. `element.get` 의 파생값 = 샤프트 아래·위 높이, 샤프트·카 면적.
- `elevator.cut_slabs(id, clearance)`: 샤프트의 높이 범위를 지나는 저작 슬래브(밑면 < 샤프트 위 - 1mm, 윗면 > 샤프트 아래 + 1mm)마다 샤프트 사각형(사방 `clearance` 만큼 넓힘)을 구멍(12.3 `openings`)으로 더한다. 카가 서는 바닥 슬래브(윗면 = 샤프트 아래)는 건드리지 않고, 위 정차층 바닥 슬래브는 샤프트가 지나므로 구멍이 난다. 같은 구멍이 이미 있으면 `already`, 경계 밖이거나 다른 구멍과 겹치면 `skipped`(이유 포함)로 알리고 건너뛴다. 슬래브 id 순으로 처리하므로 같은 입력이면 같은 결과다(다시 실행해도 중복 없음).
- IFC: `IfcTransportElement`(ELEVATOR)의 몸체는 **카 상자 하나**(`IfcExtrudedAreaSolid`, 카 바닥에서 카 높이만큼). 샤프트는 IFC 에 따로 내지 않고 슬래브 구멍(IfcOpeningElement)과 벽이 표현한다. 속성·재료 없음(`pset.set`). 가져오기 시 `IfcTransportElement` 가 의도(DoBIM_Intent)와 형상이 맞으면 저작 `elevator` 로 되살아나고 해시 3종이 같다. 외부에서 형상을 바꾸면 분리(동결)된다.
- 평면: 절단 높이가 샤프트 높이 범위(아래·위 포함)에 드는 **모든 층의 평면**(승강기가 놓인 레벨만이 아니다)에 샤프트 윤곽과 카 윤곽(`proj`), 카의 대각 X(`symbol`), 카 가운데 위쪽에 `EV` 문자를 그린다. 카는 정차층에만 있지만 관행대로 지나는 모든 층에 같은 기호를 그린다.
- 단면·입면: 샤프트 상자와 카 상자의 모서리를 투영선(`proj`)으로 그린다. 앞의 벽·슬래브·계단·패밀리가 가리고, 승강기는 다른 요소를 가리지 않는다(선만 그린다). 단면은 상자를 절단하지 않는다(절단선·채움 없음).
- 검사: `model.validate` 는 `LEVEL_MISSING` 만 본다. 설계 메모의 "레벨마다 슬래브 구멍이 샤프트와 같은지 검사"(경고)는 만들지 않았다(`elevator.cut_slabs` 로 구멍을 내고 다시 실행하면 `already`/`skipped` 로 상태를 알 수 있다).
- 한계: 카·샤프트는 직육면체(문 위치·도어 방향·기계실·피트 없음). 정차층별 문 개구부는 만들지 않는다. 승강기를 옮기면 이미 낸 슬래브 구멍은 따로 옮겨지지 않는다(`slab.set` 으로 고치거나 구멍을 지우고 `elevator.cut_slabs` 를 다시 쓴다). → 16절에서 피트·기계실·승강장 문·구멍 연동을 더했다(도어 방향은 여전히 없다).

### 13.2 지붕 슬래브와 지붕 평면 (`slab` 의 선택 입력)
`slab` 의 선택 파라미터 `use`·`fall`·`drains`(없으면 키 자체가 없다). 설계 메모의 `kind: "roof"` 는 행 종류(`kind`)와 헷갈려 `use` 로 부른다.

| 파라미터 | 의미 |
|---|---|
| `use` | `"roof"` 이면 지붕 슬래브(IFC PredefinedType ROOF). 일반 슬래브는 키가 없다(FLOOR) |
| `fall` | 배수 물매 `{"dir": 물이 흐르는 방향 도(+x 가 0, 반시계), "pct": 물매 %(0 초과 100 이하)}`. 지붕에만 |
| `drains` | 배수구 위치 `[[x,y],...]`(최대 32). 슬래브 경계 안쪽·구멍 밖. 지붕에만 |

- 커맨드: `slab.create` 의 `use`·`fall`·`drains`, `slab.set` 의 `use`(`roof`/`floor`: floor 는 `fall`·`drains` 도 지운다)·`fall`·`clear_fall`·`drains`·`clear_drains`, `slab.move` 가 배수구도 옮긴다. 검사는 `kinds._slab_params`(지붕이 아닌데 물매·배수구, 배수구가 슬래브 밖·구멍 안이면 거절).
- 물매는 **표기용**이다. 슬래브 형상은 평평하게 두고(물매는 마감 모르타르로 만든다) 지붕 평면에 방향과 크기만 그린다.
- IFC: `IfcSlab` 의 PredefinedType 만 FLOOR → ROOF 로 바뀐다. 물매·배수구는 IFC 엔티티가 아니라 의도(DoBIM_Intent)로만 왕복한다(가져오면 그대로 되살아나고 해시 3종이 같다). 외부에서 PredefinedType 을 바꾸면 분리된다.
- 지붕 평면 뷰는 새 뷰 종류가 아니라 **지붕 레벨의 평면 뷰**다: 지붕 슬래브를 지붕 레벨에 놓고 `view.create type=plan` 의 절단 높이를 슬래브 윗면 위로 준다(예: `cut_height` 1200). 절단 높이가 슬래브 윗면 위인 지붕 슬래브는 윤곽(`proj`), 물매 화살표(`symbol`, 슬래브 무게중심에서 길이 용지 12mm, 큰 슬래브가 아니면 짧아진다)와 "물매 N%" 문자, 배수구 기호(`symbol`: 반지름 용지 1.5mm 의 원과 십자)를 그린다. 구멍이 있으면 12.3 의 구멍 윤곽·X 도 함께 나온다. 절단 높이가 슬래브 두께 안이면 평소처럼 절단선만 그린다.
- 단면·입면은 지붕 슬래브도 일반 슬래브와 같은 모양이다.
- 한계(경사 지붕·파라펫은 16절에서 더했다): **경사 지붕**(설계 메모의 `roof` 종류: 경계·방향·경사·처마)은 만들지 않았다.
 지붕 슬래브는 평평한 판이다. 지붕 평면에서 파라펫·옥상 설비·지붕 선(용마루)·단면 물매 표기는 없다. 지붕 위에 올라온 승강기 기계실(샤프트 `rise` 가 지붕 위로 나간 부분)은 샤프트 윤곽이 지붕 평면의 절단 높이에 따라 보일 수 있다.

### 13.3 평면 절단 채움이 슬래브 구멍을 비운다 (12.3 의 한계 해소)
절단 높이가 슬래브 두께 안이라 평면에서 슬래브를 절단 채움(`view_fills`)으로 칠할 때, 구멍이 있으면 채움이 구멍을 뺀다. 채움 목록의 항목은 여전히 슬래브당 **다각형 하나**다(내보내기(SVG·PDF)·시트 렌더가 항목마다 한 경로로 칠하므로 소비자 코드는 그대로다).
- 방법: `drawing.fill_ring` 이 경계(반시계)에 구멍(시계 방향으로 뒤집음)을 **폭 0 의 틈(브리지)으로 이어 붙인 고리 하나**를 만든다. 비영 규칙·짝수-홀수 규칙 모두 구멍이 비고, 틈은 같은 점을 지나는 두 변이라 칠하는 쪽에 자국이 남지 않는다. 구멍은 왼쪽 끝 꼭짓점 (x, y) 순으로 하나씩, 이미 이어진 고리의 꼭짓점과 가장 가까우면서 어떤 변과도 만나지 않고 중점이 영역 안인 쌍으로 잇는다(거리·인덱스 순 결정적). 구멍이 여럿이거나 경계가 오목해도 된다(시험: ㄴ자 경계 + 구멍 3개의 격자 점 검사, 면적 = 경계 - 구멍).
- 바이트 불변: **구멍이 없는 슬래브의 채움은 이전과 같다**(경계 그대로, `fill_ring` 을 부르지 않는다). 구멍이 있는 슬래브가 절단 높이에 걸린 평면의 채움 데이터만 바뀐다(선분은 그대로: 구멍 둘레는 12.3 대로 절단선).
- 한계: 이을 수 없으면(후보가 4만 쌍을 넘거나 어떤 쌍도 막힘) 옛 채움(경계만)으로 돌아간다. 단면의 채움은 12.3 에서 이미 구멍 구간이 빠졌다.


## 14. 대지 단면·조경/공개공지·주차 계획·간판 (열두 번째 작업, 법정 P-03·P-05·P-06·E-03)
다섯 입력을 새 종류로 둘지 기존 요소의 속성으로 둘지부터 정했다. 결론은 **새 종류 없음**이다.

| 입력 | 둘 곳 | 이유 |
|---|---|---|
| 지반 표고점 `terrain` | `site` 의 선택 파라미터 | 지반은 대지에 속하고 대지가 지워지면 같이 사라져야 한다. 독립 요소로 두면 대지와의 관계(`on_site`)·고아 규칙·병합 검사가 새로 필요하다 |
| 조경·공개공지 영역 `zones` | `site` 의 선택 파라미터 | 영역은 대지 경계 안에서만 뜻이 있다(검사: 모든 꼭짓점이 대지 안, 경계 위 포함). 대지 경계를 줄이면 밖으로 나간 영역을 가진 채로 저장되지 않는다(`site.set` 이 거절) |
| 주차 계획 `parking` | `site` 의 선택 파라미터 | 주차면·차로·동선은 한 계획의 세 부분이고 대수는 합계로만 뜻이 있다 |
| 간판·건물번호판 `signs` | `site` 의 선택 파라미터 | 벽 id 를 가리키지 않고 **방위(face)와 평면 위치**로 면을 정한다. 벽을 나누거나 합쳐도 참조가 끊기지 않는다(벽에 달면 `wall.split` 이 간판을 나눠야 한다). 간판은 광고물 허가 대상이라 대지 단위 설치 계획으로 보는 편이 도서(배치도·입면)와 맞는다 |
| 대지 단면 | `view` 의 선택 파라미터 `with_site`(단면 뷰) | 새 뷰 종류는 도면 코드 전체(뷰 설정 튜플의 모든 분기)에 걸쳐 퍼진다. 종·횡 두 방향은 절단선이 다른 단면 뷰 두 개로 만든다(절단선이 대지를 지나는 구간만 그린다) |

선택 파라미터는 모두 **없으면 키 자체가 없다**: 이 입력이 없는 프로젝트의 요소 행·상태·파생·IFC 해시와 모든 도면은 바이트까지 이전과 같다(시험: 더했다 `clear` 로 지우면 해시 3종과 뷰 데이터가 처음과 같다). `site.set` 은 각 속성을 통째로 바꾸고 `clear` 로 지운다. 해시 형식 번호는 11 → **12** 로 올렸다(ADR-0014: 가져온 프로젝트를 한 번 다시 판정할 뿐 제품 클로저는 같다).

### 14.1 입력 모양
| 속성 | 모양 |
|---|---|
| `terrain` | `[[x,y,z],...]`(1~64). z 는 모델 기준 높이 mm(1층 바닥 0, 아래는 음수). 점 위면 그 값, 그 밖은 **거리 제곱 역가중 평균**으로 보간한다(사칙연산만이라 결정적) |
| `zones` | `[{"use": "landscape"\|"open_space", "name", "boundary"}...]`(1~32). 다각형은 반시계로 저장 |
| `parking` | `{"bays": [{"origin","angle","count","w","d","accessible"?}], "aisles": [{"path","width"}], "routes": [{"path"}]}`(키는 있는 것만). 주차면 배열은 시작 모서리에서 `angle` 방향으로 폭 `w` 씩 `count` 칸, 깊이 `d` 는 그 왼쪽. 기본 2500x5000. `accessible` 은 참일 때만 저장 |
| `signs` | `[{"name","kind": "sign"\|"address","face": "N"\|"E"\|"S"\|"W","center","z","w","h","text"}...]`(1~32). `face` 는 붙은 벽 면이 바라보는 방위(입면 뷰 `dir` 과 같은 면에 그려진다), `z` 는 아래 모서리 높이 |

### 14.2 도면 표현
- **배치도**: 영역은 윤곽(`proj`)과 해치(`hatch`: 조경 45도, 공개공지 135도, 간격 3.5mm x 축척, 세계 격자에 맞춰 영역이 달라도 무늬가 이어진다)와 "이름 면적㎡" 문자, 대지 문자 아래에 영역 종류별 **면적 합계**와 대지면적 대비 %. 주차면은 사각형 윤곽(`proj`)과 배열별 "주차 N대"/"장애인 N대", 차로는 양쪽 선(`proj`), 진출입 동선은 선과 화살표 머리·시작 가로대(`symbol`), 마지막에 "주차 합계 N대(장애인 전용 M대)".
- **입면**: 뷰 `dir` 과 같은 `face` 의 간판·번호판 사각형(`symbol`)과 "간판 이름 폭x높이" 문자(사각형 위), 문구(안). 벽 가림 판정은 하지 않는다(벽 앞면에 붙은 것으로 본다).
- **대지 단면**(`view.create type=section with_site=true`): 절단선이 대지 경계 안쪽인 구간에 지반선(`cut`, 표본 간격 1m·최대 400점), 지반 아래 사선 눈금(`hatch`), GL 수평선(`proj`), 구간 시작·끝이 경계를 가로지르는 곳의 세로 표시(`symbol`)와 "대지 경계" 문자. GL 은 건물 외곽 경계 상자 가운데의 지반 높이(건물이 없으면 표고점 평균, 표고점이 없으면 0)이고 문자는 "GL +값"(대지에 `elevation` 이 있으면 "(EL +m)" 도). 표고점이 없으면 지반은 모델 0 높이의 수평선이다.
- 쿼리는 모두 뷰 단위 증분 노드다(`VIEW_SCOPED` 에 등록). 시험이 증분 == 전체 재계산을 본다.

### 14.3 IFC
새 IFC 엔티티를 만들지 않는다: 속성은 `IfcSite`(하위 대지)의 `DoBIM_Intent` 로 왕복하고(가져오면 경고 없이 같은 값으로 되살고 해시 3종이 같다), 대지 단면 뷰는 다른 뷰처럼 `DoBIM_Defs` 정의로 실린다. 표준 매핑(조경·공개공지 = 외부 `IfcSpace`, 주차면 = `IfcSpace` PARKING 분류, 간판 = `IfcSign`(IFC4X3 전용)·`IfcGeographicElement`)은 쓰지 않았다: IFC4 에는 간판 클래스가 없고, 영역·주차면을 IfcSpace 로 내려면 대지 밖 엔티티가 요소 행과 1:1 이어야 해서 종류를 따로 세워야 한다. 외부 도구가 보려면 이 단계의 한계다.

### 14.4 한계
- 지반은 표고점의 역거리 보간이라 등고선·경사면 삼각망(TIN)이 아니다. 단면 지반선은 표본 간격 1m 로 꺾인 선이다. 자연지반/인공지반 구분(N-07)은 없다.
- 영역끼리 겹치는지·주차면이 건물·영역과 겹치는지·진출입 동선이 대지 경계와 도로에 닿는지는 검사하지 않는다(입력 책임). 면적 합계는 겹침을 두 번 센다.
- 주차 대수는 입력한 칸 수 그대로다(법정 설치 대수 산정·주차 구획 규격 검사 없음). 주차 경사로·기계식 주차는 없다.
- 간판은 직사각형이고 벽 두께·돌출·조명·마감·벽에 붙은 높이 검사가 없다. 평면·배치도에는 간판을 그리지 않는다(입면만).
- 대지 단면에서 지반 아래 건물(지하층) 표현·흙막이·성토·절토 구분은 없다.

## 15. 수직동선 상세·승강기 치수·입면 마감 옵션·시트 방위 (열세 번째 작업, B-05·L-10)
새 요소 종류와 새 뷰 종류는 만들지 않았다. 계단·승강기 상세 도면은 **기존 평면·단면 뷰에 선택 옵션을 더하는 방식**이다(`with_site` 와 같은 패턴: 없으면 키 자체가 없고, 옵션이 없는 뷰는 정의·IFC·도면이 바이트까지 그대로다). 해시 형식 번호는 12 → **13** 으로 올렸다(뷰 정의에 새 선택 키가 생겼다. 가져온 프로젝트를 한 번 다시 판정할 뿐 제품 클로저는 같다).

### 15.1 뷰의 선택 옵션
| 옵션 | 뷰 종류 | 의미 |
|---|---|---|
| `crop` `[x1,y1,x2,y2]` | 평면·단면·입면 | 부위 상세. 뷰 좌표(평면은 모델 x,y mm / 단면·입면은 가로 s·절대 높이 z)의 사각형으로 선·채움·문자를 잘라 그린다(선은 Liang-Barsky, 채움은 Sutherland-Hodgman). 사각형 밖 문자는 뺀다. 잘라낸 경계에는 선을 그리지 않는다 |
| `dims` `true` | 평면·단면 | 뷰에 보이는 계단·승강기의 치수를 자동으로 단다(아래). `crop` 이 있으면 그 사각형과 겹치는 요소만 |
| `finish` `true` | 입면 | 외부 마감 해치와 재료 문자를 그린다(15.4) |
| `around` + `margin` | `view.create` 만 | 계단·승강기 id 를 주면 그 요소가 뷰 안에서 차지하는 범위 + `margin`(기본 1000mm)을 `crop` 으로 계산해 **저장한다**(요소 참조는 남기지 않는다). 이후 요소를 옮겨도 `crop` 은 그대로이고, 다시 맞추려면 `view.set crop` 을 쓴다 |

`view.set` 은 `crop`·`clear_crop`·`dims`·`finish` 를 받는다(거짓·없애기는 키 삭제). 종류에 맞지 않는 옵션(평면에 `finish`, 입면에 `dims`, 배치도에 `crop`)은 거절한다. 요소 참조를 저장하지 않은 이유: 참조를 두면 요소 삭제·병합 때의 id 치환과 고아 뷰 규칙이 새로 필요하다. 상세 뷰는 만든 시점의 범위를 쓰는 정적 부위 뷰가 도서 관행과 맞는다(상세 위치를 시트의 부위 상세 표시 `callouts` 가 따로 가리킨다).

### 15.2 계단·승강기 치수 (dims)
치수 항목은 연관 치수 주석과 같은 모양(`("dim", id, 보조선 둘, 치수선, 글, 글 위치, 방향)`, id 는 `detail:<요소 id 끝 6자>:...`)이라 SVG·PDF·시트가 그대로 그린다. 치수선은 대상에서 용지 6mm(승강기 두 번째 줄은 9.6mm) 떨어진다. 값은 저작 요소 파라미터에서 바로 계산한 순수 함수다(`drawing.view_dims`, 뷰 단위 증분 노드).
- **계단 평면**: 단 묶음마다 왼쪽 옆선을 따라 디딤 사슬 `td x (n-1) = 길이`, 폭(첫 단 묶음은 시작 끝, 둘째는 위 끝), 꺾인 계단은 층참의 두 변 `층참 L`. 걸음선 오른쪽에 문자 `N단 챌판 R 디딤 td`(`R` 은 소수 첫째 자리까지, 정수면 정수).
- **계단 단면**(걸음선이 단면과 나란한 단 묶음만, |cos| ≥ 0.999): 단 묶음 밑 디딤 사슬, 위 끝의 오름 사슬 `R x n = 높이`, 첫 챌판 높이 `R`, 첫 디딤판 깊이 `td`, 난간 높이 `난간 H`(같은 자리·높이의 난간은 하나), 꺾인 계단은 층참 윗면 높이 문자 `층참 +z`. 걸음선에 수직인 단면은 계단 치수를 달지 않는다.
- **승강기 평면**(L-10): 카 폭·깊이(`카 1100`)와 샤프트 폭·깊이(`샤프트 1800`)를 두 줄 치수선으로(안쪽이 카, 바깥이 샤프트). 승강기가 지나는 모든 층 평면에 단다(옵션을 켠 뷰에만).
- **승강기 단면**: 카 높이 `카 H`, 오버헤드 `OH`(샤프트 위 - 카 천장), 승강로 전체 `승강로 H`, 카 바닥이 정차층 아래(`base_offset < 0`)이면 피트 `피트 D`.
- 평면 치수는 절단 높이가 계단 아래 끝보다 낮으면 달지 않는다(계단이 안 그려지는 평면).

### 15.3 L-10 과 바이트 불변의 충돌
L-10 은 승강기 평면에 샤프트·카 치수가 있어야 한다. 이미 있는 승강기 평면(`EV` 문자·윤곽·X)에 치수를 기본으로 더하면 승강기가 있는 모든 평면 도면의 바이트가 바뀌므로, **뷰 옵션 `dims` 로 켠다**(옵션이 없는 뷰는 그대로). 시험이 옵션을 켰다 끄면 뷰 데이터와 해시 3종이 처음과 같음을 본다.

### 15.4 입면 외부 마감 해치 옵션화 (품질 수정, 기존 산출이 바뀐다)
이전에는 `Pset_WallCommon.IsExternal` 이 참이고 재료가 있는 벽의 입면 앞면 **전체에** 45도 해치와 재료 문자를 깔았다. 층 구성이 있는 벽은 재료가 "가장 두꺼운 층"(구조체, 예: 철근콘크리트)이라 입면 벽 전체에 구조체 이름이 깔렸다. 입면 관행은 벽 전체 해치가 아니라 마감 표기다. 고친 것:
1. 해치·재료 문자는 뷰의 **`finish` 옵션을 켠 입면에만** 그린다(기본은 그리지 않는다). 옵션이 없는 입면은 외부 벽이 있어도 선 윤곽만 나온다.
2. 재료 문자는 `material.set` 으로 지정한 **마감 재료**만 쓴다(`Q.material` 이 아니라 지정 재료 입력). 층 구성(`wall.layers`)을 주면 재료는 층 구성이 정하므로(지정 재료가 지워진다) 구조체 이름을 입면에 깔지 않는다 — 층 구성 외벽에는 입면 마감 표기가 없다(한계).
영향: 외부 마감 재료를 가진 프로젝트의 입면 도면이 바뀐다(해시는 불변: 뷰 데이터는 파생물이다).

### 15.5 시트 방위 각 기본값 (품질 수정)
시트 표제란 방위표는 `north_angle`(기본 0 = 도면 위가 정북)을 그렸고 배치도 방위표는 대지의 정북 각만큼 기울어, 대지가 있는 모델의 시트(배치도가 아닌 도면)와 배치도가 진북·도북이 어긋났다. `sheet.export`·`sheet.define` 의 `north_angle` 을 **생략하면 대지의 정북 각**(`site.north_angle`, 대지가 둘 이상이면 id 순 첫째, 없으면 0)으로 정한다. `sheet.define` 은 정한 숫자를 저장한다(저장 형식은 그대로 숫자라 정의 형식·IFC 왕복 불변: 명시한 값과 대지가 없는 프로젝트는 이전과 같다). 로그에 기본값이 남지 않게(`log_args` 가 null 을 뺀다) 기본값을 `None` 으로 두었다.

### 15.6 (c) 단면선과 개구부
도면 엔진이 문·창을 못 그리는 것이 아니라, 판정 시나리오의 기존 종단면(A-A, x=2000)이 문·창을 지나지 않아 개구부가 안 보였다. 기존 산출 바이트를 지키려고 A-A 는 그대로 두고 문 2개·창 1개를 지나는 단면 D-D(x=8300)를 새로 만들어 시트 A-017 에 올렸다(통과 여부는 벽 축선과 개구부 범위에서 독립으로 센다). 입면 창 모서리의 이상 표시는 이번에 점검하지 못했다(그림을 볼 수 없는 환경이라 수치만 확인했고, 입력 오류가 아니라는 근거도 없다: 미해결로 남긴다).

### 15.7 한계
- 요소 상세는 만든 시점 범위의 정적 crop 이다(요소를 옮기면 `view.set crop` 으로 다시 맞춘다). 잘라낸 경계에 파단선·테두리는 없다.
- 계단: 단면은 걸음선과 나란한 단 묶음만 치수(비스듬한 단면은 오름 치수만 불가). 곡선·삼각 디딤판·세 번 꺾인 계단 없음. 법정 계단 규격(챌판·디딤판 한계) 검사는 하지 않는다(표기만).
- 승강기: 샤프트 바닥 = 카 바닥이라 피트는 `base_offset < 0` 일 때만 표기, 기계실·문 위치·도어 방향·비상용 구분 없음. 코어(계단실+승강기) 통합 상세·주차경사로 상세 없음.
- 입면 마감: 층 구성 외벽은 마감 재료 표기가 없다(15.4).

## 16. 경사 지붕·파라펫·승강기 보강 (열네 번째 작업, 제도·관행 L-06·DM-09)
13.2·13.1 의 한계(경사 지붕·파라펫·승강장 문·피트·기계실·구멍 연동 없음)를 푼다. 새 종류는 `roof` 하나이고 나머지는 모두 기존 요소의 **선택 입력**이다(없으면 키 자체가 없다). 해시 형식 번호는 13 → **14** 로 올렸다(사유는 16.5).

### 16.1 `roof` 를 새 종류로 두고 `slab` 을 늘리지 않은 근거
| 판단 | `slab` 확장(경사 입력 추가) | 새 종류 `roof` (택함) |
|---|---|---|
| 형상 | 슬래브는 "경계 다각형 + 두께의 각기둥"이다. 슬래브 도면 함수 전부(절단 채움·구멍·가림 조각·층 구성·`railing.from_slab`·`elevator.cut_slabs`)가 평평한 윗면을 전제한다. 경사를 넣으면 모든 분기에 "경사면이면" 이 퍼진다 | 경사면은 평면 여러 개이고 용마루·추녀마루가 있다. 독립 종류가 순수 함수 `kinds.roof_geom` 하나에 형상을 모으면 그리기·IFC 가 같은 값을 쓴다 |
| IFC | `IfcSlab` 한 개 | IFC4 의 관행대로 `IfcRoof` 아래 경사면마다 `IfcSlab`(ROOF)가 집합한다(꺾인 계단의 단 묶음과 같은 투영 소유 부속, 10절) |
| 바이트 불변 | 슬래브 도면 코드를 건드려 회귀 위험 | 지붕이 없으면 새 코드가 모두 빈 값이다(시험) |

평지붕은 그대로 `slab` 의 `use=roof` 이고(13.2), 평지붕의 파라펫만 슬래브의 선택 입력이다(16.3).

### 16.2 경사 지붕 (`roof`)
`IfcRoof`, 투영 순서 1, 관계 `on_level`, `geometric`. 외곽은 **직사각형(회전해도 된다)** 이다.

| 매개변수 | 의미 |
|---|---|
| `name` | 이름 |
| `boundary` | 외곽 꼭짓점 4개 `[[x,y],...]` mm(반시계로 저장. 이웃 변 수직·반대 변 같은 길이, 변 500mm 이상). 처마 선이 되는 선 |
| `form` | `gable`(박공) · `hip`(모임) · `shed`(외쪽) |
| `pitch` | 물매 각도 도(0 초과 75 이하). 모든 경사면이 같다 |
| `overhang` | 처마 내밀기 mm(0~3000). 외곽에서 물매대로 더 내밀어 끝 높이 = `base_offset` - tan(물매) x `overhang` |
| `base_offset` | 레벨 높이에서 처마 선(외곽의 변)까지 |
| `thickness` | 지붕 두께 mm(윗면에서 수직 아래로) |
| `ridge` | (박공만, 있으면 `"short"`) 용마루를 짧은 변 방향으로. 없으면 긴 변 방향 |
| `dir` | (외쪽만, 필수) 물이 흐르는 방향 도(+x 가 0, 반시계) |

- 형상은 `kinds.roof_geom`(순수 함수, libm 없이 사칙연산과 `sincos_deg`): 박공 = 경사면 둘, 모임 = 사다리꼴 둘 + 삼각형(정사각형이면 넷 다 삼각형), 외쪽 = 경사면 하나. 용마루(`ridges`)·추녀마루(`hips`)·바깥 둘레(`perimeter`)·경사면마다 물이 흐르는 방향과 평면 방정식을 함께 낸다. 같은 입력이면 같은 값이다(시험).
- 커맨드: `roof.create/set/move/delete`. `roof.set` 은 `form` 을 바꾸면 쓸 수 없게 된 `dir`·`ridge` 를 지운다. `element.get` 파생값 = 처마 끝 최저·꼭대기 높이·내민 외곽 면적·면 수.
- 한계: 외곽은 직사각형뿐이다(L자·T자 지붕, 합각, 맞배 사이의 박공벽, 지붕창, 다락, 홈통은 없다). 경사면은 모두 같은 물매다.

### 16.3 지붕 슬래브의 파라펫
`slab` 의 선택 입력 `parapet` `{"height", "thickness"}`(지붕 슬래브 `use=roof` 에만). 슬래브 윗면 위로 `height`, 슬래브 경계에서 안쪽으로 `thickness` 두께의 띠가 경계를 한 바퀴 돈다. 안쪽 고리는 각 변을 안쪽으로 민 직선들의 이웃 교점(마이터, `kinds.parapet_ring`)이다. 두꺼워서 접히거나 안쪽 고리가 자기 교차하면, 구멍이 안쪽 고리 밖에 걸리거나 배수구가 파라펫 위에 있으면 거절한다. 구멍·배수구는 그대로 파라펫 안쪽에 있다.
- 커맨드: `slab.create`·`slab.set` 의 `parapet`, `slab.set` 의 `clear_parapet`(`use=floor` 로 되돌리면 함께 지운다).
- IFC: 슬래브에 집합한 `IfcWall`(PredefinedType PARAPET). 몸체는 바깥 둘레와 안쪽 고리 사이(`IfcArbitraryProfileDefWithVoids`)를 위로 압출한 것이다.

### 16.4 승강기 보강 (`elevator` 의 선택 입력)
| 입력 | 모양 | 뜻 |
|---|---|---|
| `pit` | mm(0 초과 5000 이하) | 피트 깊이: 카 바닥 아래로 더 내려간 샤프트 바닥. `base_offset` 이 음수인 기존 표기(피트 = 레벨 - 카 바닥)와 같은 선을 쓴다 |
| `machine` | `{"height"}` | 기계실: 샤프트 위에 같은 평면 크기로 얹는 상자 |
| `doors` + `stops` | `{"face": N\|E\|S\|W, "w", "h"}` + 레벨 id 목록 | 승강장 문 개구부: 샤프트의 한 면 가운데에 정차층마다 같은 크기로. 층의 레벨 높이에서 위로 `h`. 문 폭은 면보다 200mm 이상 좁고, 문이 샤프트 높이 범위에 들어야 한다(`elevator.create/set` 이 검사). `elevator.create/set` 의 인자는 `doors: {face, w, h, levels}` 이고 저장은 `doors` 와 `stops` 로 나뉜다(레벨 id 목록은 병합이 id 를 옮기는 `ids` 참조 형태) |
| `hole_slabs` + `hole_clearance` | 슬래브 id 목록 + mm | **승강기가 소유한 슬래브 구멍**(아래). `elevator.cut_slabs` 가 기록한다. 직접 쓰지 않는다 |

**구멍 연동(소유 추적)**: 승강기가 낸 구멍과 사용자가 직접 낸 구멍을 구분하는 방법은 *구멍에 표식을 달지 않고 승강기가 `슬래브 id + 여유`만 기억하는 것*이다. 구멍(`openings`)은 표식 없는 다각형 목록이라 구멍마다 소유자를 달면 슬래브 행 형식·병합·IFC 구멍 부속이 모두 바뀐다. 승강기 행에 `hole_slabs`(구멍을 낸 슬래브들)와 `hole_clearance`(그때의 여유)를 두면, 구멍 하나는 `샤프트 + 여유` 사각형과 꼭짓점이 같은 구멍으로 **재현**된다.
- `elevator.cut_slabs` 가 낸 슬래브만 `hole_slabs` 에 더한다(이미 같은 구멍이 있던 슬래브(`already`)는 사용자 구멍일 수 있어 소유하지 않는다). 여유를 바꿔 다시 부르면 소유한 구멍도 새 여유로 맞춘다(구멍이 둘로 늘지 않는다).
- `elevator.move`·`elevator.set`(샤프트가 바뀔 때)은 소유한 슬래브마다 `옛 샤프트 + 옛 여유` 와 같은 구멍 하나를 찾아 새 사각형으로 바꾼다(한 커맨드의 효과라 실행 취소가 승강기와 구멍을 함께 되돌린다). 다른 모양의 구멍, 소유하지 않은 슬래브의 같은 모양 구멍은 건드리지 않는다.
- 사용자가 고친·지운 구멍(옛 사각형이 없다)과 지운 슬래브는 따라가지 않고 응답의 `holes.lost` 에 알린다. 새 구멍이 슬래브 경계 밖이거나 다른 구멍과 겹치면 **이동 전체를 거절한다**(`CONSTRAINT`, 승강기도 그대로).
- 승강기를 지우면 구멍은 남는다(소유 기록만 사라진다). `cut_slabs` 의 구멍 범위(카 바닥~샤프트 위)는 피트·기계실과 무관하다.
- 이전에 낸 구멍(이 기능 전)은 소유 기록이 없어 따라가지 않는다: `elevator.cut_slabs` 를 다시 부르면 `already` 로 건너뛰고 소유하지 않으므로, 구멍을 지우고 다시 내야 연동된다.
- IFC: 입력은 모두 의도(DoBIM_Intent)로만 왕복한다. 카 상자 몸체는 그대로다(피트·기계실·문은 IFC 형상이 아니다).

### 16.5 해시 형식 14 와 바이트 불변
`CLOSURE_FORMAT` 13 → 14: 클로저에 **슬래브의 집합 부속**(파라펫)이 더해졌다(이전에는 계단만 부속을 담았다). 외부 도구가 슬래브에 부속을 붙여 낸 옛 파일은 가져올 때 분리로 판정된다(안전한 쪽). 지붕·파라펫·승강기 선택 입력이 없는 프로젝트는 요소 행·`state`·`derived`·`ifc` 해시와 도면 산출이 이전과 같다(시험: 입력을 더했다 지우면 뷰·해시가 처음과 같다).
- 의도된 변경: `elevator.cut_slabs` 가 승강기 행에 `hole_slabs`·`hole_clearance` 를 기록한다(구멍 연동의 전제). 이전 입력에 `cut_slabs` 가 있던 프로젝트는 승강기 요소 행·해시가 바뀐다. 도면 산출은 같다.
- 의도된 변경: `elevator.move` 가 소유한 구멍을 따라 옮긴다(옛 동작은 구멍을 두고 승강기만 옮겼다). 시험 `test_승강기_증분이_전체_재생성과_같다` 의 이동량을 경계 안에 머물게 고쳤다.

### 16.6 도면 표현
- **지붕 평면**(새 뷰 종류 아님): 지붕 레벨 평면 뷰의 절단 높이를 **지붕 꼭대기 위로** 주면 그린다(절단 높이가 지붕을 자르는 평면에는 그리지 않는다). 처마 내민 윤곽·외곽(처마 선)(`proj`), 용마루·추녀마루(`proj`), 경사면마다 물이 흐르는 방향 화살표(`symbol`, 몸통 + 20도 촉 둘), "물매 N°(가로 10 에 대한 세로)" 문자(예: `물매 30°(5.8/10)`), "용마루" 문자. 평지붕 파라펫은 절단 높이가 파라펫 안이면 바깥 둘레·안쪽 고리 절단선과 고리 채움(구멍 있는 슬래브와 같은 `fill_ring`), 파라펫 위면 안쪽 고리를 투영선으로.
- **단면**: 절단면이 경사면을 자른 띠(면마다 수직 두께 사각형 `(s,z)` 네 점)를 절단선·채움으로(`outline_edges` 합집합 윤곽). 파라펫은 슬래브 윗면에서 `height` 만큼의 띠 둘(바깥 둘레·안쪽 고리의 교차를 짝수-홀수로).
- **입면·단면의 윤곽과 가림**: 경사면 윗면의 모서리(용마루·추녀마루 포함)와 바깥 둘레의 아랫선·수직 모서리를 투영선으로. 지붕이 가리는 것은 "윗면 아래 ~ 처마 끝 높이"의 쐐기인데 가림 조각이 수직 기둥이라 **높이를 16 조각으로 나눈 수평 단면**(각 조각 윗면 높이의 단면: 보수적으로 작게)의 볼록 기둥으로 근사한다. 경사선은 `_visible_slanted` 로 가려낸다. 지붕은 승강기 샤프트 선을 가리고, 벽·슬래브·계단·패밀리는 지붕 선을 가린다.
- **승강기**: 평면은 정차층(문이 있는 층) 평면에서 샤프트 면의 선을 문 폭만큼 비우고 문설주 둘·문 선(`symbol`, 샤프트 안쪽 150mm)을 그린다. 카가 있는 높이만 `EV`·카·X 이고, 피트(카 바닥 아래)·기계실(샤프트 위) 높이의 평면은 샤프트 윤곽과 "피트"·"기계실" 문자만. 단면·입면은 샤프트 상자를 피트 바닥까지 늘리고, 샤프트 위에 기계실 상자, 샤프트 면 위에 정차층마다 문 사각형을 더한다. `dims` 옵션은 문 폭("문 900", 문이 있는 층 평면)·피트 깊이("피트 D", 피트 입력으로도)·기계실 높이("기계실 H")를 더한다.

### 16.7 한계
- 지붕은 직사각형 외곽·단일 물매뿐이다. 지붕이 벽·슬래브·승강기 기계실과 간섭하는지 검사하지 않는다(기계실을 지붕 위에 놓으려면 샤프트 높이·구멍을 직접 맞춘다).
- 입면에서 벽이 지붕에 가려지는 것은 판정하지 않는다(벽은 처마 높이에서 끝나고 박공벽 삼각형이 없다). 단면 위의 지붕 가림 조각은 16 조각 근사라 경사 가장자리에서 한 조각 폭(전체 높이 차 / 16)만큼 어긋날 수 있다.
- 파라펫은 슬래브 바깥 경계 한 바퀴뿐이고(구멍 둘레는 없다) 파라펫 코핑·배수 개구부는 없다. 승강기 문은 면당 하나(정차층 공통)이고 도어 방향·양면 출입·비상용 구분이 없다.
- 이 기능 전에 낸 승강기 구멍은 연동되지 않는다(16.4).

## 17. 난간 연동·공간 섬 구멍·슬래브 구멍을 통한 가림 (열다섯 번째 작업)
새 요소 종류와 새 뷰 종류는 없다. 모두 기존 요소의 **선택 입력**이다(없으면 키 자체가 없다). 해시 형식 번호는 **14 그대로**다: 이전 형식의 요소 행·IFC 엔티티가 달라지지 않고(섬 구멍이 없는 공간, 출처가 없는 난간은 이전과 같다), 구멍 있는 공간의 몸체는 클로저가 이미 형상을 그대로 펼쳐 담는다.

### 17.1 난간 연동: 출처를 난간 쪽에 적는다 (B3)
14절 승강기 구멍 소유 추적(16.4)의 원칙을 그대로 따른다: 출처를 기록하고, 사용자가 고친 것은 건드리지 않고 알리고, 한 커맨드의 효과라 실행 취소가 함께 되돌린다. 다른 점은 기록 위치다.

| 판단 | 원본 쪽에 기록(승강기 `hole_slabs` 방식) | 난간 쪽에 기록 (택함) |
|---|---|---|
| 승강기와 구멍 | 구멍은 승강기 하나가 만든 같은 모양이라 `슬래브 id + 여유` 만으로 재현된다 | 난간은 계단 하나가 **여러 개**(단 묶음 x 양옆 + 층참)를 만들고, 슬래브는 둘레·구멍 여럿에서 변 구간마다 만든다. 어느 난간이 원본의 어느 자리인지(표식)를 난간마다 적어야 한다 |
| 원본 행 | 계단·슬래브 행에 난간 id 목록이 생겨 원본 편집·병합·IFC 의도가 모두 난간 개수에 묶인다 | 원본 행은 그대로다. 난간 행에만 키가 더해진다 |
| 원본 삭제 | 기록이 원본과 함께 사라져 정리할 것이 없다 | 난간에 원본 id 가 남으니 지울 때 풀어 주어야 한다(아래) |

저장: 난간 `params` 의 선택 키 `src`(원본 계단·슬래브 id, 참조 형태 `id` 라 병합이 id 를 옮긴다), `src_tag`(그 원본의 어느 난간 자리인지), `src_inset`(계단 옆 들임 mm, 계단 표식에만). `src` 와 `src_tag` 는 함께 있어야 한다. 표식 형식:

| 원본 | 표식 | 뜻 |
|---|---|---|
| 계단 | `f{i}L`·`f{i}R` | i 번째 단 묶음의 걸음 방향 왼쪽·오른쪽 옆선 |
| 계단 | `landing` | 꺾인 계단 층참의 트인 가장자리 |
| 슬래브 | `outer:{시작}+{개수}` · `o{k}:{시작}+{개수}` | 바깥 경계(`outer`) 또는 k 번 구멍(`o{k}`)의 변 `시작` 에서 `개수` 개가 이어진 한 줄 |
| 슬래브 | `outer:all` · `o{k}:all` | 모든 변(닫힌 한 줄) |

난간선은 **원본 params 의 순수 함수**다(`_stair_rail_specs`·`_slab_rail_spec`: `railing.from_stair`·`from_slab` 이 같은 함수로 만들고, 연동이 같은 함수로 다시 계산한다). 그래서 "사용자가 고쳤는가"는 난간에 옛 난간선을 따로 저장하지 않고 **옛 원본에서 만든 난간선 = 지금 난간선(허용 0.001mm)** 인지로 가린다.
- 원본을 바꾸는 커맨드(`stair.set`·`stair.move`·`slab.set`·`slab.move`)와 승강기가 소유한 슬래브 구멍을 옮기는 `elevator.move`·`set`(구멍 둘레 난간이 연쇄로 따라간다)가 `옛 원본 / 새 원본` 으로 난간을 갱신한다. 난간 높이·이름은 사용자 것이라 그대로 둔다. 난간 자리가 바뀌지 않은 변경(이름만 바꾸기 등)은 난간을 건드리지 않고 알리지도 않는다.
- 옛 원본의 난간선과 지금이 다르면(`railing.move`·`set` 으로 고쳤다) **건드리지 않고** 응답 `railings.lost`(`{id, reason}`)에 알린다. 새 원본에 그 자리가 없어도(`stair.set clear_turn` 의 층참 난간, 구멍을 지운 슬래브의 구멍 난간) lost 다. lost 난간의 출처는 남는다(원본을 다시 바꿀 때마다 알린다). 끊으려면 `railing.set clear_source`.
- **원본 삭제**(`stair.delete`·`slab.delete`·`element.delete`): 난간은 **남고** 출처만 지워 독립 난간이 된다(응답 `railings_released`). 승강기 구멍이 승강기를 지워도 남는 것(16.4)과 같은 선택이다: 난간은 IFC 로 나가는 독립 요소이고, 자동으로 지우면 사용자가 손댄 난간까지 사라진다.
- 응답 모양: `{"moved": [난간 id], "lost": [{"id", "reason"}]}`. 소유한 난간이 없으면 키가 없다(이전 응답과 같다). 난간 id 는 id 순이다.
- 한 커맨드의 효과라 `history.undo` 가 원본과 난간을 함께 되돌린다(시험: 상태 해시가 처음과 같다).
- 이 기능 전에 낸 난간(출처 없음)은 따라가지 않는다. `railing.from_stair`·`from_slab` 을 다시 부르면 새 난간이 생긴다(기존 난간은 건드리지 않는다).
- IFC: 입력은 의도(DoBIM_Intent)로만 왕복한다(난간 몸체 형상은 그대로). 가져온 뒤에도 연동이 이어진다(시험).

### 17.2 `space.from_walls` 섬 구멍 (B4)
방 안에 떨어져 서 있는 것을 구멍으로 빼 면적에 반영한다. 새 입력은 공간의 선택 파라미터 **`holes`**(슬래브 `openings` 와 같은 모양: 반시계 다각형 목록, 최대 32개, 공간 경계 안쪽·서로 겹치지 않음, `kinds.openings_problem` 을 같이 쓴다)와 `space.from_walls` 의 `islands`(기본 참)다. 공간 `create`·`set`(`holes`·`clear_holes`)·`move`(구멍도 함께)가 같은 입력을 받는다.
- **섬(닫힌 내부 벽 고리)**: `regions.find_faces(walls, islands=True)`. 벽 평면 그래프의 연결 성분마다 바깥 둘레(시계 방향 고리)를 구해 두고, 방(성분 A 의 반시계 면)마다 **다른 성분의 바깥 둘레 중 그 방 안에 있는 것**을 구멍 후보로 낸다. 후보 안에 다른 후보가 또 있으면(섬 안의 방 안의 섬) 안쪽 후보는 안쪽 방의 구멍이다. 구멍 모양은 `edge=inner` 이면 그 바깥 둘레를 벽 두께의 절반만큼 **바깥(방 쪽)으로** 넓힌 선들의 교점(섬 벽의 바깥 면, `inner_polygon(…, outer=True)`), `center` 면 벽 중심선 고리다.
- **기둥**: 레벨의 저작 기둥(호스트 없이 서는 `column` 계열 패밀리 인스턴스)의 바닥 윤곽(가장 넓은 각기둥 단면, 24각형 근사 포함)이 방 안에 완전히 서 있으면 구멍이다. 벽에 닿거나 걸친 기둥은 구멍으로 빼지 않는다(경고 후 건너뜀).
- 결정성: 구멍 순서는 섬(연결 성분 번호 순) -> 기둥(id 순)이고 각 다각형은 가장 왼쪽-아래 꼭짓점에서 시작한다. 벽 순서를 섞어도 같은 결과다(시험).
- 섬 안쪽 방은 따로 공간이 된다(`all`·`points`): 점이 섬 안쪽이면 가장 작은 영역(섬 안쪽 방)이 고른다.
- 면적: `element.get` 파생값 `area_m2` 가 구멍을 뺀 값이 되고 `hole_area_m2`·`holes` 가 더해진다(구멍 없는 공간의 응답은 그대로). 평면의 면적 문자도 구멍을 뺀다. 문자 위치(무게중심)가 구멍 안이면 구멍 밖의 가장 가까운 격자점(16x16)으로 옮긴다(결정적).
- IFC: 구멍 있는 공간의 몸체는 `IfcArbitraryProfileDefWithVoids`(바깥 둘레 + 구멍 폴리라인들)를 압출한 것이다. 의도(DoBIM_Intent)에도 `holes` 가 실려 왕복하고 해시 3종이 같다(시험). 구멍이 없는 공간은 이전과 같다.
- **곡선 벽은 범위 밖이다.** 엔진에 호·곡선 벽 종류가 없다(벽은 직선 축선뿐이다: `wall.create` 는 `axis` 네 수). 곡선 벽 종류가 생기면 다각형 근사 변으로 같은 그래프에 넣는다(결정성은 근사 분할 수를 고정해 지킨다). 이번에는 섬 구멍만 했다.
- 한계: 섬이 가지(다리 벽)로 바깥 벽과 이어지면 같은 성분이라 구멍이 아니다(방이 갈라진다). 바깥 둘레가 자기 접촉(아령 모양 두 고리가 한 벽으로 이어짐)이면 구멍으로 못 빼고 경고한다. 방 경계에 닿거나 겹치는 구멍은 건너뛰고 경고한다. 공간 높이 방향의 구멍(천장 개구부)은 없다.

### 17.3 슬래브 구멍을 통한 단면·입면 가림 (B5, 품질 수정)
12.3 의 한계(가림 판정용 조각이 슬래브 구멍을 뚫지 않는다)를 푼다. 슬래브 가림 조각은 경계 삼각분할이었다. 단면 절단면이 구멍 안을 지나거나 구멍 너머에 뒤쪽 요소가 있으면 구멍을 지나 보여야 할 선이 슬래브 두께 높이에서 가려졌다.
- 구멍이 없는 슬래브: 삼각분할(귀 자르기) 그대로다 -> 도면 바이트가 같다.
- 구멍이 있는 슬래브(`slab_tris`): 꼭짓점 x 좌표마다 세로로 자른 **사다리꼴(볼록 사각형·삼각형)** 로 나눈다(`_trapezoids`). 띠마다 경계·구멍의 변을 y 로 정렬해 짝수-홀수로 속이 찬 구간만 조각으로 낸다. 결정적이다. 이웃 띠는 오른쪽으로 1e-3 mm 겹친다(이음매에 놓인 세로선이 두 조각 사이로 빠지지 않게. 맨 오른쪽 띠는 경계를 넘지 않는다).
- 효과: 구멍을 지나는 시선 위의 선(예: 절단선이 구멍 안인 단면에서 구멍 속에 선 벽·계단의 모서리)이 슬래브 두께 높이(밑면~윗면)에서도 보인다. 구멍 둘레(구멍의 먼 벽)가 가리는 것은 그대로다. 시험: 같은 모델에서 구멍을 지우면 그 높이(2800~3000)가 다시 가려진다.
- 한계: 입면에서 구멍은 슬래브의 바깥 경계가 시선의 맨 앞이라 보이는 것이 거의 달라지지 않는다(구멍은 경계 안쪽에서만 허용된다). 구멍의 내벽 선(구멍 둘레의 수직 모서리)은 그리지 않는다.

### 17.4 바이트 영향
- 새 입력이 없는 프로젝트(구멍 없는 슬래브·섬 없는 공간·출처 없는 난간)의 요소 행·`state`·`derived`·`ifc` 해시와 도면 산출은 이전과 같다.
- 의도된 변경 1: `railing.from_stair`·`from_slab` 이 만든 난간 행에 `src`·`src_tag`(·`src_inset`)가 기록된다. 이 커맨드를 쓴 프로젝트는 난간 행·`state`·`ifc`(난간의 DoBIM_Intent) 해시가 바뀐다. 도면 산출은 같다.
- 의도된 변경 2(품질 수정): 구멍 있는 슬래브가 있는 프로젝트의 단면·입면 도면(가림 판정)이 바뀔 수 있다(구멍 너머가 보이는 경우에만). 해시는 불변이다(뷰 데이터는 파생물).
- 의도된 변경 3: `space.from_walls` 가 섬을 구멍으로 뺀다(`islands` 기본 참). 방 안에 섬이 있는 모델에서만 결과가 다르다(`islands=false` 로 이전 동작).

## 18. 도면 흠 두 건과 이미지 렌더 (열여섯 번째 작업)
새 요소 종류·뷰 종류는 없다. 해시 형식 번호는 **14 그대로**다(상태·IFC 의미가 바뀌지 않았다: 도면은 파생물이고 PNG 인자는 시트 정의에 저장하지 않는다).

### 18.1 지붕 평면의 공간 문자 (품질 수정)
원인: `plan_space_labels` 가 뷰 레벨에 놓인 모든 공간의 실명·면적을 절단 높이와 무관하게 그렸다. A-020 별채 지붕 평면(1F, 절단 6000)에 아래 방(별채 홀·설비실)의 문자가 올라와 물매·용마루 문자와 겹쳤다.
판단: 관행상 지붕 평면은 지붕 위에서 내려다본 그림이라 방을 자르지 않으므로 방 이름·면적을 쓰지 않는다. 그래서 문자 위치를 피해 옮기지 않고 **그리지 않는다**. 규칙: 절단 높이(레벨 + `cut_height`)가 공간 윗면(레벨 + 공간 `height`)보다 높으면 그 공간 문자를 만들지 않는다(같으면 그린다. 공간이 더 높은 강당이면 6000 절단에서도 그린다). 별도 "지붕 평면" 뷰 종류는 만들지 않았다: 엔진은 이미 지붕 평면을 절단 높이로 가른다(`roof_plan_parts`). 1200 같은 보통 절단의 평면은 바뀌지 않는다.

### 18.2 입면의 지붕 아래 벽 선 (품질 수정)
원인: 벽 선의 가림 후보(`vwall_lines`)에 지붕이 없었다(벽·기둥·슬래브·계단만). 처마 높이 = 벽 윗면(3000)이면 벽 윗선(z=3000)과 세로선이 지붕 판 앞면(처마 끝 아랫면 2619 위)에서도 그려져 지붕 띠 안으로 비쳤다. 같은 높이의 중복선이 아니라 **가림 누락**이다(높이가 같으면 눈에 띌 뿐).
수정: 지붕 판의 실제 부피 `roof_solid_slices`(윗면 ~ 두께 아래, 높이 두께/4 조각, 최대 64)를 가림 후보로 더했다(`_roof_solid_vpieces`). 조각 다각형은 면마다 {z0 <= 윗면 높이 <= z0 + 두께 + 1mm} 이다(가림 판정은 다각형의 관찰자 쪽 변만 쓰고, 이음매 높이의 선이 새지 않게 z 를 2·EPS 겹친다). 기존 쐐기(`roof_slices`: 판 밑 빈 곳까지 메운 근사)는 박공 쪽 입면에서 처마 밑 벽 모서리를 가려 쓰지 않았다(승강기 선은 그대로 쓴다). 적용: 벽 선·벽 숨은 선·기둥·슬래브·계단·난간 선. 옆에서 본 가림은 조각 높이만큼 덜 가리는 쪽으로 어긋난다. 평면은 불변. 시험: test_roof_sloped(남측에서 벽 윗선이 없고 세로선이 2619 에서 끝남, 박공 쪽은 처마 밑 모서리 유지).

|---|---|---|

| resvg(architecture.md 표) | Apache-2.0, 네이티브 바이너리 서브프로세스 | 플랫폼별 바이너리가 늘고 버전에 따라 화소가 달라질 수 있다 |

택한 근거: 결정성(부동소수·zlib 만, 프로세스·캐시 상태와 무관하게 같은 바이트: 시험), 의존·GUI 없음, 속도 충분(실측: A1 시트 2400px 0.95~1.7초, 글꼴 부분집합을 처음 만들 때 +1초). 방식: 모든 요소를 다각형 채움 하나로 모은다(선 = 굵기 사각형, 원 = 다각형·고리, 문자 = Noto Sans KR 윤곽, 점선은 조각). 세로 4칸 부표본 x 가로 정확 면적 안티앨리어싱, 감김수 규칙. 0.75화소보다 가는 선은 그 굵기로 그린다. 글꼴이 없으면 글자 칸만 속이 빈 사각형으로 그리고 경고한다.

### 18.4 커맨드·MCP 설계
- `view.image`·`sheet.image`: risk **read**, 파일을 쓰지 않는다. 결과의 비공개 키 `_png` 에 이미지를 싣고 `dispatch.run` 이 봉투 밖으로 뺀다. 봉투에는 크기·바이트·sha256·화소/mm·영역만 남는다(CLI·`dobim_query` 는 요약, `dobim_render` 는 같은 PNG 를 ImageContent 로). 이미지를 봉투에 넣지 않는 이유는 응답 상한(6,000B) 때문이다.
- `sheet.image` 인자: `id`(저장된 시트 정의) 또는 `views` + `sheet.export` 와 같은 인자 중 하나. 저장 시트와 같은 인자의 이미지는 바이트가 같다.
- 파일로 받기: 기존 `view.export`·`sheet.export`·`sheet.render`·`sheet.index` 가 `.png` 경로를 받는다(destructive·확인 토큰·덮어쓰기 스냅숏 규칙 그대로, 응답에 `pixels`). 이름을 새로 만들지 않았다.
- 공통 인자: `max_px`(64~4096, 기본 1600, 긴 변 상한), `crop`(용지 비율 [x0,y0,x1,y1], 잘라 내면 그 영역에 max_px 를 써 확대). 출력 1600만 화소 상한. `max_px`·`crop` 은 시트 정의(sheet.define)에 저장하지 않는다(`NOT_STORED`).
- MCP `dobim_render(target=view|sheet, id, sheet, max_px, crop, project)`: 읽기 전용 도구. 성공하면 ImageContent(image/png) + 같은 봉투 텍스트·structuredContent, 실패하면 이미지 없이 is_error.
- 한계: 커닝·굵은 글꼴 없음(굵게는 이중 그리기), 색은 요소가 가진 값 그대로, 투명 PNG 없음, 큰 max_px 는 시간이 늘어난다(그림 요소 수에 비례하고 화소 수에는 거의 무관).
