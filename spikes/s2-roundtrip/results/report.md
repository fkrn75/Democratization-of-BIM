# S2 보고서: 외래 IFC 왕복과 의도 복원 (spike/s2-roundtrip)

질문(docs/roadmap.md S2): 외래 IFC를 무손실로 통과시키고 의도를 복원할 수 있는가?
합격 기준: Building-Architecture.ifc와 Revit 내보내기 표본 1건 이상에서 수정하지 않은 요소의 의미 동일(ifcdiff 차이 0), 변조 요소가 "분리됨"으로 표시. 실패하면 외래 요소를 가져오기 전용으로 제한.

**결론: 합격.** 실패 조건(가져오기 전용으로 제한)은 발동하지 않았다. 독립 검수(조건부)에서 나온 결함 11건(필수 3, 권장 8)을 고쳤고 각각 회귀 시험을 더했다(2026-11-09). 지휘자가 검수 재현 스크립트를 수정본에 다시 돌려 필수 3건이 해결된 것을 확인했다. 아래 "한계·미확인"을 함께 읽을 것.

## 1. 무엇을 만들었나

- `ifc.import`: 외래 IFC4를 새 프로젝트로 가져온다. 원본은 SQLite에 압축 보존(외래 기반)하고 요소를 `authored`(의도가 정본) / `foreign`(IFC가 정본) / `detached`(외부가 형상을 바꿔 동결)로 분류한다.
- 분류는 요소 클로저 해시로 한다. 파일 안 `DoBIM_Intent`를 다시 투영한 결과와 들어온 요소를 비교해서, 같으면 authored, 다르면 detached, 의도가 없거나 못 읽으면 foreign이다.
- `ELEMENT_FROZEN`: foreign·detached 요소의 형상·삭제·재료는 거절하고 속성(`pset.set/delete`)만 편집한다.
- 내보내기는 외래 기반 사본 위에서 저작 요소만 투영한다. 규칙 본문은 `docs/architecture.md` 4.1, 근거는 `docs/adr/0005`.
- 새 오류 코드: `UNSUPPORTED_SCHEMA`, `IMPORT_INVALID`, `ELEMENT_FROZEN`.

- Revit 표본은 원본 자체에 IfcOpenShell 유효성 오류가 있다(IFC4RV 26건, IFC4DTV 13건). 통과 후 오류 수는 같다(증가 0). 그래서 S0 도구의 M8("오류 0건")은 Revit 표본에서 실패로 표시되지만, 원인은 원본이다.
- 공식 ifcdiff는 PyPI ifcdiff 0.9.0(ifcopenshell 0.9.0.post1과 같은 버전)을 별도 venv에 설치해 별도 프로세스로 호출했다. 소스는 복사하지 않았다(LGPL-3.0).
- 엄격 비교(이 저장소의 정규화 덤프)는 검수 후 **스타일·타입 객체·수량 세트**까지 보도록 넓혔다. 코어가 직접 만든 모델의 IFC 해시는 바뀌지 않는다(해당 항목이 없으면 아무것도 더하지 않는다). 넓힌 뒤에도 T1~T5가 모두 통과한다.

수정 중 더 찾아 고친 것: 지운 채 다시 연 프로젝트에서 취소할 때의 `INTERNAL` 오류, 다시 열면 지운 요소만 쓰던 재료가 고아로 남아 해시가 어긋나던 문제, 지우기가 층 구성 재료의 하위 객체를 고아로 남기던 문제.

## 4. 전체 시험

`pytest -q -rs --durations=5`(spikes/s1-core, 느린 시험 포함, ifcdiff와 Revit 표본 환경변수 설정): **266개 중 266 통과**, 실패 0, 오류 0, 건너뜀 0, 2758초. S1 기존 228개 + S2 38개(`test_s2_authored`, `test_s2_samples`, `test_s2_review`). 결과 파일 `results/s2_pytest.json`은 스크립트가 만들었다.

## 5. 한계·미확인

- ifcdiff는 속성셋 STEP 번호만 달라도 `properties_changed`로 센다(지웠다 되돌려 속성셋이 새로 만들어진 경우). `ifcdiff_id_only_changed`로 따로 세고, 내용 차이는 엄격 비교가 잡는다(0).
- 되살리지 못하는 것: 문을 지울 때 개구부에 붙은 속성, 외래 개구부의 형상, 몸체 솔리드에 걸린 레이어 지정(지우기→취소에서).
- 단일 `IfcMaterial`의 부가 속성(분류, 설명)은 이름으로만 복원한다.
- Revit 표본은 1개 모델(RA-01)의 두 내보내기다. 다른 저작 도구(ArchiCAD, Bonsai 등)·대형 모델·메모리 한계는 미시험. IFC2x3·IFC4X3은 범위 밖(2x3은 거절 동작만 확인).
- 분리됨→저작 복귀 경로, 기존 프로젝트에 외부 수정본 합치기, 외래·분리 요소 삭제는 없다. 단위 외의 프로젝트 수준 변경(좌표계 변환 등)은 감지하지 않는다.
- 분류는 보수적이다. 같은 모양을 다른 엔티티 구성으로 쓴 도구는 detached가 될 수 있다. 부동소수는 소수 6자리 반올림 비교다.
- Windows 11, Python 3.12, ifcopenshell 0.9.0.post1에서 잰 값이다.

```
DOBIM_IFCDIFF_PYTHON=<scratch>/python, DOBIM_REVIT_DIR=<선택>
python spikes/s2-roundtrip/run_s2.py ; cd spikes/s1-core && python -m pytest
```
