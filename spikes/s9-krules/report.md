# S9 보고서: 한국 납품 규칙을 기계 검사로 옮길 수 있는가

작성 2026-11-09. 합격 기준: 국토부·조달청·세움터 현행 원문 확보, 규칙 20개 이상을 IDS + 코드로 구현, RA-01과 표본에서 동작.

## 1. 결론

**부분 합격.** 국토부·조달청은 확보와 출처 확인이 끝났다. 세움터 가이드는 공식 파일을 확보하지 못해 미충족이다. 후보 52개를 뽑아 37개를 검사(IDS 18 + 코드 19)로 구현했고 37개 모두 CLI로 실행된다(파일 검사 36개 + 폴더 검사 1개는 `--package`). 시험 145개가 통과한다(검증·검수 반영 뒤. 반영 전 48개. 8절 프로파일 도입 뒤 201개). 원문이 IFC 속성 이름을 거의 지정하지 않아 구현 요구사항 37개 중 24개는 우리 해석에 의존한다. 독립 검수(조건부 통과, 필수 결함 0) 뒤 에너지 검토 조건부 규칙 3개를 일반 위반 집계에서 분리했고, 망가진 입력이 트레이스백 대신 오류 JSON이 되게 했다.

## 5. 사람이 확인해야 할 것

1. **IFC 속성 사상은 우리 해석이다**(구현 37개 중 24개). 원문은 "실명·실ID·사업정보를 입력"이라고만 하고 IFC 속성을 정하지 않는다. 가정: 실명=IfcSpace.LongName, 실ID=이름이 `실ID`인 속성(우선)·IfcSpace.Name(보조), 건축규모=Pset_BuildingCommon/Qto_* 또는 한국어 사용자 속성. 발주처 BIM 담당자 확인이 필요하다(7절 참고).
2. **세움터 가이드 3종은 사람이 세움터 공개자료실에서 받아야 한다.** 받으면 같은 절차로 후보를 추가한다. 비공식 사본으로 만든 세움터 초안 프로파일은 8절 참고.
3. **문서 간 충돌 3건**(도구는 두 기준을 따로 검사): 단위(조달청 mm 원칙 vs 국토부 m 또는 mm), 열관류율 대상(조달청 6종 vs 국토부 5종), 좌표계(기본지침 UTM52 계열 vs 시행지침 GRS80 TM).
4. **공공누리**: 시행지침은 제4유형(상업 이용 금지, 변경 금지)이다. 저장소에는 원문 없이 요약만 넣었다. 이 요약을 공개 저장소에 두어도 되는지, 상업 제품 근거로 써도 되는지는 법무 확인이 필요하다.
5. **최신 개정 확인**: 국토부 정책정보에는 위 두 건만 나왔고 조달청 v2.2는 찾지 못했다(없다고 단정하지 않음). 유지관리자 편(안)은 2025-01 의견 조회만 확인했다.
6. **구현 범위의 한계**: 실시설계(5장)만 구현했다. 공간 겹침은 경계상자 근사라 비직사각형 방은 오탐할 수 있다. 공간분류코드와 공사코드는 형식만 검사한다. 납품 폴더 구성은 PDF 표가 평탄화돼 해석했으므로 원본 표를 눈으로 봐야 한다.
7. **ifctester 제약**: IDS를 읽을 때 specification identifier를 버려 실행기가 XML에서 따로 읽는다. propertySet 정규식은 일치하는 모든 Pset에 속성이 있어야 통과시켜, 공사코드 존재 검사는 코드로 뒀다. 속성 dataType 지정은 뺐다(IfcLogical·IfcReal 값도 통과). 사용자 정의 Pset에 값을 넣은 모델은 실행기가 08~10을 재판정해 통과로 바꾸지만(`tolerated`), `.ids` 파일을 다른 IDS 도구로 단독 실행하면 여전히 위반으로 나온다.
8. **에너지 검토 여부는 IFC에서 알 수 없다.** 사람이 `--energy`로 알려 줘야 한다.
9. **성능 한도**: 공간 겹침은 같은 층끼리만 비교하고 공간 3,000개를 넘으면 판정을 생략한다. 형상 중복(KR-CODE-17)은 형상 객체 20,000개를 넘으면 생략한다. 100MB급 파일 성능은 미측정이다.
10. **KR-CODE-18(납품 폴더 구성)은 합성 폴더로만 시험했다.** 실제 납품 폴더로는 확인하지 못했다.

## 7. 검증 반영 (2026-11-10)

해석 의존 요구사항 24개를 원문(조달청 부속서-1·부속서-8 사용자 가이드, 국토부 시행지침)과 IFC 공식 Pset 정의로 다시 검증했다(판정: 타당 6, 대안 있음 14, 틀림 3, 판단 불가 1). 핵심 발견은 조달청 부속서-8 가이드(Revit·ArchiCAD)가 실ID·부재명·사업정보·부위분류를 IFC 표준 슬롯이 아니라 **소프트웨어 사용자 정의 속성**으로 넣게 한다는 점이다. 표준 슬롯 하나만 정답으로 보면 가이드대로 만든 모델이 위반으로 나오므로, 아래 규칙은 "표준 슬롯 또는 한국어 사용자 속성 중 하나"를 인정(OR)하도록 고쳤다. 결과 JSON 의 `found_via` 에 어느 위치에서 값을 찾았는지 개수로 적어 발주처가 확인할 수 있게 했다.

| 요구사항 | 검사 | 바꾼 내용과 이유 |

해석 의존 개수 변화: 해석 의존 구현 요구사항은 여전히 24개다(어느 IFC 위치인지 원문이 정하지 않았다는 사실은 그대로). 달라진 것은 불확실한 위치 하나를 정답으로 못박던 요구사항 18개(REQ-007·012·015·016·017·018·022·023·024·025·028·034~037·040·041·051)가 여러 위치를 인정하고 `found_via` 로 근거를 남기게 되어, "틀림" 3건(REQ-015·022·025)이 해소되고 가이드대로 만든 모델의 오탐 경로가 닫혔다는 점이다. 시험은 48개에서 145개로 늘었다(검수 반영 포함)(수정마다 표준 슬롯만 / 한국어 사용자 속성만 / 둘 다 없음 세 경우).

결과 파일: `results/` 는 RA-01 3종·양성 대조군을 재생성했다(RA-01 은 KR-IDS-15 가 위반에서 통과로 바뀜: 층 개체가 있어 층수가 계산됨. 양성 대조군은 전부 통과 유지). **Building-Architecture 결과 2개는 공개 외래 표본이 이 환경에 없어 재생성하지 못했다**(반영 전 값 그대로, 갱신하려면 `python make_results.py --building-architecture <경로>`). 양성 대조군 합성기에는 부재명을 위해 Pset_*Common.Reference 를 추가했다.

남은 한계:
- 실제 Revit·ArchiCAD 내보내기 파일로는 시험하지 못했다. 시험은 합성 모델이며 내보내기 동작(IfcSpace.Name=방 번호, 유형 주석 위치 등)은 IFC 공식 문구와 일반 지식에 근거한 가정이다. 내보내기 시험 파일 2개면 REQ-015·022·025·034~037 을 확정할 수 있다.

- 결과표 "대안 있음"과 어긋나는 점: 없음. 다만 REQ-024 는 이미 이름이 `조달청표준공사코드`일 때만 구문을 검사하고 있어 결과표가 지적한 오탐 경로는 코드에 없었다(ArchiCAD Pset 은 존재만 보도록 KR-CODE-19 쪽만 넓힘).

### 검수 반영 (2026-11-10, 독립 검수 조건부 통과 후)

- 자리표시 값: `ok()` 가 빈 문자열, 제로폭·특수 공백만 있는 값, `0`, `-`, `없음`, `해당없음`, `N/A`, `UNKNOWN` 등과 숫자 0 을 값으로 인정하지 않는다. 면적·층수는 0 보다 큰 수(문자열은 안의 첫 숫자, 예 `지하4층, 지상10층`=4, `5,990.42㎡`)여야 하고 음수·숫자 없는 문장은 거부한다. `건설정보분류체계-부위분류` 는 원문·결과표에 형식 규정이 없어 자리표시 거부 + 영숫자 포함만 본다. 분류 참조는 코드(Identification/ItemReference)가 비어 있으면 분류로 보지 않는다(Name 만으로는 불인정).
- 인정 범위: 사용자 속성은 그 객체 자신과 프로젝트까지만 본다(다른 건물·대지 값 차용 금지). 층 개체 수 층수는 그 건물에 집합으로 속한 층만 센다.
- 공간 두 세트: 같은 (실ID, 실명) 공간이 둘 이상이어도 상자가 거의 같으면(0.02 m 이내로 서로 포함) 두 세트가 아니라 중복으로 보아 위반, 포함 관계가 아니면 세트로 보지 않는다. 3개 이상은 큰 순서로 엄격히 포함되는 사슬일 때만 세트 3개 이상으로 나눈다.
- 공사코드: ArchiCAD Pset 은 값이 있는 속성이 하나라도 있어야 인정. IFC2X3 `ePSet_*` 는 `id` 밖에 속성이 없는 빈 속성세트를 선언으로 보지 않는다.
- 결과 표기: OR 판정 결과도 `na` 일 때 "적용 대상 객체 없음" 노트를 남긴다. KR-IDS-04 는 `found_via` 를 "Name 값(보조, 실번호일 수 있음)" 으로, 노트를 "Name 이 있다고 실ID 가 있다는 뜻이 아님" 으로 정리했다.
- `run_file(ids_path=...)` 에 기본이 아닌 IDS 를 주면 OR 판정으로 대체하지 않고 그 IDS 결과를 그대로 쓴다(택1: 대체 안 함). IDS 엔진이 죽어 error 가 된 규칙은 OR 판정이 덮어쓰지 않고 error 로 전파한다.
- CRS 정규식에 앞 단어 경계를 넣어 `EPSG:25178` 이 5178 로 오인되지 않는다.
- 시험(`tests/test_review_fixes.py`, 51개)에서 항목별 반례, 포함 관계가 아닌 쌍, 200MB 대 200MiB 경계(200,000,000 통과 / 200,000,001·209,715,200 경고)를 추가했다. 코드를 임시로 되돌려 새 시험이 실패하는지 확인했다: `_contains` 무력화, 동일 상자 중복 판정 제거, 자리표시 거부 제거, 수치 검사(`ok_number`) 제거, 속성 범위 확대, CRS 경계 제거, IDS 오류 전파 제거 모두 실패로 잡혔다(되돌린 뒤 복원, 145개 통과).

## 8. 납품처별 프로파일(2026-11-10)

조달청 규칙과 세움터 가이드는 목적이 다르다(납품 검사 대 건축인허가 민원 제출). 파일명, 폴더, 사업정보, 식별 속성, 상세수준, 압축 규칙이 갈려서 한 규칙 집합으로 두 곳을 모두 맞추면 어느 쪽 모델이든 오탐이 난다. 그래서 규칙을 `공통 코어 + 조달청 프로파일 + 세움터 프로파일(초안, 기본 꺼짐)`으로 나눴다.

### 8.1 구조

- 실행: `python -m krrules.run <ifc> --profile procurement|seumteo`, `run_file(..., profile=...)`, `run_package(..., profile=...)`. 기본은 `procurement`이다. 모르는 이름은 오류 JSON(`UNKNOWN_PROFILE`, 종료 코드 2)이다.
- **기본 결과는 불변이다.** 기본(조달청) 프로파일은 기존 37개 검사를 그대로 돌리고 결과에 프로파일 표식 키를 더하지 않는다. 확인: `make_results.py`로 `results/`를 다시 만들어 기존 결과 파일이 한 바이트도 달라지지 않았고(저장소 diff 0), 시험(`test_default_profile_results_match_committed_snapshots`)이 RA-01 3종과 양성 대조군을 저장된 결과와 문자열 단위로 비교한다. 기존 145개 시험은 수정 없이 통과한다.
- 규칙 id 체계는 그대로다. 각 규칙의 소속은 `catalog.CHECK_SCOPE`(common·procurement)와 `catalog.SEUMTEO_CHECKS`(seumteo)에 있고 `requirements.json`의 `checks[].profile_scope`, `seumteo_checks`로도 내보낸다. 세움터 결과는 항목마다 `scope`를 달고, 조달청 전용 규칙은 `status: na`, `excluded_by_profile: true`로 남기며 대신 판정하는 규칙이 있으면 `replaced_by`를 적는다.
- 새 파일: `krrules/profiles.py`(프로파일 표·해당 없음 사유), `krrules/seumteo.py`(세움터 전용 검사 15개와 변형), 시험 `tests/test_profiles.py`(56개), 합성 모델 `tests/fixtures.py::build_seumteo`. `KR-CODE-10`만 공통 소속이면서 세움터에서는 대상(실 공간)을 달리 잡아 돌린다(`check_space_overlap`에 `spaces` 인자 추가, 기본 동작 동일).
- 세움터 결과(`results/RA-01.seumteo.json`, `results/seumteo-fixture.json`)의 맨 위에 `profile_id`와 초안 경고를 둔다: "초안: 세움터 BIM 설계기준서 v1.0(안) 2021-12, 공식 배포본 미확보, 실제 세움터식 내보내기 미시험".

### 8.2 세움터 프로파일 근거와 한계

근거는 세움터 BIM 설계기준서·업무지침서·검토기준서 v1.0(안, 2021-12)의 비공식 사본 3종과 S9 규칙의 대조표다. 아래 한계가 모두 적용된다.

1. **공식 원본이 아니다.** 사본이고 문서 표지·각 쪽에 "(안)"이 붙어 있으며, 안내문이 의견수렴용 자료이고 정부의 공식 입장이 아니라고 밝힌다. 세움터 현행 요건과 같은지는 원본(로그인 후 BIM가이드)으로 확인해야 한다.
2. **IFC 위치가 문서에 없다.** 설계기준서는 IFC 엔티티·속성세트 이름을 한 번도 지정하지 않고 Revit 용어와 내보내기 설정만 적는다. 그래서 `AIS_*` 속성은 **이름이 `AIS_*`이면 어떤 Pset에 있든 찾는다**고 가정했다(Pset 불문). 면적 객체(용도·방화구획, 건축·대지면적)는 IfcSpace로 나올 수 있다고 추정하고, `AIS_분류코드` 값(A+5자리·B·F·S)에 더해 면적 객체 전용 속성(`AIS_연면적제외` 등, `방화구획여부`)이 이름으로 붙어 있거나(값 무관), 실 정체(실명·분류 참조·공간분류코드)가 없고 면적 값이 있을 때만 면적 객체로 보고 실명·분류코드·중첩 검사에서 뺀다. 코드만 있거나 마커 속성만 있으면 실 공간으로 남겨 검사한다(코드 오입력·무관한 플래그가 검사를 빠져나가지 않게). 제외한 개수와 예시는 해당 규칙 결과의 `excluded_area_objects`에 노출한다. 같은 이름 `AIS_분류코드`가 층(`L지상` 등)·면적·룸에 모두 쓰여 값의 형태로 대상을 가른다. 이 추정은 실제 파일로 확인하지 못했고, 추정에 기댄 판정(실명, 범용객체 분류, 같은 종류 면적 객체 중첩, 면적 객체 존재)은 위반(fail)이 아니라 경고(warn)·정보(info)로 낮췄다.
3. **사본 내부 불일치가 있다.** 예: 오피스텔·공동주택은 업무지침서에서 대상 제외인데 설계기준서 용도 목록에는 있음, 룸 AIS_ 불린 4종이 룸 속성인지 계단·운송설비 속성인지, AIS_공구상면적 타입(실수 대 문자), 부속서 번호. 해소하지 못했다.
4. **세움터식 내보내기 파일로 시험하지 못했다.** 시험은 합성 모델이다. 세움터 규칙으로 통과한다는 말은 "사본이 적은 대로 만든 합성 모델이 통과한다"는 뜻이다.
5. 세움터 프로파일은 `--energy`를 무시한다(결과에 `energy_mode: false`와 `energy_note`로 표기, 조건부 3개 규칙은 판정하지 않음).
6. 알려진 사소한 한계: 면적 객체 판정은 추정 단서 기반이라 실명 없는 실에 코드와 면적 값이 함께 있으면 면적 객체로 제외될 수 있다(제외 예시로 확인). 파일명 마지막 칸은 밑줄·점 없는 한 칸만 인정한다. KR-SEU-12는 사업명·주소·층수만 본다. 폴더·파일명 규칙은 (안)이다.
7. 문서에 근거가 없는 조달청 규칙(실ID·실ID 형식·부재명·공사코드 구문, 좌표계 투영)과 조건부 에너지 규칙은 세움터에서 해당 없음으로 뒀다.
