# S3 증분 벡터 도면 결과

질문: 요소별 캐시와 의존 그래프로 증분 벡터 도면이 가능한가? (docs/roadmap.md S3)

합격 기준: RA-01 평면·단면·입면 생성. 벽 1개 이동 시 영향 뷰 갱신 2초 이내이고 전체 재생성 결과와 선분 일치 99% 이상. 실무 검토자가 "납품 초안으로 쓸 수 있다"고 판정.

**결론:** 기술 기준(갱신 2초, 선분 일치 99%)은 통과했다. 실무 검토자 판정은 **미확인(사람 판정 필요)**이다. 코어가 가진 벽·문·레벨·조인만 그리므로 창·슬래브·기둥이 없어 "납품 초안" 수준은 아니다. 후퇴안(뷰 단위 재생성)은 쓰지 않았다.

## 1. 방식 (접근 조사)

| 후보 | 판단 |
|---|---|
| `ifcopenshell.draw` (LGPL, 0.9.0.post1 포함, OCC HLR) | 코어가 투영한 IFC에서 평면·단면·입면 SVG가 나온다(평면 0.13초, 단면 0.24초, 입면 0.29초). 파일 전체를 다시 그리고 요소별 캐시가 없어 증분이 불가능하다. **독립 대조군**으로만 썼다 |
| 자체 HLR-lite (채택) | 코어 의도 데이터(축선·두께·높이·조인·문)에서 직접 2D 선분을 만든다. 벽이 연직 기둥이라 가림 계산이 정확하고 짧다. 코어의 증분 그래프(graph.py) 위에 얹었다 |
| ifc-lite `drawing-2d` | 시험하지 않음 |

캐시 단위(`drawing.py`): `wall_solid(w)`(뷰와 무관한 벽 형상, 문 개구부로 나눈 띠) → `plan_pieces(V,w)` / `vpieces(V,w)` → `*_bbox`, `*_nbrs`(가릴 수 있는 이웃, 이웃 집합이 같으면 전파가 멈춘다) → `plan_wall_lines(V,w)` / `vwall_lines(V,w)` → `view_lines(V)`(겹침 병합). 아키텍처의 `view.cut_lines(V,E)`·`view.proj_lines(V,E)`에 해당한다.

- 평면: 절단 높이의 벽 단면 사각형을 합집합 윤곽으로(내부 이음매 제거) + 문 평면 기호(문짝 선, 호). 문 구간은 벽이 끊긴다.
- 단면: 절단선이 벽을 자른 사각형(문 개구부는 비움) + 절단면 뒤의 가림 처리된 투영선. 절단면 앞은 잘라낸다.
- 입면: 방위 4종. 벽의 수직·수평 모서리와 문틀을 이웃 벽 조각으로 가림 판정한다.
- 순수성: 시각·난수·파일·sin/cos/hypot 없음(AST 시험), ifcopenshell import 없음(import-linter 계약에 추가).

## 2. 코어 확장

- 의도 요소 `view`(IFC로 투영하지 않음). 뷰를 만들어도 IFC 해시는 안 바뀐다. undo/redo·해시·로그에 그대로 들어간다.
- 커맨드 7개(레지스트리 31 → 38): `view.create`, `view.set`, `view.delete`, `view.list`(캐시 상태 fresh·stale·new), `view.linework`(선분 통계 + 페이지 목록), `view.export`(SVG·PDF 파일, 응답은 경로·크기·요약만. **destructive: 확인 토큰 + 덮어쓰기 전 스냅숏, `ifc.export`와 같은 절차**, 9절), `view.affected`(rev를 주면 그 변경이 건드린 입력 키에서 의존 그래프 역추적, 생략하면 낡은 뷰 = 갱신 대기열).
- 규약 준수: 스키마·examples·위험 등급·응답 상한(`commands.search`가 상한 안에 들도록 요약 문구를 짧게 함)·패리티 C 100%(`results/s3_parity.json`, 레지스트리 38개, 예시 45개, 오류 사례 38개. `view.export`는 destructive 라 위험 등급 도구 불일치 검사 대상이 늘었다).
- 비 IFC 요소 판정은 `ifc.ents`에 있는지가 아니라 **종류**로 한다(신원이 사라진 요소의 KeyError를 숨기지 않기 위해, `test_review4`가 이를 지킨다).
- 산출물: SVG(한글 제목·레벨 기준선 라벨 포함), PDF(벡터, 1쪽). **PDF는 글꼴을 내장하지 않아 한글이 `?`로 나온다**(S0 E5와 같은 한계, 응답에 `non_ascii_dropped`).

## 3. 모델: 코어 범위의 RA-01

포함: 레벨 2, 벽 14(외벽 8 + 내벽 6), 문 5, 조인(모서리 8, T 10). 뷰 7개: 평면 2(1F·2F, 절단 1200), 단면 1(B-B, 내벽 문 개구부를 지남), 입면 4(N·E·S·W).

**뺀 것(코어에 없음):** 창 8, 슬래브 3, 기둥 12, 보 8, 계단 1, 공간 6, 벽 재료 층, 문 종류(타입). 그래서 입면에 창이 없고 단면에 슬래브가 없다.

## 4. 합격 기준별 판정

| 기준 | 결과 | 판정 |
|---|---|---|

| 벽 1개 이동 시 영향 뷰 갱신 2초 이내 | 이동 40회, 이동 + 7뷰 갱신 p50 12.1ms / p95 25.9ms / 최대 27.5ms (이동 커맨드 p50 1.6ms, 뷰 갱신 p50 10.3ms; 9절 재측정값, 다른 작업과 동시에 돌려 첫 측정보다 조금 느림) | **통과** |
| 전체 재생성과 선분 일치 99% 이상 | 이동 40회 × 7뷰 전부 **100%**(개수·길이). 임의 편집열 4개 × 300스텝, 검사 10,536회 불일치 0, 예외 0 | **통과** |

| 실무 검토자 "납품 초안" 판정 | 검토용 SVG·PDF를 만들어 두었다(`run_s3.py export`로 재생성, `out/`은 저장소에 넣지 않음). 창·슬래브·치수·주석·선 굵기 표준이 없어 통과 가능성은 낮다 | **미확인(사람 판정 필요)** |

정의:
- 선분 정규화: 등급(cut·proj·symbol) 유지, 끝점을 0.01mm 격자로 반올림, 끝점 순서 고정, 길이 0 제거, 같은 직선 위의 겹치거나 이어진 선분은 병합. 일치율 = 다중집합 교집합 / 더 큰 쪽 개수(길이 가중도 함께 기록).
- "전체 재생성"은 (a) 캐시 없는 `RefGraph`와 (b) 빈 증분 그래프에서 처음부터, 두 가지를 쟀다.
- **100%는 같은 질의 함수를 증분·비증분으로 돌린 자기일관성이다.** 기하가 옳은지는 ifcopenshell.draw와 따로 대조했다(5절).

## 5. 측정 요약 (`results/*.json`)

- 처음부터 생성(빈 캐시, 중앙값 ms): 평면 1F 1.5 / 2F 1.8, 단면 4.3, 입면 N 3.5 · E 3.3 · S 3.2 · W 5.0, 7뷰 한 그래프 17.2. 선분 수: 평면 59·46, 단면 34, 입면 7·9·18·11.
- 증분: 갱신 p50 10.3ms. 전체 재생성은 (a) p50 160ms(약 11배 빠름, 결과 파일의 배율 10.9), (b) p50 24.4ms(약 2배). 이동 1회에 재계산한 노드 p50 185개(전체 574). 이동이 바꾼 뷰 평균 2.75개. 벽 이동 40회에서 `view.affected(rev)`는 바뀐 뷰를 빠뜨리지 않았다(보수적: 평균 6개 보고 vs 실제 2.75개). **다만 이 측정은 "기존 벽 이동"만 봤다. 새 요소·뷰 삭제를 포함한 임의 편집열에서의 누락·오류는 독립 검수에서 결함으로 나와 9절에서 고쳤다.** 1F 벽 이동은 2F 평면 캐시를 건드리지 않는다.
- 규모(합성 격자, 조인 없음, 이동 뒤 평면·단면·남측입면 갱신):

| 벽 수 | 처음부터(3뷰) | 증분 p50 / p95 | 전체 재생성(a) p50 | 배율 |
|---|---|---|---|---|
| 24 | 20ms | 8ms / 12ms | 88ms | 11x |
| 84 | 103ms | 35ms / 46ms | 829ms | 23x |
| 220 | 476ms | 135ms / 192ms | 4,563ms | 31x |

220벽에서도 2초 안이다. 다만 이웃 판정이 뷰 안 벽 전체를 훑어 벽 수에 대해 대략 제곱으로 늘어난다. 아키텍처의 5,000요소 T1 300ms 목표는 이 구현으로 못 맞춘다(공간 격자 색인과 깊이 컬링 필요).

- ifcopenshell.draw 대조(1F 평면 절단선, 허용 2mm): 우리 선의 98.9%가 그 선 근처에 있고, 그 선의 91.3%가 우리 선 근처에 있다(그쪽은 벽별 윤곽·문 본체·코어 IFC의 L 모서리 노치 포함). 단면·입면은 뷰 방향 규칙이 달라 선분 대조를 못 했다.
- 임의 편집열: S1 생성기(이동·두께·문·조인·삭제·undo/redo) + 뷰 설정 편집을 섞어, 매 스텝 모든 뷰를 증분과 전체로 비교.
- 변이 11종: 벽 형상·개구부·입면/평면 이웃·평면 조각·코너 범위·뷰 설정의 의존성 미기록, 그래프의 관계/요소/버킷 변경 미표시, 이웃 변화 조기 차단 오류. 첫 편집열에서 1~25스텝 안에 잡혔다.

## 7. 한계와 미확인

1. 코어 범위만: 창·슬래브·기둥·보·계단·공간·재료 층이 없다. 직선 연직 벽과 문만.
2. L 조인 모서리는 표시용으로 채워 그린다(코어 `wall_trim`은 축선 교점에서 자르고 IFC 투영에는 모서리 노치가 남는다). 그 부분에서 도면과 IFC 형상이 다르다. 코어 조인 형상 개선 필요.
3. 문 평면 기호는 호스트 벽의 +v 쪽으로 열리고 경첩은 개구부 시작 쪽으로 고정(코어 문에 개폐 방향 속성이 없다). 치수·태그·방 이름·해치·그리드·북쪽 표시·시트 도곽 없음. 선 굵기는 임의(절단 0.5 / 투영 0.18 / 기호 0.25mm). 한국 도면 표준은 S9 영역.
4. 가림 계산은 연직 기둥(경사 없음)에 정확. 이웃 판정은 제곱 증가. 평면의 다른 층 투영·상부 점선 없음.
5. PDF 한글 없음(`?`). 한글 PDF는 글꼴 내장 또는 글자 윤곽선 변환이 필요하다. SVG 한글은 보는 쪽 글꼴에 의존한다.
6. 측정은 개발용 노트북에서 다른 작업과 동시에 돌렸다(시간은 상한 쪽 값으로 읽을 것). 단일 프로세스, Python 3.12.
7. 실무 검토자 판정은 미확인(사람 판정 필요). 기준을 낮추거나 시험을 약화해 통과시키지 않았다.

## 9. 독립 검수 반영 (조건부 판정 → 결함 5건 수정)

독립 검수가 `view.affected`·`view.create`·`view.export` 등에서 결함을 찾았다. 아래는 원인, 수정, 회귀 시험이다. 기준 수치(갱신 2초, 일치 99%)는 이 수정과 무관하다(수정 뒤 재측정: 이동 40회 모두 7뷰에서 선분이 정확히 같음, 최대 27.5ms).

| # | 결함 | 원인 → 수정 | 회귀 시험 |
|---|---|---|---|
| 1 | 뷰를 지우거나 뷰 생성을 취소한 뒤 `view.affected(rev)`가 `INTERNAL`(KeyError)로 계속 죽음 | 역의존 추적이 지워진 뷰의 낡은 `(view_lines, v)` 노드까지 결과에 넣고 커맨드가 삭제된 뷰의 행을 읽음. **살아 있는 뷰만 결과에 넣고**, 엔진이 뷰 삭제를 적용할 때 그 뷰의 질의 노드(선분·조각·경계 상자·이웃 등)를 **그래프에서 치움**(`Graph.drop`, `drawing.forget_views`). 되살리면(undo) 처음부터 다시 계산하고 전체 재생성과 같다 | `test_뷰를_지우거나_생성을_취소한_뒤에도_영향_뷰_조회가_죽지_않는다` |
| 2 | `view.affected(rev)`가 바뀐 뷰를 빠뜨림 (레벨만 있을 때 첫 벽, 레벨+벽 한 배치) | 추적 시작 키가 `("el", id)`뿐이라 새 요소·버킷·개수·관계 키에 닿지 못함. **효과가 건드린 모든 입력 키**(`engine.input_keys_of`: 요소·버킷·개수·관계·속성)에서 따라가고, 의존 목록이 낡았을 수 있는 **stale 뷰와 한 번도 계산 안 한 뷰는 보수적으로 포함** | 아래 임의 편집열 시험 + `input_keys_of` 가 엔진이 실제로 그래프에 알린 키와 같은지 대조하는 시험 |
| 3 | `view.create/set`에 `p2=[1e200,0]` → `OverflowError`(INTERNAL). `[-1e308, 1e308]`은 통과해 NaN 기하 | 뷰 좌표·거리 필드를 ±1e7mm(10km)로 제한(`VCoord`)하고 `**2` 대신 곱셈. 범위 밖은 `SCHEMA_INVALID` | `test_큰_좌표는_구조화_오류로_거절하고_범위_안은_그대로_된다` |
| 4 | `view.export overwrite=true`가 확인 토큰·스냅숏 없이 덮어씀 | `view.export`를 `risk=destructive`(미리보기·확인 토큰, 인자·리비전에 묶임)로 바꾸고 덮어쓰기 전 `.dobim-snapshots/<이름>.<번호>` 스냅숏(`ifc.snapshots`로 목록)을 남김. 쓰기가 실패하면 방금 만든 스냅숏을 지움. 아키텍처의 파괴적 커맨드 규칙(파일 덮어쓰기 = 확인 토큰 + 자동 스냅숏)을 그대로 따름. 새 파일 내보내기도 같은 절차(확인 없이 쓰는 길 없음). `a.txt:b.svg`(대체 데이터 스트림)도 `PATH_DENIED`. 패리티 하네스는 destructive 를 이미 2단계로 실행하므로 예시는 그대로 두고 100%를 다시 확인 | `test_내보내기_덮어쓰기는_확인_토큰_없이는_쓰지_않는다` 외 기존 내보내기 시험 갱신 |

### 9.1 영향 뷰 조회 누락 시험 (결함 2 의 증명)

- 오라클: 변경 직전 모든 뷰의 증분 선분과, 변경 뒤 캐시 없는 전체 재생성 선분을 비교해 "선분이 실제로 바뀐 뷰" 집합을 구하고, `view.affected(rev)`가 그 집합을 모두 포함하는지 본다. 뷰 생성·수정·삭제와 undo/redo 도 같은 방식이다(`s3lib.fuzz_affected`).
- 결과(시드 41~44, 시드당 300스텝): 변경 **1,205건**, 바뀐 뷰 **865개**를 대상으로 **누락 0**, 오류 0. 낡은 뷰 포함 없이 입력 키 따라가기만으로 센 누락도 0.
- 정밀도: 보고한 뷰 1,488개 중 실제로 바뀐 것 865개(과포함 623개, 정밀도 0.58). 의존만으로 알 수 있는 상한이다(조기 차단 전의 전파 범위). 놓치는 것보다 많이 알리는 쪽을 택했다.
- 음성 대조: 옛 방식(요소 id 키만 추적)으로 바꾸면 같은 시험이 누락을 잡는다(`test_음성_대조_요소_id_키만_…`).
- 수정 전 재현: 검수 스크립트 t1(결함 1)은 `INTERNAL`, t2(결함 2)는 첫 벽에서 평면만·레벨+벽 배치에서 빈 목록이었고, 수정 뒤 모두 캐시 조회(`view.affected {}`)와 같아졌다.

### 9.3 남은 한계 (검수 반영 뒤)

- `view.affected(rev)`는 **현재 그래프의 의존**으로 추적한다. 과거 rev 를 한참 뒤에 물으면 그 사이 계산한 뷰의 의존 목록은 현재 상태 기준이다(최신 변경 직후에 묻는 용도가 정확하다).
- 평면 뷰의 레벨 삭제는 막지 않고 `model.validate`가 알려 주기만 한다. 코어의 `element.delete`가 뷰의 참조를 모르기 때문이며, 벽이 있는 레벨처럼 삭제를 거부하는 쪽이 더 안전하다(후속).
- 뷰 좌표 한도 ±1e7mm 는 임의로 정한 값이다(건물 규모의 10배 이상). 벽·레벨의 `Num`은 이번에 건드리지 않았다.
